# T163：抖音账号级内容口吻与局部修复

- 状态：已完成
- 决策：ADR-0081
- 类型：抖音多账号最小增强

## 目标

让同一公司的不同抖音账号分别采用企业官方或一线师傅口吻，同时阻止师傅口吻编造人物履历和客户
案例；口吻问题只修改命中句段，不重写整篇内容。

## 交付物

1. Contracts/API/Web：抖音自动化策略保存并回显独立的账号级内容口吻。
2. 数据库：新增受平台和值域约束的 `content_voice`，历史抖音策略回填企业官方口吻。
3. AI Worker：把口吻作为独立 Writer Input 强约束，并为两种口吻提供明确生成规则。
4. 质量门禁：确定性识别个人师傅身份、工龄、亲历、具体客户、客户反馈与客户案例。
5. 局部修复：抖音直生成按语义字段修复，通用内容按正文块修复；修复后重新校验。
6. 基线：迁移、OpenAPI、项目上下文、发布门禁和相称测试同步。

## 验收

1. 启用抖音自动化时必须选择内容口吻，非抖音策略不能携带该字段。
2. `douyin_content_voice` 与 `douyin_account_strategy` 在冻结输入中相互独立。
3. 企业官方和一线师傅提示约束不同；一线师傅必须包含现场判断或动作，但不得冒充真实人物。
4. 含虚构工龄、亲历和客户案例的单一段落只触发该段落修复，其他内容保持不变。
5. 历史内容、其他平台、账号 Profile 隔离、选题占位、排期和发布并发控制行为不变。
6. 全新数据库、单元/集成测试、类型检查、Web 生产构建、OpenAPI 和 Release static gate 通过。
