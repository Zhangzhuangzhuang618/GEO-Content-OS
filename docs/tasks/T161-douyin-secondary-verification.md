# T161：抖音登录二次验证

- 状态：已完成
- 决策：ADR-0076
- 类型：生产登录链路补全

## 目标

让抖音扫码后出现的短信或原设备二次验证可在现有 PUB-01 中安全完成，并为无法自动处理的验证保存
可审计的脱敏诊断，且不绕过平台风控。

## 交付物

1. Contracts：抖音二次验证动作、严格会话诊断和登录响应契约。
2. Worker：保留挑战页面的状态轮询、短信发送与校验、原设备二维码、成功后加密快照。
3. 诊断：私有脱敏截图、白名单页面特征、内容哈希和页面签名；不保存一次性输入或身份信息。
4. API：既有登录/重新认证端点透传严格动作，网关失败继续只暴露安全错误原因。
5. Web：二次验证说明、脱敏截图、短信和原设备操作，以及交互式验证码拒绝说明。
6. 基线：ADR/项目上下文、OpenAPI 与 SDK 同步；端点、数据库表和迁移基线不变。

## 验收

1. `attention_required` 轮询不会导航离开仍存活的挑战页面。
2. 短信发送只有用户操作才触发；4–8 位数字验证码不持久化、不回显、不写日志。
3. 原设备二维码可返回给当前用户，诊断截图中二维码、输入和账号信息全部遮盖。
4. 登录证据明确后才保存加密 storage state；失败或未知结果继续保持人工处理。
5. Worker 单元和浏览器集成、Contracts、API、Web、OpenAPI、构建和静态发布门禁通过。
6. 不在本任务中拉取生产代码、迁移生产数据库或重建生产容器。
