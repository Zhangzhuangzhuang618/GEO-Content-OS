# T162：抖音多账号内容隔离与资源控制

- 状态：已完成
- 决策：ADR-0079
- 类型：抖音多账号最小增强

## 目标

让同一公司在一个工作区安全运行多个抖音账号：各账号按自身定位生成，不在同日重复占用相同搜索主题，
并避免单机同时运行多个自动发布 Chromium。

## 交付物

1. Contracts/API/Web：策略配置与回显账号定位、服务范围、目标地区和主题池。
2. AI Worker：选择并冻结账号策略，把当次地区、服务和主题作为标题、检索和正文的强约束。
3. 数据库：公司级“关键词＋搜索意图＋日期”唯一占位及严格租户、工作区、账号、策略、批次范围校验。
4. 排期：同工作区抖音任务事务串行计算，冲突时间按 20 分钟错开。
5. Douyin Worker：保留账号 Profile 隔离，并把发布与状态核验的实例并发限制为 1。
6. 基线：迁移、OpenAPI、项目上下文、发布门禁和相称测试同步。

## 验收

1. 未完整配置四项定位的抖音策略不能启用，新批次不会无约束生成。
2. 两个账号的冻结 Writer Input 分别包含自身定位和主题，不发生策略串用。
3. 同公司同日重复“关键词＋搜索意图”由数据库原子拒绝并自动选择下一组合。
4. 多账号排期至少错开 20 分钟，单 Worker 自动 Chromium 最大并发为 1。
5. 搜狐号、列举网、旧内容和历史发布任务行为不变；冻结质量门禁不降低。
6. 全新数据库、单元/集成测试、类型检查、Web 生产构建、OpenAPI 和 Release static gate 通过。
