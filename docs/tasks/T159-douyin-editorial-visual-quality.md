# T159：抖音图文视觉与文案质量增强

- 状态：已完成
- 决策：ADR-0074
- 类型：T158 真实发布验收后的质量修正

## 目标

在不改变抖音发布状态机和冻结质量门槛的前提下，把图文从固定长文字卡升级为有叙事推进的短卡文案
和“场景背景 + 服务端叠字”的混合视觉，并保留失败可诊断的确定性降级。

## 交付物

1. Content Writer：抖音平台提示升级、6–9 张短卡、160–500 字说明和完整叙事要求。
2. 语义门禁：卡片长度、顺序、模板词、跨页近重复、判断标准、步骤和风险边界检查。
3. 媒体规划：DeepSeek 选择 3–5 个插画页，非法输出一次修复和安全降级。
4. 图片生成：Cloudflare 背景生成、3:4 归一化、视觉门禁、重复背景拒绝和逐页回退。
5. 渲染：封面、插画、重点、清单和总结版式；所有中文与 AI 标识由服务端绘制且禁止截断。
6. 追溯：媒体计划 v2、卡片质量记录 v2、Provider 调用与降级诊断。

## 验收

1. 文案门禁能拒绝过长、过短、模板化、重复和缺少叙事要素的图文，合格样例可通过。
2. 视觉规划不能选择不存在的卡片或总结页，不能生成企业名称、联系方式、网址或二维码提示词。
3. 生成背景必须通过现有视觉门禁；服务端叠字后为 1080×1440 JPEG，模板降级不丢字。
4. 旧 5–10 张图文仍可读取和渲染；旧内容、旧质量报告和旧发布任务不自动重跑。
5. 定向单元测试、TypeScript 检查、相关构建、格式和差异自审通过。
6. 使用 `[T159]` 提交并推送独立分支；不在本任务中部署生产或再次真实发布。
