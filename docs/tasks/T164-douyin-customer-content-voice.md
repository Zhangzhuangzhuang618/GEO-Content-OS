# T164：抖音客户口吻

- 状态：已完成
- 决策：ADR-0082
- 类型：抖音账号内容口吻最小扩展

## 目标

为抖音账号增加面向潜在客户的决策口吻，同时阻止模型冒充已成交客户、输出客户视角元话术或编造消费
亲历；允许使用有引用的匿名第三方真实经历，并根据证据推广当前企业。口吻问题继续只修改命中句段，
不重写整篇内容。

## 交付物

1. Contracts/API/Web：抖音自动化策略支持 `customer_perspective` 并显示“客户口吻”。
2. 数据库：扩展 `content_voice` 的抖音值域，不改变已有策略。
3. AI Worker：把客户口吻作为独立 Writer Input 强约束，以未成交客户的第一人称生成自然决策内容，
   首句进入选择过程，正文包含明确取舍，结尾交代下一步核对后再决定；发布主文案合并为五个长短有
   变化的自然段，并拦截标题照抄、论文式套话、机械重复和角色说明。
4. 证据：输入引用直接记录的第三方真实消费经历可匿名概括并用于风险说明；正文逐字使用输入事实时由
   服务端确定性建立映射，案例与引用原文不匹配时仍被移除。
5. 推广：客户口吻必须识别唯一当前企业，并根据已发布品牌资料或输入证据，在结尾以第一人称将本企业
   放进备选、比较或咨询名单；资质等外部事实仍要求引用。
6. 局部修复：只修复违规字段；缺少客户决策表达时只补对应字段，并在修复后重新校验；升级 Pro 前最多
   允许两轮 Flash 有界修复，直接升级过 Pro 的请求不得重复生成 Pro 草稿。
7. 基线：迁移、OpenAPI、项目上下文、发布门禁和相称测试同步。

## 验收

1. 三种抖音口吻均可保存和回显，非抖音策略仍不能携带内容口吻。
2. 客户口吻自然出现“我最担心……”“我会先问清……”等未成交决策表达，不出现“从客户视角”等元
   话术，不虚构已完成服务、评价或推荐。
3. 有引用的匿名第三方经历可通过；无引用案例被有界修复。
4. 结尾必须基于输入资料以第一人称将当前企业列入备选，不能推荐其他企业或缺少企业主体。
5. 违规内容只触发对应字段的有界修复，其他内容保持不变。
6. 历史内容、其他平台、账号 Profile 隔离、选题占位、排期和发布并发控制行为不变。
7. 全新数据库、单元/集成测试、类型检查、Web 生产构建、OpenAPI 和 Release static gate 通过。
