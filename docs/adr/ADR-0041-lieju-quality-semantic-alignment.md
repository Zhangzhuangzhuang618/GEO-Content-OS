# ADR-0041：列举网生成与质检语义对齐

- 状态：已批准实施
- 日期：2026-08-17
- 任务：HOTFIX-20260817-08
- 影响范围：列举网生成、重写、共享 Quality Checker
- 前置决策：ADR-0037、ADR-0040

## 背景

HOTFIX-20260817-07 部署后，列举网第二次日批仍为 0/30。生产证据显示主要问题已从队列重复失败
转为模型语义误报：标题未超过 30 字却被 `lieju.title.max_characters` 阻断，中性的“通过页面联系
方式咨询”被当成具体联系方式，“电话公司”被当成第三方企业名称；部分标题未满足冻结的
`question_coverage` 门槛。没有高风险事实的输入仍会看到带高风险 BLOCK 的固定 few-shot，也继续诱发
无对应 claim 的问题。

## 决策

1. 标题上限校验增加 `.title.max_characters` 规则 ID 变体；标题字数仍由服务端按 Unicode 字符确定，
   未超限时任何对应标题上限 BLOCK 都是无效模型输出。
2. 列举网的 `contact_in_content_forbidden` 明确指正文中的具体电话号码、网址、微信 ID 或 QQ ID；
   “通过页面联系方式咨询”不包含联系方式值，属于允许的中性引导。模型问题必须指向实际包含具体
   联系值的位置，服务端不代替模型生成结论。
3. “搬家公司”“物流公司”“电话公司”等行业泛称不是可识别企业名称。`brand.other_company_name`
   仍必须引用准确的第三方专有名称和位置。
4. 每次质检首次调用都注入当前标题实际字数、上限、允许的高风险 claim 位置和列举网联系方式边界。
   当输入没有高风险无支持或冲突事实时，few-shot 中对应的高风险事实和问题从示例对中同时移除；
   冻结高风险事实 BLOCK 规则本身不变。
5. 列举网首稿、日批简报和重写提示统一要求 5–30 字的问题/方法型标题，自然使用“如何、怎么、
   指南、方法、哪些”等问法；两个未满足问题覆盖的日批角度同步改为自然问法。

## 不变项

- GEO、事实、品牌、可读性、问题覆盖和平台适配门槛不降低，最多三次重写不变。
- 具体电话、手机号、网址、微信 ID、QQ ID 继续禁止出现在列举网正文，由发布账号配置填写。
- 旧候选、旧内容版本和旧质量报告不修改、不重新评估；部署后需显式发起新的日批尝试。
- 不新增公开端点、数据库迁移或 Web 运行时改动。

## 验收

- 日志中的标题点号规则、页面联系中性引导和行业泛称均有回归测试。
- 无高风险事实的首次请求不再包含高风险问题示例输出；有高风险事实时仍必须精确 BLOCK。
- 列举网首稿与重写提示明确问题型标题和具体联系方式边界。
- Skills、AI Worker、类型检查、单元、契约与集成测试通过。
