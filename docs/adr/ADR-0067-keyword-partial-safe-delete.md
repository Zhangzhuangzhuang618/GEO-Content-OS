# ADR-0067：关键词批量删除安全跳过历史引用项

- 状态：已批准实施
- 日期：2026-08-21
- 任务：HOTFIX-20260821-05
- 影响范围：STR-04、关键词 API、策略契约与 OpenAPI
- 修订决策：ADR-0064 第 4 项、ADR-0065 第 4 项

## 已核验事实

关键词被 `brief_keywords` 引用后不能物理删除，否则会破坏历史 Brief 与关键词的关系。现有实现只要
在一次批量删除中发现一个引用项，就返回 409 并回滚全部删除；因此用户同时选择引用项和未引用项时，
未引用关键词也无法删除，只能重新定位并拆分操作。

## 决策

1. 批量删除仍在一个数据库事务内重新解析、锁定并校验完整选择集。租户、项目、关键词集、权限、
   显式 ID 或筛选条件不合法时仍整批失败。
2. 仅对“已被历史 Brief 引用”实行安全分流：引用项保留，未引用项在同一事务中物理删除。不得删除
   `brief_keywords` 或任何历史内容关系来完成删除。
3. 即使全部选择项均被引用，接口也返回 200；`affected_count` 表示实际删除数，新增
   `skipped_referenced_count` 表示因历史引用而保留的数量。显式 ID 请求继续原样返回
   `keyword_ids`，筛选全选继续返回 `keyword_ids: null`。
4. 更新、禁用操作返回 `skipped_referenced_count: 0`。批量操作结果与两个数量写入既有审计和幂等
   记录，不删除或覆盖历史审计。
5. STR-04 在删除确认时说明引用项会被保留；成功后同时展示实际删除数和跳过数，并明确提示被引用
   关键词需要改为禁用。成功后仍清空本次选择，不自动替用户禁用。
6. 不修改关键词唯一性、日批取词规则、质量门槛、历史 Brief、旧内容或旧质量报告。

## 后果

- 无数据库迁移、无新增公开端点；可执行端点数保持 160。
- 需要重新构建部署 API 与 Web；不需要重新构建 AI Worker 或发布 Worker。
- 删除仍具有事务性：数据库错误会回滚本次所有可删除项；“部分成功”只来自预先定义的历史引用
  安全跳过，不吞掉其他错误。
- 既有调用方必须接受响应新增的必填计数字段。

## 验收

- 显式选择一个引用项和一个未引用项时返回 200，只删除未引用项，并分别返回删除数 1、跳过数 1。
- 全部选择项均被引用时返回 200、删除数 0、跳过数为引用项数量，引用关系和关键词均保留。
- 筛选结果跨页全选遵循相同分流规则，不在前端拆分请求。
- 更新和禁用返回跳过数 0；租户、权限、状态及无效 ID 错误仍保持原有失败语义。
- 前端提示被引用关键词未删除且需要禁用；Contracts、API 集成测试、STR-04 回归、Web 构建与
  OpenAPI 校验通过。
