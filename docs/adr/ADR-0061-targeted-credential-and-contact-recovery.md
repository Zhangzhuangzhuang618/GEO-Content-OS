# ADR-0061：证照声明定向修复与列举网联系方式误报恢复

- 状态：已批准实施
- 日期：2026-08-20
- 任务：HOTFIX-20260820-09
- 影响范围：Content Writer、Quality Checker、AI Worker
- 延续并修正：ADR-0040、ADR-0041、ADR-0057、ADR-0058、ADR-0059

## 已核验事实

HOTFIX-20260820-07 部署后，生产显式重新质检 8 个列举网旧候选，1 个发布成功、7 个进入人工处理。
其中 5 个候选在完整质量重写后仍保留没有通过冻结 `citation_map` 逐项支持的营业执照、道路运输证
或道路运输经营许可证声明；一次最终整篇修复仍可能原样保留问题，或返回结构非法的短稿。

另有 2 个候选的模型报告最终为 pass，但语义修复输出仍附带
`lieju.contact_in_content_forbidden`。服务端按报告给出的准确区块检查后确认该位置没有电话号码、
网址、微信 ID 或 QQ ID，拒绝原因为 `prohibited_contact_detail_is_not_present_at_location`，导致整个
质检执行失败。

## 决策

1. 当浏览器平台质量重写后的结构已合格，剩余确定性问题仅为不受支持的证照声明及可能同时存在的
   “重写未变化”时，不再要求模型返回完整文章。改为列出含问题的具体标题、摘要、CTA 或正文块，
   最多执行两轮无工具的结构化定向修复。
2. 模型必须为每个目标返回且只返回一个非空替换文本。服务端只把模型返回值应用到对应目标，其他
   字段、区块顺序和锁定区块保持不变；未知、重复、缺失、未变化或仍含不受支持证照声明的替换均
   拒绝。相关声明被删除后，只移除正文已不再承载的 citation 映射，不生成或借用新引用。
3. 定向修复仍只读取候选原始冻结 Writer 输入。锁定区块不允许修改；无法在这些边界内完成时保持
   `CONTENT_QUALITY_INSUFFICIENT`，不得放宽证照证据门槛。
4. Quality Checker 首次输出仍执行完整语义验证，并只在既有语义修复阶段启用确定性误报恢复。
   对列举网联系方式问题，只有准确位置存在、规则与分类合法且该位置确定没有字面电话、网址、
   微信 ID 或 QQ ID 时，才删除这一条不可验证问题。
5. 恢复后只根据其余模型问题和冻结 warning 上限计算 decision，模型分数保持不变，并继续执行
   确定性风险扫描。真实联系方式、位置无效、分类或严重度错误及其他规则继续阻断或失败。

## 兼容性与恢复边界

- 不新增数据库迁移、公开 API 或前端契约。
- 不降低证照、联系方式、品牌、事实、标题或任何冻结质量门槛；服务端不生成正文、引用或分数。
- 不自动重评旧候选、旧内容和旧质量报告。旧候选仍只使用首次生成时冻结的证据，必须由用户显式
  重新质检；需要后来上传的证照时必须发起新候选。

## 验收

- 无冻结证照支持的声明可在不改动无关正文和锁定区块的前提下由模型定向删除；仍保留则失败。
- 定向修复不接受缺目标、未知目标、重复目标、空文本、原文返回或新增证照声明。
- 列举网精确位置没有字面联系方式时，重复误报不再以 `SKILL_OUTPUT_INVALID` 终止；真实电话、网址、
  微信 ID 和 QQ ID 仍然 BLOCK。
- Skills、AI Worker、类型检查和全量回归通过。
