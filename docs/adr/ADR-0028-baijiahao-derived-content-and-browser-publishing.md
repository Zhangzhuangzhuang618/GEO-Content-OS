# ADR-0028：百家号同源派生、质量门禁与托管浏览器发布

- 状态：已批准实施
- 日期：2026-08-02
- 任务：T145
- 影响范围：`baijiahao` 内容自动化与发布；官网自动化只新增发布成功事件，不迁移既有表或状态机
- 前置决策：ADR-0014、ADR-0021、ADR-0023、ADR-0027

## 1. 业务目标

系统为百家号提供自动生成、机器质检、最多三次自动重写、自动排期和服务器托管浏览器发布。默认从已成功发布的官网文章派生百家号变体；没有官网来源时可显式启用独立生成。百家号失败不得改变官网文章、官网自动化运行或官网每日批次状态。

## 2. 内容来源

策略支持且只能选择以下来源之一：

1. `official_site_derived`：监听官网 API 发布成功事件，在同一内容包中创建百家号变体。复用官网选题、事实、引用、结构和核心观点，不重新选题或检索，不从零生成。
2. `independent`：使用项目中适用于百家号的关键词、已发布品牌资料和已解析知识资料创建独立候选。独立补位必须显式开启，默认不得因为官网文章不适合百家号而强行生成。

`official_site_derived` 开启独立补位时，系统最早只在当天第一条排期前一小时启动补位，并只补足尚缺数量；这样给官网同源内容优先机会，也避免到排期时才开始生成。补位仍使用同一冻结门禁和候选上限。

派生模式必须满足：

- 官网发布任务已通过 API 成功完成，具有不可变官网内容版本和公开 URL；
- 只选择信息型、指南型、解释型或决策辅助型内容；明显落地页、强营销、纯企业公告或无法去除外链 CTA 的内容必须跳过；
- 百家号版本通过一次平台定向改写完成，必须改变标题、摘要、段落顺序、表达方式和信息重点；
- 删除 FAQ、Schema.org、slug、meta description、官网链接、二维码、电话和外部平台 CTA；
- 保存来源官网内容版本、URL、实际沿用的引用、派生版本和相似度；
- 禁止原文复制和近义词机械替换。相似度门禁由确定性算法执行，生产阈值必须由版本化平台规则冻结，禁止运行时放宽。

## 3. 质量门禁

百家号自动发布门禁不得弱于：

- GEO 总分至少 85；
- 事实准确性至少 90；
- 品牌一致性至少 90；
- 可读性与安全至少 85；
- 问题覆盖至少 80；
- 平台适配至少 80；
- 任一 `BLOCK` 或 Quality Checker 决策不是 `pass` 时禁止发布；
- 最多自动重写 3 次，仍失败进入 `manual_required`。

确定性阻断至少包括：

- 标题 2–40 个 Unicode 字符、摘要 1–120 个字符、标签 3–8 个；
- 禁止其他公司的可识别名称；
- 禁止无证据价格、规模、资质、承诺、排名和客户结果；
- 禁止二维码、营销电话、外部平台账号、第三方网址和明显导流；
- 禁止相对时间冒充最新消息；
- 题文、封面和正文必须一致；
- 图片不得包含推广水印；
- 派生正文不得与官网来源完全相同或高度相似。

服务端只执行确定性校验和冻结门禁，不得伪造模型质量判断。

## 4. 发布通道

新增独立进程 `workers/baijiahao-browser`，实现现有 Baijiahao Delivery Adapter 所需的 `/capabilities`、`/publish`、`/status/:id` 和 `/metrics/:id` 协议，并提供受保护的扫码登录会话接口。

每个百家号平台账号对应一个隔离浏览器 Profile：

- 用户通过二维码登录，不保存账号密码；
- Cookie、storage state 和必要 Profile 数据使用现有凭证信封加密，按租户和账号隔离；
- 容器内明文 Profile 只能位于受限 `tmpfs`，进程重启后由数据库中的加密 storage state 恢复，不创建未加密持久卷；
- 同一账号浏览器操作并发固定为 1；
- Profile 可在浏览器进程重启后恢复；
- 登录失效进入 `reauth`；验证码、风控或页面签名不匹配进入 `attention_required`；
- 禁止自动识别、绕过或代填验证码；
- 日志、错误、审计和截图元数据不得包含 Cookie、二维码令牌或凭证。

## 5. 未知发布状态

点击发布前写入不可变发布尝试和内容指纹。提交中断或响应不确定时，任务进入未知态，不得直接重复点击。浏览器必须先进入内容管理页，按账号、标题、内容指纹和提交时间窗口核验：

- 找到唯一匹配项：关联远端内容并继续同步审核状态；
- 未找到：只有在确认页面未创建内容后才能使用同一幂等键重试；
- 多个匹配项或页面不可验证：进入 `manual_required`。

## 6. 审核状态

提交成功不等于发布成功。系统持续同步 `processing | published | failed | unknown`，记录远端内容 ID、最终 URL、审核原因和核验时间。只有远端状态为 `published` 才把发布任务和百家号自动化运行标记为发布完成。

## 7. 数据与事件

新增百家号独立策略、运行、每日批次、批次条目和浏览器会话表；不得迁移、改名或复用 `official_site_automation_*`、`official_site_daily_*` 表。

新增事件：

- `publishing.job.published.v1`：Publisher 在 API 发布成功事务中写入；
- `content.variant.baijiahao_adaptation_requested.v1`：请求同源派生或质量重写；
- `baijiahao.publication.reconcile_requested.v1`：核验未知态和审核状态。

内容与发布事件使用 Outbox、`event_id` 和业务唯一键幂等。扫码会话是用户发起的同步管理操作，由 API 调用内部浏览器网关，不进入异步队列。官网发布成功事件只描述已经发生的事实，不改变官网状态机。

## 8. 明确不做

1. 不迁移或通用化官网自动化表。
2. 不让百家号失败反向修改官网内容、发布任务或每日批次。
3. 不原文同步官网文章。
4. 不自动绕过验证码、风控或平台登录验证。
5. 不在 API 或 Publisher Worker 内直接启动浏览器。
6. 不在本地、CI 或验收中访问生产百家号。
7. 不宣称浏览器提交成功等同于百家号审核通过。

## 9. 上线门禁

必须完成单元、契约、PostgreSQL 集成、本地仿真页面浏览器 E2E、安全、租户隔离、幂等、未知态恢复和进程重启恢复测试。首轮只允许单一受控账号、串行低频灰度；完成自审、提交和推送后才允许部署。
