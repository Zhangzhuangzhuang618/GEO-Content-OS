# ADR-0082：抖音客户口吻

- 状态：已批准实施
- 日期：2026-09-03
- 任务：T164
- 影响范围：PUB-01、抖音每日批次、AI Worker、数据库
- 前置决策：ADR-0081

## 背景

ADR-0081 已支持企业官方和一线师傅两种账号级内容口吻，但部分账号需要从潜在客户正在比较服务的角度
表达需求、顾虑和核对步骤。直接把“客户口吻”写进账号定位无法形成独立约束，也容易让模型冒充已成交
客户，编造消费经历、服务评价或推荐结果。

## 决策

1. 抖音自动化策略的 `content_voice` 新增 `customer_perspective`（客户口吻）。该值继续独立于账号定位，
   仅适用于抖音；搜狐号和列举网不得设置。
2. 客户口吻表示潜在客户尚未成交时的真实决策过程，不是让模型解释自己正在扮演客户。正文首句必须
   由潜在客户自然进入选择过程，并至少呈现一次明确的筛选态度，例如不接受模糊总价、愿意继续比较
   可核对的方案；结尾还要说明下一步询价或核对实际方案后再决定。不得出现“从客户视角”“站在客户
   角度”“作为客户”等元话术。
3. 生成后确定性检查客户决策表达，并拦截服务人员身份、已完成消费或服务亲历、客户评价和推荐结果。
   第一人称历史陈述一律视为不受支持内容；输入引用直接记录的第三方真实消费经历可以匿名概括为
   “某先生”“某女士”或“某位消费者”，用于说明对应风险和注意事项，但可见事实必须映射原引用。
4. 命中违规句段或缺少客户决策视角时，沿用 ADR-0081 的有界局部修复：只改命中字段，或选择一个未
   锁定正文段补充客户需求和核对表达；其他事实、引用、标题和段落保持不变。
5. 客户口吻仍承担推广当前企业的目标。启用该口吻时，已发布品牌资料必须且只能识别一个法定企业
   全称；正文根据已发布品牌资料或输入引用支持的本企业能力说明选择理由，资质等需外部证明的事实仍
   必须引用，结尾以未成交客户的第一人称把本企业列入备选、比较或咨询对象，不得生成虚假客户好评或
   无依据推荐。
6. 客户口吻的发布主文案由结构化字段合并为五个长短有变化的自然段，不把报价、防护、排期和清单机械
   拆成等长说明段；清单允许使用 ①②③ 等轻量编号。生成与局部修复同时拦截论文式、助手式套话、标题
   照抄、机械重复“我会”和伪造已完成比较的表达。
7. 正文逐字包含输入引用中的完整事实句时，由服务端确定性补齐引用映射；匿名第三方案例只有在被引用
   原文逐字包含该案例时才视为有证据，不把映射完整性继续交给模型随机决定。
8. 局部修复后再次执行同一口吻、第三方案例证据和本企业推荐门禁。Flash 最多执行两轮有界字段修复后
   才升级完整 Pro 草稿；Flash 已因结构错误直接升级 Pro 时不得重复生成第二份 Pro 草稿。连续修复仍不
   合格时按既有失败关闭流程处理，不降低质量阈值。

## 数据与兼容性

- 迁移 `0057_douyin_customer_content_voice` 只扩展现有数据库检查约束，不修改已有策略值。
- 不新增业务表或公开端点；当前业务表仍为 93 张，公开端点仍为 170 个。
- 旧内容、旧批次、旧质量报告和历史发布任务不重写。

## 验收

1. 抖音策略页面可选择、保存并回显客户口吻，接口与数据库接受 `customer_perspective`。
2. Writer Input 继续单独冻结 `douyin_content_voice`，客户口吻提示明确采用潜在客户决策视角。
3. 已完成消费、服务亲历、评价、推荐结果、服务人员身份和客户视角元话术被确定性拦截；开头、正文和
   结尾均能识别自然的未成交客户第一人称决策表达。
4. 第三方消费经历只有在匿名化且完成输入引用映射时可通过；无引用案例只删除案例句段，不放宽事实
   门禁。
5. 正文根据当前企业资料给出有依据的克制推荐；缺少唯一企业名称、明显 AI 套话或结尾未以第一人称将
   本企业列入备选时停止或局部修复。
6. 全新数据库迁移仍得到 93 张表；Contracts、API、Web、AI Worker、OpenAPI、构建和 Release static
   gate 通过。
