# ADR-0055：企业保险证明原件私有保存与脱敏摘要检索

- 状态：已批准实施
- 日期：2026-08-20
- 任务：T156
- 影响范围：资料导入、Knowledge Worker、资料详情、数据库约束
- 延续决策：ADR-0014、ADR-0015、ADR-0053

## 已核验事实

保险单通常包含投保企业、承保机构、保险类型、保障期间和参保人数，也可能包含员工姓名、证件号码、
联系电话、保单号和人员清单。用户提供的九页 PDF 是无文字层扫描件，现有 PDF Parser 无法提取文字；
生产环境也没有可声明为真实能力的 OCR Provider。

保险原件可证明特定期间内的企业投保事实，但不能证明服务质量、理赔结果或保险到期后的持续有效性。
将整份原件写入 chunk、Embedding 或模型上下文会不必要地暴露个人信息。

## 决策

1. 新增 `insurance_proof` 资料类型，首版只接受 PDF。上传时必须人工确认投保主体、承保机构、保险
   类型、保障起止日期和参保人数，资料可信级别必须为 `verified`，并明确确认脱敏摘要可用于检索和
   生文。
2. 原始 PDF 继续经过格式签名、大小和恶意文件检查，并按原内容哈希保存到租户私有对象存储。原件
   不作为文章图片，不返回公开地址，也不进入 Publisher 媒体选择。
3. Knowledge Worker 对 `source-insurance-proof@1` 完全跳过 PDF 文字提取和 OCR。它只根据人工确认的
   固定字段生成确定性摘要；保单号、员工姓名、个人证件号、电话、邮箱、银行卡和原始正文不得进入
   `metadata_json`、`source_chunks`、Embedding、检索结果或模型 Prompt。
4. 脱敏摘要固定包含资料类型、投保主体、承保机构、保险类型、保障期间、参保人数及用途边界。用途
   边界明确说明该资料不代表服务质量、理赔结果或到期后的持续有效性。资料标题由服务端固定为
   “企业保险证明”，文件名、用户自填标题和保单编号不得进入检索或生文。
5. 资料详情展示结构化保险摘要、保障期间和“原件公开：禁止”，并将 chunk 区域标为“可检索脱敏
   摘要”，不得把摘要标为 PDF 原文。
6. 有效期沿用 `source_documents.effective_from/effective_to`；既有检索状态规则继续在到期后排除资料。

## 安全与兼容边界

- 元数据采用严格的 `source-insurance-proof@1` 字段集合，数据库拒绝额外字段、非 PDF、非 verified、
  缺少完整有效期、无摘要确认或越界参保人数。
- 人工确认字段拒绝常见个人手机号、身份证号、银行卡号和邮箱格式。
- 不引入 OCR 依赖，不伪造扫描识别结果，也不把文件名或 PDF 图像中的内容当作已核验事实。
- 普通 PDF、图片证照及历史资料保持原路径；旧失败资料不会自动转换为保险证明。
- 不改变冻结质量门槛、旧质量报告、旧内容版本或旧发布任务。

## 验收

- 保险 PDF 原件私有保存且内容哈希一致，API 只返回非敏感结构化摘要。
- 扫描 PDF 即使不含文字层也能完成入库、分块和索引，因为 Worker 不读取原始正文。
- 自动测试以含虚拟姓名、证件号和电话的 PDF 字节验证这些内容不进入摘要。
- 使用用户提供的九页扫描 PDF 做本地真实文件回归，生成的唯一可检索文本必须为人工确认摘要。
- Contracts、迁移、OpenAPI、API、Web 和 Knowledge Worker 的相关测试及构建通过。
