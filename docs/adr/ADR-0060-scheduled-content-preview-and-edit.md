# ADR-0060：已排期内容按冻结版本预览与安全修改

- 状态：已批准实施
- 日期：2026-08-20
- 任务：HOTFIX-20260820-08
- 影响范围：Publishing API、Content API、Web、AI Worker、自动发布状态机
- 延续决策：ADR-0009、ADR-0013、ADR-0021、ADR-0028、ADR-0037

## 已核验事实

发布任务详情只展示状态、时间、尝试和技术结果，没有展示任务实际绑定的不可变文章版本。用户无法在
发布前核对全文，也没有从已排期任务进入人工修改、重新质检和重新发布的安全路径。直接编辑当前
内容会使发布任务仍指向旧 `content_version_id`，直接覆盖旧任务又会破坏发布历史和幂等边界。

## 决策

1. `GET /publish-jobs/{id}` 返回任务实际绑定的 `content_version_id`、`content_hash` 和完整结构化
   内容。服务端必须同时校验版本属于同一租户、工作区、项目、内容变体和内容包，且内容 hash 与
   任务 `payload_hash` 完全一致；不一致时拒绝响应，不改用当前版本代替。
2. 发布任务详情向有发布权限的成员展示冻结全文；只有企业 owner 或 admin 可从 `scheduled` 任务
   发起“修改并重新质检”。已经开始外部调用、已发布、失败或终态任务不开放该入口。
3. 进入修改前先通过既有乐观锁接口取消原任务。原发布任务、发布尝试、质量报告和内容版本保持
   不可变；自动化运行及日批条目按既有人工取消语义安全停止。日批条目转为 `retired` 时清空旧排期、
   合格时间和发布任务关联，并在错误标记中保存精确源任务 ID；普通重新排期可据此恢复原关联，人工
   修改则只能据此恢复原自动化链路。
4. 人工保存产生新的不可变内容版本。重新质检请求必须携带已取消的源发布任务 ID；服务端只恢复
   同租户、同变体、同来源且确由该任务取消的自动化运行，禁止客户端指定租户、平台或其他运行。
5. 人工修改后的质检不自动调用 Content Writer 重写。门禁不通过或质检执行失败时进入人工处理，
   保留新版本供继续修改；不得由 AI 覆盖用户刚保存的正文。
6. 门禁通过后，官网、百家号、搜狐号和列举网自动化创建绑定新版本的新发布任务；人工来源内容由
   用户按现有审核流程重新排期。旧任务不得改绑新版本，也不得覆盖历史。
7. 若重新质检通过后进入自动配图，媒体运行必须持久化源发布任务与 `manual_edit` 标记；Worker
   崩溃后的过期运行恢复必须携带同一标记，禁止恢复成普通自动重写链路。

## 兼容性与恢复边界

- 不新增公开端点或数据库迁移；扩展既有发布详情响应和质量检查请求契约，并同步 OpenAPI。
- 普通质量检查继续接受空对象并按 `full` 模式执行，旧客户端保持兼容。
- 不自动修改、取消或重新质检既有任务。只有用户从已排期详情显式进入流程时才执行。
- 质量分数、BLOCK、引用、事实、平台规则、重写上限和外部未知态规则均不变。

## 验收

- 发布详情展示任务冻结的标题、摘要、正文、行动引导、标签及版本，不误用内容变体的后来版本。
- 非 owner/admin 和非 `scheduled` 任务看不到修改入口。
- 修改流程保留旧任务，保存新版本并重新质检；状态或版本竞争返回 409，不静默覆盖。
- 自动化来源通过后创建新任务，不通过时不触发 AI 重写；人工来源通过后按现有审核流程重新排期。
- Contracts、OpenAPI、API、AI Worker、Web 类型检查和页面回归通过。
