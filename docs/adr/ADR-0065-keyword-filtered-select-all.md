# ADR-0065：关键词筛选结果跨页全选

- 状态：已批准实施
- 日期：2026-08-21
- 任务：HOTFIX-20260821-03
- 影响范围：STR-04、关键词批量操作契约、API、Web
- 延续决策：ADR-0064

## 已核验事实

ADR-0064 的表头复选框只选择当前页，批量接口一次最多接收 500 个显式关键词 ID。若前端为了实现
跨页全选而逐页或按 500 个一组提交，后续分组可能因历史 Brief 引用而失败，造成前面的删除已经提交、
后面的删除被拒绝，破坏既有的整批原子性。

## 决策

1. STR-04 保留逐项和当前页选择，并增加“选择全部 N 个筛选结果”。这里的“全部”指当前关键词集内
   符合已提交搜索词、状态和适用平台过滤条件的全部关键词，不受当前页和优先级排序影响。
2. 扩展既有 `POST /keyword-sets/{id}/keywords/batch` 请求：除 1 至 500 个显式 `keyword_ids` 外，
   可提交 `selection.mode=all_filtered` 及同一组过滤条件。两种选择方式互斥。
3. 服务端在同一数据库事务中按租户、授权项目、关键词集和过滤条件重新解析并锁定完整选择集，再执行
   修改、禁用或删除。客户端展示数量只作提示，不作为服务端操作依据。
4. 筛选结果为空时拒绝操作；全选删除中只要存在一个已被历史 Brief 引用的关键词，整次删除返回 409，
   不删除任何关键词。不得将全选拆成多个独立写事务。
5. 显式 ID 操作继续在响应中返回 `keyword_ids`；筛选全选只返回服务端实际 `affected_count`，
   `keyword_ids` 为 `null`，避免无界响应。筛选全选审计记录过滤条件、实际数量、动作和修改字段，
   不写入无界关键词正文快照。
6. 表头和逐项勾选仍只作用于当前页并在普通翻页时清空；进入筛选全选模式后翻页继续保持全选。
   修改筛选条件、切换关键词集、导入或写操作成功后清空选择，避免把旧条件下的选择误用于新结果。
7. 不修改关键词唯一性、日批取词规则、质量门槛、历史 Brief、旧内容或旧质量报告。

## 后果

- 无数据库迁移、无新增公开端点；可执行端点数保持 160。
- 需要重新构建部署 API 与 Web；不需要重新构建 AI Worker 或发布 Worker。
- 全选操作会在一次事务内锁定全部匹配关键词，换取批量修改和删除的原子性。

## 验收

- 两页以上结果可先选择当前页，再切换为全部筛选结果；翻页后仍显示全部已选择。
- 全选批量请求只提交过滤条件，不枚举或分批提交全部 ID；服务端返回实际处理数量。
- 超过 500 个匹配结果仍作为一个服务端事务处理；500 上限只约束显式 ID 请求。
- 搜索词、状态和平台过滤均限制全选范围，页码和排序不改变范围。
- 全选删除混有历史引用时整批失败且所有匹配关键词仍保留。
- 显式 ID 批量操作保持兼容；Contracts、API 集成、STR-04 回归、Web 构建与 OpenAPI 校验通过。
