# ADR-0062：证照核验建议、混合定向修复与质检误报恢复

- 状态：已批准实施
- 日期：2026-08-20
- 任务：HOTFIX-20260820-10
- 影响范围：Content Writer、Quality Checker、AI Worker
- 延续并修正：ADR-0056、ADR-0057、ADR-0058、ADR-0059、ADR-0061

## 已核验事实

HOTFIX-20260820-09 部署后，生产显式重新质检 7 个列举网旧候选，1 个发布成功、6 个进入人工处理。
失败中有 3 个候选在完整重写后继续保留没有冻结 citation 支持的证照声明；其中一个候选还同时含有
列举网禁止推广词，既有证照专用定向修复不会处理该混合问题。

另有 2 个候选在 Quality Checker 语义修复后仍返回不可验证问题：一条把不具备高风险事实资格的正文
位置标为 `fact.high_risk.unsupported`，另一条把“设备清单”等普通称谓标为
`brand.other_company_name`。日志中先前的合格报告和之后的非法输出属于不同质检尝试，非法输出没有
替换已持久化报告。其余一个候选在最多重写次数后仍未达到冻结事实准确性和总分门槛，属于真实质量
失败。

## 决策

1. 不受支持证照扫描必须区分“当前企业实际持有、有效或齐全”的断言与“核验是否具备、选择时应
   确认”等非断言式建议。只有后者不作为证照声明；肯定式持证、有效期和资质齐全表述继续要求原候选
   冻结证照及 citation_map 的逐项支持。
2. 浏览器平台完整质量重写后的结构已合格，且全部剩余问题仅为不受支持证照声明、列举网禁止推广词
   或“重写未变化”时，允许进入 ADR-0061 的最多两轮精确目标修复。每个目标同时列明待删除证照声明
   和待替换推广词；模型只能返回该目标的中性替换文本。
3. 服务端继续验证目标完整性、唯一性、非空、已变化、锁定区块和结构，并额外确认替换后既无不受
   支持证照声明，也无列举网禁止推广词。任何失败都不得持久化模型原始输出，只记录有限、枚举化的
   脱敏拒绝原因。
4. Quality Checker 首次输出仍执行完整语义验证。只有既有模型语义修复后的重复问题满足以下精确
   条件时，才删除对应不可验证问题：
   - `brand.other_company_name` 的引文确定不是可识别企业名称；
   - `fact.high_risk.unsupported` 的准确位置确定不具备承载高风险事实的资格。
5. 位置、分类、严重度或引文不能确定验证时继续失败；真实第三方企业名称和位于合格位置的无证据
   高风险事实继续 BLOCK。恢复后模型分数保持不变，只根据其余问题和冻结 warning 上限重算 decision，
   并继续执行完整确定性风险扫描。

## 兼容性与恢复边界

- 不新增数据库迁移、公开 API 或前端契约。
- 不降低证照、品牌、事实、推广词或任何冻结质量门槛；服务端不生成正文、引用、分数或质量结论。
- 不自动重评旧候选、旧内容和旧质量报告。显式重新质检仍读取候选首次生成时冻结的 Writer 输入；
  需要后来上传的证照时必须发起新候选。

## 验收

- 证照核验和选择建议不再误报；实际持证、有效和齐全断言仍在缺少精确证据时 BLOCK。
- 同一字段同时含无证据证照声明和列举网禁止推广词时，可在不改动无关字段及锁定区块的前提下定向
  修复；任一风险仍存在则失败。
- 定向修复拒绝日志不含模型原始正文、Provider 响应或凭据。
- 质检语义修复后的两类精确误报可恢复；真实品牌和高风险事实问题不得被删除。
- Skills、AI Worker、类型检查和全量回归通过。
