# ADR-0025：官网分阶段生成与证据质量计分

- 状态：已批准实施
- 日期：2026-07-27
- 影响范围：仅 `official_site`
- 前置决策：ADR-0012、ADR-0014、ADR-0021、ADR-0023

## 1. 问题

官网稿原先要求模型在一次 Content Writer 输出中同时返回母稿、官网稿、正文块、引用、FAQ、slug、meta description 和 Schema.org。DeepSeek 当前只提供 JSON mode，不能由 Provider 强制执行严格 JSON Schema。深层且重复的输出容易被截断或违反 Schema，并使已经合格的正文因 FAQ 或技术字段错误而整体重写。

原 GEO 证据分还按引用条数递增：一至四条引用只能得到 70–85 分，无法通过事实准确性 90 分门禁；五条不相关引用反而可能得到高分。引用数量不能代表证据支持质量。

## 2. 决策

1. 只含 `official_site` 的生成任务使用官网专用分阶段流程；包含其他平台的任务继续使用既有一次母稿加多平台变体流程。
2. 第一阶段只让模型返回标题、摘要和正文块。标题 20–60 字，正文硬门槛为 1,300–2,500 个有效字符，模型写作目标为 1,500–2,200 个有效字符，以覆盖模型自然计数与服务端排除空白、标点和符号后的偏差；至少 8 块、3 个分节标题和 1 个清单，首个正文块必须直接回答主题。不得用重复、空话或虚构事实填充长度。
3. 正文成功后立即保存为既有母稿内容版本，不等待 FAQ 或平台技术字段。
4. 第二阶段只让模型依据已完成正文生成 4–6 个 FAQ，不得引入正文中没有的新事实。FAQ 的结构化输出最多独立尝试 3 次，不重新生成已经保存的正文。
5. slug、meta description、Schema.org、平台代码、空标签和引用映射由服务端确定性组装。模型不得生成这些技术字段。
6. 引用映射只允许输入中真实存在的 citation ID；未知 ID 触发正文修复，仍未修复则生成失败，不得持久化或用于加分。
7. 官网自动重写继续根据质量问题重写完整正文，但输出仍为浅层正文结构；长度不足时必须扩展有实质信息的解释、判断标准、步骤和风险边界至 1,500–2,200 个有效字符，不得贴着 1,300 硬门槛生成。正文通过后再独立生成 FAQ 和确定性技术字段。
8. 证据分按声明与引用原文的支持质量计算，不按引用条数计算。直接支持的单条证据可得 95 分；部分支持、冲突或不支持按风险权重降分。
9. 涉及数字、价格、电话、地址、资质、规模、排名或承诺的高风险声明，其关键值必须在引用原文中精确出现；否则判为不支持。
10. 官网已发布品牌档案继续按 ADR-0014 作为企业第一方依据。内容没有声称外部引用且事实未超出品牌档案时，证据基线为 95 分。
11. ADR-0021 的质量阈值、任一 BLOCK 阻断、最多重写 3 次和官网发布最多重试 3 次均不改变。

## 3. 内部契约

新增两个内部 JSON Schema，不新增公开 API：

- `official-site-article-draft@1`：`title + summary + blocks[]`；
- `official-site-faq-draft@1`：`faq[4..6]`。

既有 `content-writer-input@1`、内容版本、生成运行、Outbox 事件和发布 API 保持兼容。每日官网候选在 Brief constraints 中写入 `official_site_direct=true`；只选择官网的普通生成任务也自动进入该流程。

## 4. 持久化与恢复

不新增表和迁移：

1. 既有 master generation run 保存正文阶段；
2. 既有 official-site variant run 保存 FAQ 和确定性技术字段组装后的官网稿；
3. FAQ 失败不会删除母稿；同一生成事件重放时可复用已成功母稿；
4. 每日批次在平台稿最终失败时继续按 ADR-0023 淘汰候选并自动补位。

## 5. 安全边界

1. 技术字段只能从已生成正文确定性派生，不能借机增加经营事实。
2. FAQ 只能概括正文，不能添加价格、地址、电话、资质、客户数量、排名或承诺。
3. 数字等高风险事实必须精确匹配证据；字符重合度只用于普通声明的辅助判定。
4. 确定性证据评分不替代 Quality Checker 和阻断规则，两者均通过后才能发布。

## 6. 明确不做

1. 不降低任何官网自动发布门禁。
2. 不改变其他六个平台的生成、审核或发布流程。
3. 不新增向量模型、NLI 模型或第三方事实核验服务。
4. 不改变官网发布 API、幂等键或数据库表。
5. 不把 FAQ、Schema.org 或引用数量当作正文质量的替代指标。
