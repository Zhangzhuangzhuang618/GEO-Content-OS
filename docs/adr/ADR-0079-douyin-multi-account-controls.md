# ADR-0079：抖音多账号内容隔离与资源控制

- 状态：已批准实施
- 日期：2026-09-02
- 任务：T162
- 影响范围：PUB-01、抖音每日批次、AI Worker、Douyin Browser Worker、数据库
- 前置决策：ADR-0037、ADR-0073、ADR-0074

## 背景

一个工作区已经可以连接多个抖音账号，但各账号原先共用项目关键词轮转，缺少账号级内容定位，也没有
公司级的同日选题占位。两个策略可能在同一天选择相同关键词和搜索意图，并按相同时间启动 Chromium。
账号级 Profile 已经隔离，但不同账号可以并行占用浏览器资源；生产曾出现 Chromium 内存和 CPU 压力，
因此仅依靠 Profile 隔离不足以保护单机发布。

## 决策

1. 抖音自动化策略增加账号定位、服务范围、目标地区和主题池。启用或更新抖音策略时四项必须完整；
   历史策略在迁移时保留空值以保证迁移兼容，但新批次遇到空配置时失败关闭并提示补齐。搜狐号和列举网
   不接受这些字段。
2. 每个候选确定性选择一个地区、服务和主题，并将完整策略及当次选择冻结到 Writer Input。标题主体、
   检索焦点、受众和生成指令都使用同一选择；模型不得扩展到配置外的地区、服务或其他主题。
3. 新表 `douyin_topic_reservations` 以
   `tenant_id + workspace_id + business_date + keyword_term + search_intent` 建立唯一占位。工作区作为当前
   公司边界；同一公司多个抖音账号同日不能生成相同“关键词＋搜索意图”组合。候选未取得任何证据时
   释放占位；候选成功创建后保留占位作为审计记录。
4. 抖音排期在同一租户和工作区范围内读取其他抖音策略的当天任务，并使用事务级 advisory lock 防止
   并发计算出相同结果。发生冲突时按 20 分钟间隔顺延；搜狐号和列举网继续使用原策略内排期规则。
5. Douyin Browser Worker 在保留 `douyin/{tenantId}/{accountId}` Profile 路径和账号锁的基础上，对发布
   与发布状态核验增加进程级全局锁，同一 Worker 实例同时只运行一个自动 Chromium 操作。调度错峰降低
   排队概率，全局锁是实际并发上限。
6. 本次不增加可配置“服务器 ID”或分布式资源调度。当前生产只有一个 Douyin Worker 实例；如果未来
   横向扩容，再单独设计跨实例租约，不能把本次进程锁误当成跨主机锁。

## 数据与兼容性

- 迁移 `0055_douyin_multi_account_controls` 为现有策略增加 4 个字段，并新增 1 张占位表。
- 当前业务表从 92 张增至 93 张；公开端点仍为 170 个，只扩展既有策略请求和响应。
- 旧内容、旧质量报告、旧发布任务和历史批次不重写、不重排。已有空定位策略必须先在 PUB-01 补齐配置，
  才能继续生成新的抖音日批。
- 公司边界沿用租户内工作区，不推测企业名称，也不跨租户读取内容或排期数据。

## 验收

1. 两个抖音策略分别保存并回显各自的定位、服务、地区和主题池；缺少任一项不能启用。
2. Writer Input 同时冻结完整策略和当次选择，标题主体与检索焦点使用选择结果。
3. 同工作区两个账号同日使用同一关键词时，得到不同搜索意图占位；数据库拒绝重复组合。
4. 同工作区抖音发布时间至少相隔 20 分钟，并发调度不能产生重复或过近时间。
5. 两个账号并发请求发布或状态核验时，单个 Worker 的 Chromium 自动操作最大并发为 1；Profile 路径
   仍按租户和账号隔离。
6. 全新数据库迁移得到 93 张表；Contracts、API、Web、AI Worker、Douyin Worker、OpenAPI、构建和
   Release static gate 通过。
