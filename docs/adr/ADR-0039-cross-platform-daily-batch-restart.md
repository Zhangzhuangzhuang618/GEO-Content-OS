# ADR-0039：跨平台日批保留历史并重新发起

- 状态：已批准实施
- 日期：2026-08-17
- 任务：HOTFIX-20260817-06
- 影响范围：官网、百家号、搜狐号、列举网及后续接入日批自动化的平台
- 前置决策：ADR-0024、ADR-0032、ADR-0037

## 背景

官网已经支持候选耗尽后保留旧批次并创建新尝试；百家号、搜狐号和列举网只能停止在
`attention_required`，用户无法在不删除历史记录的前提下继续补足当天目标。不同平台若各自实现
“重置批次”，容易重新评估旧报告、重复创建发布任务或覆盖审计记录。

## 决策

1. 所有具备日批自动化的平台采用统一恢复语义：旧批次、候选、内容版本、质量报告、发布任务和审计
   记录保持不变；恢复动作只创建同一业务日期的下一 `attempt_no`。
2. 新尝试的候选上限独立计算；当天已合格、已排期、发布中、已发布及发布失败所占名额跨全部尝试
   汇总。新尝试只补足剩余目标，不重新生成已经占用名额的内容。
3. 发布失败只处理原发布任务，不通过新尝试生成替代文章，防止外部平台实际成功但本地误判时重复
   发布。
4. 只有候选上限耗尽，或平台已经实现的人工终止状态，才能创建新尝试。前置资料缺失且零候选仍
   原地重试；运行中、已排期、已完成、发布失败和历史日期不可通过该入口重置。
5. 请求必须携带当前批次版本和项目 ID，使用幂等键、事务、乐观锁和审计。每个平台同一业务日期
   最多一个 `running` 或 `scheduled` 尝试。
6. 冻结质量门槛、最多三次按报告重写、旧报告不可变和真实发布状态判定全部保持不变。
7. 后续平台接入日批自动化时必须复用统一的 restart 请求契约、`attempt_no` 数据模型和跨尝试计数
   规则；仅有导出或人工发布能力的平台不因此获得虚假的日批入口。

## 接口与数据

- 官网继续使用 `POST /platform-accounts/{id}/official-site-automation/daily-batch/restart`。
- 百家号新增 `POST /platform-accounts/{id}/baijiahao-automation/daily-batch/restart`。
- 浏览器平台新增 `POST /platform-accounts/{id}/content-automation/daily-batch/restart`，当前服务搜狐号和列举网。
- `browser_platform_daily_batches` 增加 `attempt_no`、日期加尝试唯一约束和单活跃尝试唯一索引。

## 验收

- 候选耗尽后可从管理界面保留历史并创建下一次尝试。
- 新尝试只生成当天缺口，当前尝试候选计数从零开始，当天排期和发布数跨尝试汇总。
- 旧候选、质量报告和发布任务不被修改或重新评估；发布失败不触发替代生文。
- 并发或重复请求只创建一个新尝试，过期版本返回冲突。
- Contracts、迁移、OpenAPI、API、AI Worker、Publisher、Web 和相关测试通过。
