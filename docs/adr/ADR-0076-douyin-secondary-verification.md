# ADR-0076：抖音登录二次验证

- 状态：已批准实施
- 日期：2026-08-28
- 任务：T161
- 影响范围：抖音浏览器登录状态机、内部网关、Publishing API、PUB-01 与私有诊断制品
- 前置决策：ADR-0019、ADR-0036、ADR-0073

## 背景

抖音扫码授权完成后，创作者中心可能继续要求短信验证码、原设备扫码或交互式验证码。现有无界面
Worker 将这些页面统一返回为 `CAPTCHA_REQUIRED`，既没有可操作入口，也没有保存脱敏页面证据；
前端轮询还可能在验证未完成时打开编辑页，破坏当前挑战页面。

## 决策

1. 扩展既有抖音登录和重新认证请求体，不新增公开端点。除普通二维码外，只接受
   `verification_device_qr`、`verification_sms_send` 和 `verification_sms_verify` 三种明确动作。
2. 二次验证必须在原账号的独立浏览器 Profile 和当前页面中继续。`attention_required` 状态轮询先检查
   当前挑战，不得导航到编辑页；挑战消失后才重新核验登录态。
3. 短信只在用户明确点击后发送；验证码只在当次请求内传给 Worker，不写数据库、对象存储、审计或
   日志。原设备二维码仅作为 `no-store` 响应返回，不写入诊断截图。
4. 只有创作者中心出现明确已登录证据后，才导出并加密保存 storage state、清除挑战错误并恢复账号。
   验证结果不明确时失败关闭，不得把二维码授权或页面跳转推断为登录成功。
5. 登录挑战保存全页 PNG 前必须隐藏全部页面文字与背景图，并遮盖输入框、图片、画布、iframe、SVG、
   视频、头像和账号区域。
   脱敏截图写入私有对象存储；会话错误只保存对象 URI、内容哈希、挑战类型、可用方式、是否存在验证码
   输入框、去除查询和片段后的 origin/path，以及由这些白名单特征生成的 SHA-256 页面签名。
6. API 不返回原始 DOM、页面正文、Cookie、storage state、手机号、邮箱、昵称、短信码或带查询参数的
   URL。返回结构使用严格契约，额外字段直接拒绝。
7. 滑块、拼图及其他交互式验证码仍保持 `attention_required`。系统只展示脱敏诊断，不识别、破解或
   绕过平台风控；未知页面结构返回 `PAGE_SIGNATURE_CHANGED`。
8. 本次复用 `douyin_browser_sessions.last_error_json` 和现有私有对象存储，不新增数据库迁移或表。
   当前基线保持 92 张表、迁移 0053 和 170 个公开端点。

## 取舍

- Worker 进程存活且当前挑战页面仍在时可继续验证；进程重启后保留最后一份脱敏诊断，但用户需要重新
  发起扫码，不尝试从持久化页面内容恢复一次性挑战。
- 本期只支持页面明确提供的短信或原设备扫码，不增加远程桌面、通用浏览器控制台或验证码识别能力。

## 验收

1. 扫码后出现短信或原设备验证时，PUB-01 展示脱敏诊断及对应操作，轮询不离开挑战页面。
2. 短信发送只能由用户明确触发；正确验证码或原设备扫码完成后保存加密登录快照并恢复账号。
3. 验证码、二维码、Cookie、账号身份信息和未脱敏截图不进入数据库、对象存储元数据、API 响应或日志。
4. 交互式验证码和未知页面继续失败关闭，不降低 ADR-0073 的账号隔离与安全门槛。
5. Contracts、Worker 单元/浏览器集成测试、API、Web、OpenAPI、生产构建和 Release static gate 通过。
6. 本任务不自动部署生产；部署及真实账号验证需用户单独授权。
