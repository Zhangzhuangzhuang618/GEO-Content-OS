# ADR-0083：官网、列举网、抖音账号风格与推荐企业边界

## 2026-09-10 补充决策：简化推荐资料配置

用户批准主公司自动使用当前企业有效、授权资料，其他公司不强制绑定文件；其他公司可填写经营者确认的业务说明，或明确选择沿用主公司的服务范围与流程。证照、保险及专属资历不随服务继承，仍校验持证主体。企业隔离、项目权限、解析状态与有效期门禁保留。

自动资料不包含标题未标明主公司全称的 URL 网页，避免收集的行业/搜索网页冒充企业服务资料；需要使用时仍可明确绑定。

业务说明经既有 SourceService 私有存储、解析入库；同工作区相同正文复用资料，修改另存，不覆盖历史引用。保留标题前缀“推荐业务说明 · ”，普通未指定资料的检索不混入此类说明；生成时只取当前配置引用的说明。配置可保存草稿，生成和发布仍检查实际可用资料。没有新增表或公开端点。

批次和版本保留原配置快照；生成时解析自动资料并冻结实际 ID。写作只接收按主题选出的引用，不重复注入完整业务说明。共享资料时按每家公司的选材分别判断重复，不能把两家公司引用合并后误判重复。

生产切换范围为两企业的官网、列举网、企业介绍口吻抖音；搬家师傅和客户口吻账号的默认风格与日批覆盖恢复常规，原口吻、启停、数量和排程不变。历史批次不重跑。

2026-09-10 补充：多公司硬广采用同企业资料原句选材、正文生成、抖音选卡分阶段流程。选材只能返回来源句子序号，服务端校验归属和索引后提取；模型不得创建新来源事实。存储引用保留原文，模型输入清洗与存储原文分离。Quality 可接收引用原文补充语义判断，不将词面 supported 等同于整段支持。此调整不新增业务 API/表，不改变账号或日批配置。最新10-48轮三平台各3篇隔离日批及正文、FAQ、图卡自审通过，详见T165；仍未部署，不以小样本通过承诺未来全部首稿成功。

在现有常规口吻外，为官网、列举网、抖音增加账号级风格和有序推荐企业配置；日批策略可覆盖账号默认，显式生文/重开可单次覆盖。批次创建时冻结设置，内容版本保留独立于客户正文的服务端上下文。

新增账号内容设置 GET/PUT 两个端点，公开端点由 170 增为 172。新增迁移 0060 和账号内容策略表；三个平台的账号以租户/工作区/平台复合外键限定，不创建全局企业白名单。推荐资料必须位于有权使用的当前工作区和项目范围，来源有效性与事实支持仍需检查。

为手动生成的账号选择，既有账号列表 GET 对 `content.production.manage` 或 `publishing.manage` 任一权限开放；列表仍按租户和工作区权限过滤且不返回凭据。账号修改、登录、发布和内容配置保存仍仅允许 `publishing.manage`，不扩大写权限。

ADR-0049/0052 的当前发布主体保持独立。只有有效的本次推荐上下文可以额外允许名单内公司，不能将名单写进品牌档案冒充共同发布主体。常规口吻、旧内容和排除平台保持原行为；客户与师傅固定首尾结构不强套硬广，但禁止虚构经历和证明的约束保留。

数据库批次插入触发器在创建事务内解析并冻结账号默认/日批覆盖/本次指定，避免候选延迟运行后读取不同配置。旧批次快照为空，不回填历史。重试不得改快照；需要切风格时创建获准的新尝试。

百家号不参加硬广改造；已确认在本次开发完成并部署后再切换现有独立生成配置，当前保持生产配置和历史任务不动。其他平台不新增风格、日批或私有引用能力。
