# ADR-0066：官网服务电话由企业资料统一继承

- 状态：已批准实施
- 日期：2026-08-21
- 任务：HOTFIX-20260821-04
- 影响范围：KNOW-01、CONT-05、PUB-01、Workspace Contract、AI Worker、Publisher Worker、官网 Render Adapter
- 延续决策：ADR-0014、ADR-0025、ADR-0052、ADR-0060

## 已核验事实

1. 官网发文需要稳定展示企业服务电话，但既有内容文档的 CTA 可由模型或人工任意修改，
   不能作为权威号码来源。
2. 平台账号凭证属于发布连接信息，不应承载企业对外联系事实；上传的任意文档也不能自动
   成为可公开电话。
3. `workspaces.settings_json` 已有租户和工作区隔离、版本号、乐观锁与审计记录，可在不新增数据表
   的前提下保存结构化服务电话。

## 决策

1. 在 `workspace-settings@1` 增加可选字段 `official_site_service_phone`，只接受不含空格和连字符的
   中国大陆手机号、座机、400 或 800 电话。它是当前工作区的唯一权威官网服务电话。
2. 只在 KNOW-01 企业资料中提供维护入口，仅企业所有者和管理员可修改。PUB-01 只展示继承值和
   前置条件，不再保存独立电话或开关。
3. 启用官网自动化前必须已配置电话。自动化仍启用时不允许清空电话；缺少电话的日批进入
   可恢复的需处理状态，不生成或伪造内容。
4. 官网内容首次生成、质量报告重写和人工保存时，服务端在内容版本和 hash 落库前删除重复
   CTA 块，将当前电话合并到顶层 CTA，并保证该号码只出现一次。人工仍可编辑引导文案，不能删除
   或替换权威号码。
5. Quality Worker 只在官网变体的质检上下文中合并该电话，且保留品牌档案已有的其他联系信息。
   确定性门禁要求 CTA 含当前号码且全文恰好出现一次。其他平台不获得该新证据，现有电话禁止规则
   保持不变。
6. Publisher 领取官网任务时再读取当前工作区电话。官网 Render Adapter 升级到
   `official-site-render-rules@1.3.0`，只有内容 CTA 中恰好出现一次当前电话才允许发布。
7. 不改写、不重评旧内容和旧质量报告。旧官网任务若缺少当前电话、号码不一致或重复出现，最终
   发布校验必须阻断；此时应人工保存或重新生成新版本，再走新质检和发布链路。

## 后果

- 无数据库迁移、无新增公开端点；工作区契约与 OpenAPI 响应模型增加可选字段。
- 保留开关的官网自动化不能清空电话；更换电话后，仍绑定旧号码的旧任务会在发布前失败关闭。
- 部署需重建 API、Web、AI Worker 和 Publisher Worker；其他浏览器发布 Worker 无行为变更。

## 验收

- 企业管理员可在 KNOW-01 为当前工作区保存合法电话，无权角色只读，无效格式被拒绝。
- 缺少电话时不能启用官网自动化，日批显示可处理的前置条件错误。
- 生成、重写和人工修改后的最终官网内容只含一次当前电话，且电话位于顶层 CTA。
- 质检和 Publisher 均拒绝缺号、错号或重复号码；其他平台的电话证据和禁止规则不变。
- Contracts、API、Web、AI Worker、Publisher Worker、官网 Render Contract、OpenAPI 与 Web 构建通过。
