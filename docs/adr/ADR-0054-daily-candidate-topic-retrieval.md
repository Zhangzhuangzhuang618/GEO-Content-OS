# ADR-0054：每日候选按主题检索并冻结企业证据

- 状态：已批准实施
- 日期：2026-08-20
- 任务：HOTFIX-20260820-01
- 影响范围：官网、百家号独立生文、搜狐号、列举网每日批次，API 与 AI Worker 检索运行时
- 延续决策：ADR-0015、ADR-0023、ADR-0024、ADR-0032、ADR-0037、ADR-0039

## 已核验事实

现有每日批次在创建候选前按资料可信级别和更新时间固定读取最多 12 个片段，同一批次的所有候选
复用相同片段。候选标题、关键词和内容角度不同，但证据并未随主题重新检索，因此可能把无关资料
送入模型，也可能遗漏资料库中更相关但更新时间较早的片段。手动生文已使用查询向量、FTS 与
pgvector 混合检索、重排和来源分散，日批没有复用该链路。

## 决策

1. 官网、百家号独立生文及其独立回退、搜狐号和列举网日批，每创建一个候选都单独检索证据。
   百家号直接改写已发布官网文章的派生链路继续复用官网文章及其引用，不重复检索。
2. 检索查询由当前候选的关键词、标题、内容角度、内容目标和目标受众组成，规范化后最长 500 字符。
3. API 与 AI Worker 共用同一套租户隔离混合检索实现，强制 tenant、workspace、project、用户项目
   权限、资料状态、可信级别和业务日期有效期过滤；先生成查询向量，再融合 FTS 与 pgvector 结果并重排。
4. 每个候选最多选择 5 个片段，同一资料最多 2 个片段。重排不可用时允许沿用既有融合顺序降级，
   但不得放宽租户、项目、可信级别、有效期或来源数量边界。
5. 选中的资料 ID 写入该候选的 `brief_sources`，命中片段原文写入不可变 Content Writer 输入并参与
   `input_hash`。后续质量重写继续加载原始 Writer 输入，不重新检索或替换证据。
6. 没有可用资料或当前主题没有任何可检索证据时，候选不创建，批次进入既有“需要处理”路径。
   Embedding 或检索运行时的瞬时错误继续由调度器重试，不得由服务端伪造引用或质量结论。
7. 不修改质量分数、BLOCK 规则、候选上限、排期规则或旧批次。既有候选、内容、质量报告和发布任务
   不自动重新检索、改写或重投。

## 后果

- 同一批次不同候选将得到与主题相关且可追溯的独立证据集合，`brief_sources` 由检索结果确定。
- 每个新候选增加一次查询 Embedding 和一次混合检索/重排；默认本地适配器不增加外部模型费用。
- 新增共享检索包，不增加数据库迁移或公开 API。

## 验收

- 查询完整包含关键词、标题、角度、目标和受众，并使用批次业务日期执行有效期过滤。
- Writer 输入最多 5 个引用，任一资料最多 2 个；对应资料 ID 与 `brief_sources` 一致。
- 官网、百家号独立生文、搜狐号和列举网日批均通过同一检索入口创建候选。
- 重写继续复用候选创建时冻结的引用；旧批次和旧报告保持不变。
