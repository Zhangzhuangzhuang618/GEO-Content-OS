# ADR-0063：日批证据检索请求 ID 边界

- 状态：已批准实施
- 日期：2026-08-21
- 任务：HOTFIX-20260821-01
- 影响范围：官网、百家号独立生文、搜狐号与列举网日批证据检索，AI Worker
- 延续决策：ADR-0054、ADR-0057

## 已核验事实

HOTFIX-20260820-05 为主题检索与证照检索增加用途前缀后，Embedding 请求 ID 分别达到 82 和
86 个字符，超过适配器 80 字符上限。Citation Search 使用相同完整 64 位 SHA-256，同样超过
80 字符。请求在候选任何数据库写入前被拒绝，批次保持 `running`、没有候选条目，并由调度器反复
重试。官网、百家号独立生文、搜狐号与列举网日批共用 `DailyCitationRetriever`，因此共享该故障。

既有单元测试使用不校验请求 ID 的假 Embedding 与 Citation Search，未覆盖真实适配器的长度契约。

## 决策

1. 候选范围、查询和用途继续参与完整 SHA-256 计算；传入 Embedding 与 Citation Search 的请求 ID
   只使用哈希前 32 位，并保留 `topic` / `authority` 与 `embed` / `search` 前缀。
2. Embedding 输入项 ID 使用同一 32 位请求键。四类请求 ID 必须确定性生成、彼此区分，长度保持在
   适配器允许的 16 至 80 字符范围内。
3. 不修改检索查询、租户与项目隔离、有效期、可信级别、来源上限、候选上限、质量门槛或排期规则。
4. 同一业务日仍为 `running` 的批次由 AI Worker 后续巡检继续处理；已跨日终止的批次、旧候选、
   旧内容和旧质量报告不自动恢复或重新评估。
5. 单元测试必须同时经过主题与证照检索，锁定四类请求 ID 的前缀、32 位十六进制键、唯一性和长度
   上限，避免不执行真实适配器校验的测试替身再次掩盖该问题。

## 后果

- 无数据库迁移、公开 API、状态机或前端变化，仅需重新构建部署 AI Worker。
- 请求 ID 仍可区分检索用途和阶段；完整检索输入、内容证据及其不可变哈希不截断。
- 当天未写入候选的 `running` 批次无需重建，部署后会从候选创建阶段继续执行。

## 验收

- 主题与证照的 Embedding、Citation Search 请求 ID 均不超过 80 字符并通过现有格式校验。
- 四类请求 ID 在相同候选输入下互不相同，重复运行结果稳定。
- `DailyCitationRetriever` 单元测试、AI Worker 类型检查与构建通过。
- 不改动冻结质量门槛，不伪造引用或模型质量结论，不自动重评旧内容。
