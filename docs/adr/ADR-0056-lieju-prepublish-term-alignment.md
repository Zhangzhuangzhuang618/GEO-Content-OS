# ADR-0056：列举网发布禁词前移到生成、质检与重写

- 状态：已批准实施
- 日期：2026-08-20
- 任务：HOTFIX-20260820-03
- 影响范围：Content Writer、确定性质检、列举网 Render Adapter、质量引导重写
- 延续决策：ADR-0037、ADR-0038、ADR-0045、ADR-0048

## 已核验事实

生产失败文章在风险提示中使用“不要轻信‘百分百满意’等绝对化承诺”。列举网 Render Adapter 对
“百分百”执行不区分上下文的字面硬拦截，因此在调用官方 API 前返回 `PROHIBITED_TERM`。该结果不
是列举网远端拒绝。

发布层的字面规则此前没有完整进入 Content Writer 的平台提示、生成后质量检查和浏览器平台质量
重写提示。文章因此能够通过生文与质量门禁，直到发布时才暴露确定性错误；普通发布重试复用同一
不可变内容版本，所以重复失败无法自行恢复。

## 决策

1. 在 Contracts 中维护列举网禁止宣传词的唯一确定性匹配函数。列举网 Render Adapter、Content
   Writer 生成后质量检查和 AI Worker 确定性预发布扫描必须复用该函数，不再各自维护漂移词表。
2. 继续阻断“最好、最佳、首选、权威、国家级、百分百、100%保证”及 ADR-0048 定义的明确排名
   宣传；即使原词出现在否定、引用、风险提示或举例中也必须阻断并要求删除原词后中性改写。
3. “第一步、第一阶段、第一时间、第一方”等普通顺序、时间和证据属性表达继续放行，不恢复宽泛
   的“第一”拦截。
4. Content Writer 平台提示在首稿阶段显式声明字面边界。首稿仍按既有质量策略最多执行一次语义
   修复；确定性质检作为发布前兜底，命中后进入既有最多三次质量报告引导重写链路。
5. 重写必须把当前内容、当前质量问题和字面删除要求传给模型。服务端不得在质量检查后静默替换
   正文，也不得伪造通过结论。

## 兼容性与恢复边界

- 不降低冻结质量门槛，不改变列举网 Render Adapter 的硬拦截、官方 API、状态机或重试上限。
- 无数据库迁移和公开 API 变更。
- 旧内容版本、旧质量报告、旧发布任务和旧批次不会自动重新评估、改写或重投。
- 部署后，原失败任务直接普通重试仍会复用含禁词的内容而失败；必须显式重新质检并完成报告引导
  重写，或发起新的日批尝试生成新内容。

## 验收

- 生产失败句式在生成后质量检查和 AI Worker 确定性质检中均被发布前识别。
- 质量引导重写收到原问题及“否定、引用、举例也必须删除原词”的约束。
- Render Adapter 仍拒绝同一句式，证明发布硬门槛未被放宽。
- 普通“第一步、第一阶段、第一方”不被误伤。
- Contracts、Content Writer、AI Worker、列举网 Adapter 和 Publisher 相关测试、类型检查及构建通过。
