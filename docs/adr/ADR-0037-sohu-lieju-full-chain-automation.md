# ADR-0037：搜狐号与列举网全链路自动化

- 状态：已批准实施
- 日期：2026-08-16
- 任务：T153
- 影响范围：`sohu`、`lieju` 独立生文、机器质检重写、配图、排期和浏览器发布
- 前置决策：ADR-0028、ADR-0030、ADR-0032、ADR-0034、ADR-0035、ADR-0036

## 背景

搜狐号和列举网已接入普通内容生成、人工审核、排期和托管浏览器发布，但没有独立日批策略，不能像
官网和百家号一样从选题到发布自动运行。列举网属于分类信息平台，允许企业介绍服务并表达合理的
推广意图；原有约束过度接近资讯平台口径，容易把合规的服务说明误判为营销风险。

## 决策

1. 新增搜狐号与列举网共用、但按 `platform_code` 严格隔离的浏览器平台自动化策略、运行、每日批次
   和批次项表。不得迁移或复用官网、百家号自动化表。
2. 两个平台首期只支持 `independent` 独立生成，不从官网文章派生。每天按策略幂等创建批次，目标数
   1–10、候选上限不超过 30，并按配置时段自动排期。
3. 每篇候选继续执行冻结门禁：GEO>=85、事实>=90、品牌>=90、可读性与安全>=85、问题覆盖>=80、
   平台适配>=80，任一 BLOCK 或非 `pass` 禁止发布。失败必须把当前质量报告问题传入全新模型调用，
   最多重写 3 次；仍失败进入人工处理。
4. 质量通过后进入既有自动配图。图片失败按 ADR-0030 降级，不改变文章质量结论，也不阻断排期。
5. 发布任务分别使用 `origin=sohu_automation` 与 `origin=lieju_automation`，沿用对应托管浏览器的登录、
   验证码、提交后对账、未知态和人工确认规则。平台失败不得反向修改其他平台内容。
6. 列举网内容允许明确介绍本企业服务范围、流程、可核验能力和适用场景，也允许自然行动引导，例如
   建议用户按页面联系方式咨询或提交需求。允许营销不等于允许无证据宣传：电话、微信、QQ、网址仍
   不进入正文；极限词、排名、竞品贬损、虚假价格、虚假资质、虚构案例、客户评价和结果保证继续
   BLOCK。联系人和电话只由加密账号配置在发布阶段填写。
7. 列举网无人值守仍以账号免验证码权益为前提。出现腾讯交互验证码、免费额度耗尽或风控时必须转
   人工处理，不自动绕过，也不重复提交。
8. 批次候选耗尽时，已合格文章先排期，批次再进入 `attention_required`；发布失败只重试原发布任务，
   不重新生成内容，不降低门禁。

## 接口与数据

- 新增 `browser_platform_automation_policies`、`browser_platform_automation_runs`、
  `browser_platform_daily_batches`、`browser_platform_daily_batch_items`。
- 新增 `GET/PUT /platform-accounts/{id}/content-automation`，只接受 `sohu` 或 `lieju` API 账号。
- 新增 `content.variant.browser_platform_rewrite_requested.v1` 事件。
- 扩展自动配图平台范围及发布任务来源枚举。

## 不做

1. 不新增搜狐号或列举网的官网派生模式。
2. 不自动接受验证码、购买列举网套餐或伪造远端成功状态。
3. 不自动重新评估旧内容、旧质量报告或旧发布任务。
4. 不因列举网允许推广表达而降低事实、品牌、安全或平台适配门槛。

## 验收

- 两个平台可分别启用日批，互不读取或更新对方策略、运行和批次。
- 生文后自动质检；不通过时重写请求包含当前内容和当前报告问题，最多 3 次。
- 合格内容自动配图、排期并创建正确来源的发布任务。
- 搜狐号继续如实标记 AI 内容；列举网正文允许合规服务推广但阻断联系方式与高风险宣传。
- 列举网出现验证码时停在人工处理，不重复提交。
- Contracts、迁移、API、AI Worker、Publisher、Web、单元和集成测试通过。
