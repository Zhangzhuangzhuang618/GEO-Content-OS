# ADR-0036：搜狐号与列举网临时凭据登录

- 状态：已批准实施
- 日期：2026-08-14
- 任务：T152
- 影响范围：搜狐号与列举网托管浏览器登录、API 契约和发布管理界面
- 前置决策：ADR-0028、ADR-0034、ADR-0035

## 已核验的平台事实

2026-08-14 使用两个平台公开登录页只读核验：搜狐官方登录弹窗同时提供账号密码和中国大陆手机号登录；手机登录固定要求手机号、图形验证码和短信验证码。列举网官方 `/login/` 只提供用户名密码登录，另有既有 QQ OAuth 登录，没有手机验证码登录入口。

## 决策

搜狐保留微信扫码，并新增账号密码和手机验证码登录。手机流程分为获取图形验证码、用户输入图形码并明确点击发送短信、输入短信码完成登录三步；系统不自动识别、代填或绕过图形验证码。

列举网保留 QQ OAuth，并新增官方用户名密码登录。不得展示或实现平台不存在的列举网短信登录。

账号、用户名、密码、手机号、图形码和短信码只在 Web → API → 对应浏览器 Worker 的单次同步请求与 Worker 当前浏览器页面内存中存在，不写入平台账号凭据、数据库、Outbox、幂等记录、审计详情、日志或测试快照。密码输入在请求完成后清空；Worker 重启会使未完成的短信挑战失效，用户必须重新获取图形验证码。认证成功后仍只保存既有加密 storage state，明文 Profile 仍限于受限 `tmpfs`。

生产环境的 API → Worker 网关必须继续限制在容器私网或主机回环网络，不得把浏览器 Worker 网关直接暴露到公网；网关 Bearer Token 仍为必需项。

发送短信属于用户明确点击触发的外部副作用，不允许页面打开、轮询或重试自动发送。错误账号、错误验证码、额外验证码、风控和页面签名变化均失败关闭。

本 ADR 仅替换 ADR-0034、ADR-0035 中“只允许扫码登录”的登录方式限制；发布门禁、对账、验证码阻断和真实发布授权边界保持不变。公开端点数量不变，既有登录与重新认证端点增加受约束的请求体。

## 明确不做

1. 不保存或自动轮换第三方平台密码。
2. 不自动识别、购买、破解或绕过任何验证码和风控。
3. 不为列举网伪造手机验证码能力。
4. 不因新增登录方式改变发布成功判定或质量结论。

## 上线门禁

Contracts、API、Web、两套 Worker 单元测试和本地 Chromium 页面仿真必须通过；测试必须证明登录请求不会回显密码，导出的 storage state 不包含账号、用户名、密码或手机号。真实账号登录和短信发送只由用户在部署后自行触发。
