# ADR-0029：关键词表格预检与异步分批导入

- 状态：已授权
- 日期：2026-08-03
- 任务：T147
- 适用范围：STR-04 关键词管理

## 背景

现有关键词接口每次最多写入 500 条，STR-04 仅支持文本粘贴。广州搬家关键词库包含
67,809 条结构化关键词，并携带地域、服务类型、业务搜索意图、场景、修饰词、建议页面类型和
生成来源。直接把全部词设为 active 会放大近似选题、页面关键词蚕食和每日生成输入规模。

## 决策

1. 新增 XLSX 预检入口，文件最大 25 MiB、数据行最多 100,000。默认选择名为“关键词库”的
   工作表，并在前 50 行内识别包含“关键词”“搜索意图”和“建议页面类型”的表头。
2. 预检同步完成文件校验和候选暂存；正式导入创建 Outbox 事件
   `strategy.keyword_import.requested.v1`，由 `geo-knowledge` 队列的 Knowledge Worker 每批最多
   500 条幂等写入。
3. 原始业务搜索意图固定映射到冻结的四类意图：
   - `informational`：价格咨询、服务方式、服务咨询、避坑咨询、时效咨询、攻略咨询；
   - `commercial`：核心服务、本地搜索、品质筛选、信任筛选、价格筛选、价格咨询、
     商圈/街道搜索、路线需求、时间需求、比较选择、服务方式、服务咨询、时效咨询；
   - `transactional`：本地搜索、联系方式、商圈/街道搜索、即时需求、路线需求、时间需求、
     预约转化、预约咨询；
   - 当前文件没有符合“查找指定品牌或指定页面”定义的 `navigational` 业务标签，不伪造该意图。
4. 同一文件中地域、服务类型、业务意图、场景、修饰词/路线、建议页面类型和生成来源完全相同的
   词归为一个确定性词簇。最早出现的词作为主关键词，其余词写入 synonyms，最多 50 个；这只折叠
   可验证的词序变体，不使用模型伪造语义等价结论。
5. 导入元数据以 `keyword-import-metadata@1` JSON 保存到关键词记录，不新增六个业务筛选列。
6. 预检后可按原始业务意图和建议页面类型选择候选，并指定平台、优先级及导入状态。默认状态为
   `disabled`；只有用户显式选择才导入为 `active`。
7. 新增服务端关键词游标分页接口。STR-04 不再依赖一次返回关键词集全部条目。
8. 预检、确认、完成和失败均保留任务状态并写审计；租户、项目和关键词集范围完全由服务端上下文
   校验。

## API

1. `GET /keyword-sets/{id}/keywords`
2. `POST /keyword-sets/{id}/imports/preflight`
3. `POST /keyword-sets/{id}/imports/{importId}/commit`
4. `GET /keyword-sets/{id}/imports/{importId}`

## 数据库

- 新增 `keyword_import_jobs`。
- 新增 `keyword_import_candidates`。
- `keywords` 新增 nullable `import_metadata_json` 和 `source_import_job_id`。
- 迁移序号升级为 0043，当前业务表数为 74。

## 不采用的方案

- 不把 67,809 条数据拆成浏览器端连续 500 条同步请求；页面关闭会留下不可追踪的半成品。
- 不自动把全部词设为 active。
- 不调用模型判断所有近义关系；当前只折叠可由结构化列确定的词序变体。
- 不复用指标域 `import_jobs`，避免把策略关键词导入伪装成分析指标导入。

## 验收

- 正确识别目标工作簿的工作表、表头、19 类意图和 10 类页面类型。
- 67,809 行可以完成预检，不受原同步写接口 500 条限制。
- 未知意图、缺失关键词、超限文件和错误表头被拒绝或计入无效行。
- 同一词簇只创建一个主关键词，词序变体进入 synonyms。
- Worker 重试不会重复创建关键词；任务进度可查询。
- 默认导入不激活；显式选择 active 后才供现有自动化流程使用。
- Contracts、迁移、OpenAPI、API、Worker 和 STR-04 测试通过。
