# ADR-0072：归档、搜狐正文与首次生成质量恢复

- 状态：已批准实施
- 日期：2026-08-26
- 任务：HOTFIX-20260826-02
- 影响范围：PostgreSQL 归档、搜狐托管浏览器、Content Writer、AI Worker
- 延续并修正：ADR-0034、ADR-0059、ADR-0061、ADR-0062

## 已核验事实

1. 生产 PostgreSQL 的归档目录中已存在与当前 WAL 内容完全相同的目标文件。旧
   `archive_command` 把“目标已存在”一律视为失败，导致同一 WAL 持续重试，累计失败并阻止
   `pg_wal` 回收。
2. 搜狐编辑器正文通过直接修改 `.ql-editor.innerHTML` 写入，没有同步 Quill 内部文档模型。后续
   上传图片或页面状态更新触发重绘时，Quill 会用旧模型覆盖正文，最终被既有正文完整性门禁拦截。
3. 生产失败候选的冻结输入已包含 5 条引用和 5 个已授权证照来源，证照确实传给 Content Writer。
   失败发生在模型连续两次仍保留未通过 `citation_map` 绑定的持证声明之后。既有最终定向修复只在
   质量重写存在 `revision` 时执行，首次日批生成因此直接失败；同一症状同时出现在搜狐、列举网和
   百家号。

## 决策

1. WAL 归档目标不存在时复制；目标已存在且与源文件逐字节相同时返回成功；目标存在但内容不同时
   继续失败且不得覆盖。归档恢复后仍通过归档统计和恢复演练验证，不删除未确认的归档文件。
2. 搜狐正文优先通过页面实际 Quill 实例的 `clipboard.dangerouslyPasteHTML` 写入，使页面数据模型与
   DOM 同步；页面未暴露 Quill 实例时，退回浏览器原生的可编辑区输入。发布前继续执行标题和正文
   完整性校验，不降低既有 80% 门槛。
3. Content Writer 完整重试后，如果全部剩余问题仅为不受支持的证照声明、列举网禁止联系方式或
   宣传词，以及可能同时存在的“重写未变化”，允许进入 ADR-0061 的限定文本修复；该能力适用于
   首次生成和质量重写，也适用于当前全部平台。
4. 定向修复继续最多两轮、禁用工具调用，并只允许模型返回目标字段替换。服务端必须复验目标
   完整性、锁定区块、联系方式、宣传词和逐项证照证据；模型没有正确绑定冻结证照时只能删除对应
   声明，服务端不得补写正文、引用、分数或通过结论。

## 兼容性与恢复边界

- 不修改冻结质量分数、BLOCK、事实、品牌、平台适配或证照证据门槛。
- 不自动重评旧候选、旧内容或旧质量报告；旧任务仍需显式恢复或重新发起新尝试。
- 不修改公开 API、数据库结构或发布状态机。
- WAL 归档冲突只允许人工核验，禁止自动覆盖不同内容的同名文件。

## 验收

- 已存在且内容相同的 WAL 可确认归档成功，归档失败计数归零并恢复 `pg_wal` 回收。
- 搜狐上传正文图片后，Quill 重绘不会清空正文，发布前完整性校验通过。
- 首次生成连续两次保留未绑定证照声明时，百家号、搜狐和列举网均进入限定修复；修复后仍有风险
  则保持 `CONTENT_QUALITY_INSUFFICIENT`。
- AI Worker、搜狐浏览器、类型检查、格式和相关集成测试通过。
