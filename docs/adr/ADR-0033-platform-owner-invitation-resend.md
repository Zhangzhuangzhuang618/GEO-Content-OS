# ADR-0033：平台企业所有者邀请重发

- 状态：已授权
- 日期：2026-08-12
- 任务：HOTFIX-20260812-03
- 适用范围：平台企业管理与企业所有者初始邀请
- 前置决策：ADR-0006、ADR-0009

## 背景

平台管理员创建企业时会同时创建企业、所有者待接受成员关系、默认工作区和邀请。企业切换只展示
已激活成员关系；如果初始邮件未送达或链接过期，企业会保留在平台企业管理中，但被邀请的所有者
无法完成接受，也无法在企业切换中看到该企业。现有系统没有面向平台管理员的重发入口。

## 决策

1. 新增 `POST /platform/tenants/{id}/owner-invitation/resend`，仅允许
   `platform_admin` 使用，并要求 CSRF 与 `Idempotency-Key`。
2. 只允许为状态正常、且仍存在唯一 `invited` 企业所有者及其待处理邀请的企业重发。企业暂停、
   所有者已激活、邀请历史缺失或状态不一致时返回状态冲突，不投递邮件。
3. 重发沿用旧邀请的角色和工作区范围。旧待处理邀请标记为撤销，追加一条新邀请；不修改或删除
   邀请历史，不重建企业、成员关系或工作区。
4. 新令牌只写入哈希并通过邮件投递，不进入 API 响应、审计或日志。API 仍只返回企业汇总视图，
   不暴露所有者邮箱。
5. 邀请替换、审计与邮件投递在同一个事务内完成；邮件投递失败时全部回滚，旧邀请继续有效。
   相同幂等键重放成功响应，不重复生成邀请或投递邮件。
6. 企业管理页为正常企业提供“重发管理员邀请”操作。后端状态校验是最终权限和一致性边界。

## 兼容性

- 不改变冻结质量门槛、内容质量报告或租户内容隔离规则。
- 不新增数据库表或迁移，继续遵守 ADR-0006 的邀请追加历史约束。
- 可执行公开端点数从 146 增至 147；契约、OpenAPI、SDK、`PROJECT_CONTEXT.md` 和测试同步更新。

## 验收

- 对初始所有者仍为 `invited` 的企业重发成功，旧邀请撤销且只新增一个待处理邀请。
- 相同幂等键重试不新增第二条邀请；响应和审计均不包含邮箱或令牌。
- 所有者已激活或企业非正常状态时返回 409，邀请历史不变化。
- 邮件投递失败时新邀请、旧邀请撤销和审计全部回滚。
