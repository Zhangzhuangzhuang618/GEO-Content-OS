# ADR-0081：抖音账号级内容口吻与局部修复

- 状态：已批准实施
- 日期：2026-09-02
- 任务：T163
- 影响范围：PUB-01、抖音每日批次、AI Worker、数据库
- 前置决策：ADR-0074、ADR-0077、ADR-0079

## 背景

T162 已把账号定位、服务范围、地区和主题池绑定到各抖音账号，但“账号要讲什么”和“账号以什么口吻讲”
仍没有独立配置。把口吻继续写进账号定位会使生成约束难以校验，也无法安全区分企业官方账号和一线师傅
视角账号。师傅口吻还可能诱导模型编造个人工龄、亲历、具体客户或客户反馈。

## 决策

1. 抖音自动化策略新增结构化 `content_voice`，当前只允许 `enterprise_official`（企业官方）和
   `frontline_mover`（一线师傅）。该字段独立于账号定位；启用抖音自动化时与定位、服务范围、地区和
   主题池一并要求完整。搜狐号和列举网不得设置该字段。
2. 每个候选把口吻单独冻结为 Writer Input 顶层约束 `brief.constraints.douyin_content_voice`，不得放入
   `douyin_account_strategy`。企业官方使用正式、清晰、克制的团队表达；一线师傅使用通俗、直接的现场
   实务表达和可执行动作。
3. 生成后执行确定性口吻检查。企业官方不得模拟个人师傅身份或个人亲历；一线师傅不得声称真实个人
   身份、工龄、亲历、具体客户、客户评价或客户案例。系统没有账号人物身份和个人经历的已核验事实
   通道，因此上述第一人称履历或案例一律作为不受支持内容拦截，不由模型自行判断真伪。
4. 口吻问题只进入有界字段级修复。抖音直生成只传入命中的语义字段；通用生成只传入命中的正文块。
   缺少一线现场视角时只选择一个未锁定正文段补充可执行动作。已通过的标题、段落、卡片、事实和引用
   不得随整篇重写。
5. 局部修复仍不得补造身份、资质、价格、指标、排名、保证、客户或案例；修复结果再次经过相同口吻和
   事实门禁。连续修复仍不合格时按现有失败关闭流程处理，不降低质量阈值。

## 数据与兼容性

- 迁移 `0056_douyin_account_content_voice` 为策略表增加 `content_voice`；现有抖音策略确定性回填为
  `enterprise_official`，非抖音策略保持空值，并由数据库约束平台和值域。
- 不新增业务表或公开端点；当前业务表仍为 93 张，公开端点仍为 170 个。
- 旧内容、旧批次、旧质量报告和历史发布任务不重写。迁移只给后续新候选提供默认口吻。

## 验收

1. 两个抖音账号可分别保存、回显企业官方和一线师傅口吻，且口吻不混入账号定位字段。
2. Writer Input 单独冻结 `douyin_content_voice`，生成提示明确采用对应口吻。
3. 一线师傅内容中的虚构身份、工龄、亲历、具体客户、客户评价和案例被确定性拦截。
4. 口吻不合格时模型只收到命中字段或一个需补现场动作的正文段，其他段落保持不变。
5. 全新数据库迁移仍得到 93 张表；Contracts、API、Web、AI Worker、OpenAPI、构建和 Release static
   gate 通过。
