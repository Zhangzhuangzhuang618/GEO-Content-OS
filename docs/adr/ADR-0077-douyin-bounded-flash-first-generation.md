# ADR-0077：抖音日批受限结构 Flash-first 生成

- 状态：已批准实施
- 日期：2026-08-30
- 任务：HOTFIX-20260830-09
- 影响范围：抖音浏览器平台日批、Content Writer 运行时、模型路由与用量追踪
- 前置决策：ADR-0011、ADR-0037、ADR-0073、ADR-0074

## 背景

生产修正模型环境变量后，18 个新抖音日批候选中有 4 个完成生成，11 个由既有确定性文案门禁淘汰，
3 个因 Content Writer 在两个只读工具之间反复调用而达到工具轮次上限。将工具达到上限后的下一次请求
强制改成无工具，只能终止循环，不能降低完整母稿加平台变体大 JSON 的结构负担，也不能解决首段、
结论、卡片推进、证据边界等内容问题。

抖音日批在创建事件前已经把已发布品牌资料、平台规则、引用片段和授权证照来源绑定进
`writer_input`。再次由模型调用工具读取同一份数据没有新增事实价值，却引入循环和额外调用。

## 决策

1. 仅对服务端创建、只请求 `douyin`、没有锁定块且显式标记
   `douyin_daily_direct=true` 与 `server_bound_generation_context=true` 的日批启用本流程。普通人工生成、
   其他平台和质量报告驱动重写保持原路径。
2. 日批首稿使用 Balanced/Flash 模型，但继续按 `quality` 阈值做确定性验收。Quality 模型和
   Quality Checker 仍保持 Pro，生产不得把 `CONTENT_MODEL_QUALITY_KEY` 或
   `QUALITY_CHECKER_MODEL_KEY` 改回 Flash。
3. 抖音日批首稿不注册任何工具。模型只返回受限浅层草稿：标题、8 个叙事槽位、3–8 个话题、固定
   7 张语义卡片的标题与正文，以及可选引用映射。服务端持有卡片顺序、`card_key`、`kind`、内容块
   键和类型、母稿/变体封装与 trace。
4. 服务端只执行结构组装、空白与句末标点规范化、引用白名单验证，不改写模型事实或正文含义。
   组装后的结果必须继续通过冻结 Content Writer Schema、ADR-0074 抖音编辑门禁、企业名称和资质
   证据门禁；不得为提高成功率降低任何阈值或伪造通过。
5. Flash 首稿未通过本地门禁时，只对门禁定位到的文字槽位执行一次无工具定点修复。结构化输出无效、
   定点修复无效或内容仍不合格时，才使用 Pro 按相同浅层 Schema 和问题清单完整兜底。
6. Pro 兜底仍不通过时以 `CONTENT_QUALITY_INSUFFICIENT` 失败。不得把工具上限关闭后的残缺文本保存为
   内容版本。
7. 后续独立 Quality Checker 继续使用 Pro；其报告未通过时，既有质量报告驱动重写仍使用 Pro。
   用量账本按每次实际返回的模型键记录 Flash 或 Pro，便于计算升级率和单候选成本。
8. 本决策不增加数据库迁移、公开 API、环境变量、日批候选上限、质量阈值或发布权限。

## 实施校正（HOTFIX-20260830-10）

生产验证发现，浅层草稿 Schema 中的文字 `minLength` 会在确定性内容验收前把可修复的短字段归类为
结构错误，导致 Flash 定点修复无法执行。浅层 Schema 因此只保留字段、类型、数组形状和最大长度；
原最小长度全部转为带目标 ID 的服务端确定性问题，并在首稿提示中明确。只有定点修复后仍不满足原
最小长度、ADR-0074 编辑门禁、企业名称、资质证据或冻结 Content Writer Schema 时才升级 Pro。

该校正不改变任何质量阈值。Quality Checker 的 `decision` 与浏览器自动化的
`automation_gate_json.passed` 仍是两层判断；前者为 `pass` 但分项分数未达冻结门槛时必须继续阻断。

## 取舍

- 固定语义槽位减少模型结构自由度，但保留每个槽位的文本创作空间，并直接对应 ADR-0074 的硬门禁。
- 单个候选可能发生 Flash 首稿、Flash 定点修复和 Pro 兜底；调用有界，不能承诺一定少于一次 Pro。
- 该路由只适用于服务端已绑定全部事实上下文的抖音日批，不能据此移除通用 Content Writer 工具。

## 验收

1. 抖音日批 generation run 使用 Flash 首稿键，启动日志同时显示 Flash 草稿、Pro 质量生成和 Pro
   Quality Checker 路由。
2. 正常浅层草稿一次 Flash 完成；所有相关请求工具列表为空，不能出现
   `SKILL_TOOL_LIMIT_EXCEEDED`。
3. 可定位问题只请求并应用指定字段；未知、重复、缺失或越界替换失败关闭。
4. Flash 结构失败或修复后仍不合格时才调用 Pro；Pro 结果继续通过相同冻结 Schema 和确定性门禁。
5. 官网、百家号、搜狐号和列举网模型路由与生成行为不变。
6. AI Worker 测试、类型检查、Compose 解析、Release static gate 和生产健康检查通过；部署后显式重新
   发起日批并按 generation run、usage ledger、质量报告和排期结果核验真实升级率。
7. 低于文字下限但结构完整的 Flash 草稿必须进入指定字段修复，不得直接以
   `SKILL_OUTPUT_INVALID` 升级 Pro；定点修复仍不足时才允许 Pro 兜底。
