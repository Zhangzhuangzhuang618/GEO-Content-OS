# ADR-0075：资料有效期修正

- 状态：已批准实施
- 日期：2026-08-28
- 任务：T160
- 影响范围：资料详情、Knowledge API、Contracts、OpenAPI、审计与检索有效期过滤
- 前置决策：ADR-0053、ADR-0055

## 背景

资料导入时可以填写有效期，但导入后详情页只有查看、重新解析和标记失效能力。日期录入错误只能让
资料失效后重新导入，会产生不必要的文件、解析和索引副作用。重新解析也不会修正有效期。

## 决策

1. 新增 `PATCH /sources/{id}/validity`，请求显式提交起止日期和修改原因，返回更新后的资料视图。
2. 仅 `knowledge.sources.manage` 权限可调用；服务端从 Session 取得租户与用户，不接受客户端租户 ID。
3. 请求必须使用 `If-Match` 携带当前 `updated_at`。服务端在事务中锁定资料并校验版本，不一致返回
   `VERSION_CONFLICT`，禁止静默覆盖并发修改。
4. 普通资料的起止日期可为空；两者同时存在时结束日期不得早于开始日期。保险证明继续要求完整起止
   日期，保持 ADR-0055 和数据库约束。
5. 更新只修改 `effective_from`、`effective_to` 和 `updated_at`；不改变资料状态、内容哈希、原文件、
   解析任务、分块、事实、引用或历史内容，也不发出重新解析事件。
6. 每次成功更新必须原子写入 `knowledge.source.validity_updated` 审计，保存修改前后资料视图及原因。
7. 新的检索、Brief 和生文使用现有查询过滤立即读取修正后的日期；历史检索、引用、内容和质量报告
   不追溯重算。
8. 本次不新增数据库表或迁移；公开端点基线由 169 增至 170。

## 取舍

- 本期只修正有效期，不提供证照编号、持证主体或保险摘要的通用编辑。
- 有效期修正不会自动恢复已标记失效的资料；失效操作仍是单独、不可混淆的业务动作。

## 验收

1. 有管理权限的用户可在资料详情修改日期，更新后页面显示服务端返回的新范围。
2. 反向日期、保险证明缺少任一日期、无权限、越租户或过期版本均被拒绝。
3. 成功更新保留内容哈希及解析任务数量，并产生包含前后值和原因的单条审计记录。
4. Contracts、Controller、OpenAPI、SDK、Web、集成测试和 Release static gate 通过。
5. 本任务不自动部署生产；部署及生产数据修正仍需用户单独授权。
