# ADR-0064：关键词批量管理与页码导航

- 状态：已批准实施
- 日期：2026-08-21
- 任务：HOTFIX-20260821-02
- 影响范围：STR-04、关键词 API、策略契约与 OpenAPI
- 延续决策：ADR-0001、ADR-0029
- 修订决策：ADR-0067 将“引用项导致整批删除失败”改为安全跳过引用项

## 已核验事实

STR-04 当前只能逐条编辑或禁用已有关键词。列表接口使用优先级游标分页，只返回下一页游标，因而
前端无法展示总数、总页数或直接跳转到指定页。列表过滤只支持 term 与状态，不能按适用平台过滤，
也不能切换优先级顺序。

`brief_keywords` 使用 `ON DELETE RESTRICT` 引用关键词。直接删除已用于历史 Brief 的关键词会破坏
历史内容关系，不能通过级联删除或清除关联规避。

## 决策

1. 新增 `POST /keyword-sets/{id}/keywords/batch`。请求一次选择 1 至 500 个互不重复的关键词 ID，
   支持 `update`、`disable` 和 `delete`，使用 CSRF、幂等键、租户与项目权限校验，并写入审计。
2. 批量修改只覆盖适合统一应用的公共字段：搜索意图、优先级、适用平台和状态。term 与同义词继续
   逐条编辑，避免把同一名称或同义词误写到多条关键词。
3. 批量操作在单个数据库事务内执行。任一 ID 不属于当前租户、关键词集或授权项目时，整批失败，
   不允许部分成功。
4. 未被历史 Brief 引用的关键词可以物理删除；只要所选项中存在已引用关键词，整批删除返回 409，
   前端提示改用禁用。不得删除 `brief_keywords` 或历史内容关系来完成关键词删除。
5. 关键词列表增加 `page`、适用平台过滤和 `priority_asc|priority_desc` 排序，并返回当前页、每页数量、
   总数和总页数。STR-04 使用服务端页码分页，支持上一页、下一页及输入页码跳转。
6. 原有 `cursor` 查询继续兼容其他调用方；`cursor` 与 `page` 不得同时提交。页面模式按稳定的
   `priority,id` 顺序读取，超出末页的请求收敛到最后一页。
7. 不修改关键词唯一性、搜索意图枚举、平台枚举、日批取词规则、质量门槛、旧内容或旧质量报告。

## 后果

- 无数据库迁移；新增 1 个公开 API，可执行端点数由 159 增至 160。
- 需要重新构建部署 API 与 Web；不需要重新构建 AI Worker 或发布 Worker。
- 页码跳转需要对当前筛选结果执行计数与偏移查询；保留旧游标模式供不需要总数的调用方使用。
- 删除是不可撤销操作，但已进入历史内容链路的关键词只能禁用，历史审计与内容关系保持完整。

## 验收

- STR-04 可选择当前页关键词并批量修改公共字段、批量禁用或批量删除。
- 已引用关键词与未引用关键词混合删除时整批失败，未引用项仍保留；单独删除未引用项成功。
- 平台过滤和优先级升降序由服务端执行；总数、总页数、上一页、下一页和页码跳转一致。
- 旧游标调用仍可读取后续页，`page+cursor` 返回 422。
- Contracts、API 集成测试、STR-04 回归、Web 构建与 OpenAPI 校验通过。
