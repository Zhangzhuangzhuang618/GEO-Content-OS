# ADR-0078：企业基础资料与客户化正文分离

- 状态：已批准实施
- 日期：2026-09-01
- 任务：HOTFIX-20260901-01
- 影响范围：官网、列举网、Content Writer、资料检索、发布门禁
- 前置决策：ADR-0014、ADR-0015、ADR-0035、ADR-0037、ADR-0053、ADR-0055、ADR-0075

## 背景

官网和列举网原先把证照与主题资料放在同一个相似度检索配额中，单篇最多保留少量证照，不能保证当前
企业全部有效基础资料进入正文及引用映射。旧 Prompt 还会把“第一方口径”“需自行核实”“不代表服务
质量”等内部判断直接写给潜在客户，形成重复、僵硬且无助于决策的正文。

企业名称只能来自当前工作区已发布品牌资料。平台账号名称、工作区名称和其他租户资料都不能作为企业
主体来源。

## 决策

1. 官网和列举网生成前，从当前工作区最新已发布品牌资料识别法定企业全称。只能识别出一个名称；缺失
   或冲突时停止生成。证照持证主体或保险投保主体必须与该名称精确相等。
2. 基础资料只接受当前租户、工作区和项目范围内仍有效、状态正常、允许用于文章且允许公开的结构化
   证照或保险资料。支持营业执照、行业经营许可、车辆或运输证件、质量/环境/职业健康安全管理体系认证
   及保险或损坏保障资料；不把会员、奖项、中标和案例归入基础资料。
3. 基础资料通道加载当前企业全部合格资料，不参加相似度排名、不占主题资料配额。主题资料通道另取最多
   3 份与选题相关的报价、流程、场景、案例或行业资料。
4. 官网增加“企业资质与保障”标题和正文块；列举网增加一个简洁正文段落。正文由服务端根据企业名称、
   关键词服务类型和实际资料名称确定性组装，模型不得修改证照名称、重复清单或补造社保、人员、车辆、
   保险和赔付事实。
5. “可通过页面联系方式索取核验”只有在工作区设置
   `enterprise_evidence_customer_request_supported=true` 时使用；默认只写“可供客户核验”。
6. 官网和列举网的最终 `citation_map` 必须映射全部基础资料。Publisher 在实际发布前重新核对当前主体、
   有效期、授权、资料清单和最终映射；不完整时失败关闭。
7. Content Writer 输入会先移除资料原文中的内部用途边界。所有平台的生成提示、确定性扫描和 Publisher
   共同禁止内部风控、证据分类、模型免责、资料 ID、`citation_map` 和内部规则名称进入客户正文。命中
   文本只允许修复相关字段；事实核验、主体匹配和引用门禁继续在系统内部执行。
8. 不修改历史文章，不把任一企业的名称或资料复制到其他工作区。当前企业没有任何合格基础资料时，
   官网和列举网停止生成；已有资料数量不写死，按实际合格资料动态确定。工作区可通过
   `enterprise_evidence_required_kinds` 声明必须具备的资料类别；声明后缺少任一类别即停止生成和发布，
   未声明时使用当前企业实际拥有的全部合格资料。

## 数据与兼容性

- 迁移 `0054_enterprise_evidence_customer_copy` 只发布 Content Writer Prompt 1.1.4，不新增表或字段。
- 冻结 Seed 幂等补齐 Quality Checker Prompt 1.2.0 与列举网规则 1.0.0；历史迁移在身份 Seed
  之前运行时没有可用创建人的全新数据库，也必须得到完整自动日批运行基线。
- 工作区设置沿用 `settings_json`，新增可选布尔字段，不新增公开端点。
- 当前数据库仍为 92 张表，公开端点仍为 170 个。
- 旧 Prompt、旧内容、旧质量报告和旧发布任务不自动重写或重新发布。

## 验收

1. 两个不同企业工作区分别使用自身唯一法定名称和自身资料，不发生跨企业引用。
2. 官网与列举网各只有一个资质保障段落；官网另有独立标题块。
3. 当前企业全部合格基础资料都进入段落和最终引用映射，主题资料仍最多 3 份。
4. 道路运输证不被改写成车辆行驶证，资料库不存在的社保、保险或赔付事实不能通过。
5. 任一平台客户正文命中内部风控或模板化免责语言时不能发布。
6. 日志和审计只记录选择数量、资料 ID 与校验结果，不记录证照编号或客户正文。
