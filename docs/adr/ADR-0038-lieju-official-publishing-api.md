# ADR-0038：列举网官方发布 API

- 状态：已批准实施
- 日期：2026-08-16
- 任务：T154
- 影响范围：列举网账号凭据、发布 Adapter、Publisher、人工对账和账号管理界面
- 前置决策：ADR-0035、ADR-0037

## 已核验事实

列举网向会员提供 `api_key`、GBK 编码 PHP 示例及城市和区域 ID 表。官方示例使用
`POST https://post.lieju.com/post_api.php?action=postnew`，提交 `api=1`、`api_key` 和
`postdb[...]` 表单字段；标题最多 30 个汉字，正文可用 `[img]URL[/img]` 引用最多 5 张外链图片。
广州为 `city_id=5`，生活服务下的搬家最终分类沿用已实测页面 `/5/73`，即 `fid=73`。

官方材料只说明新增发布，没有提供能力探测、幂等键、状态查询、修改、删除、限额或返回码规范。
因此不能把 HTTP 2xx、任意文本或本地推断伪造成已公开发布。

## 决策

1. 列举网 API 账号优先使用官方发布接口；旧账号继续兼容托管浏览器网关，便于平滑迁移和回滚。
2. 官方 API Key 与联系人、电话、区域等配置继续使用既有凭据信封加密保存，不进入响应、日志、
   Prompt、审计详情或仓库。接口地址固定为列举网 HTTPS 域名，不接受租户自定义地址。
3. 官方请求按 GBK 编码发送 `multipart/form-data`，TLS 校验必须开启。固定 `api=1`、
   `postdb[fid]=73`、`postdb[city_id]=5`；区域、标题、正文和联系方式来自受约束配置与冻结发布载荷。
4. 仅使用持久公开 HTTPS 图片 URL，最多 5 张；私有 MinIO 或缺少公开 URL 时无图发布，不阻断
   已通过质量门禁的文章。
5. 官方接口不支持客户端幂等键。每个发布任务在发起 HTTP 请求前必须写入不可重复的提交预留记录；
   网络未知、进程中断或已有预留时禁止自动重投，转人工核实，避免重复发布。
6. 只有平台明确返回成功语义才记为已提交。返回可访问且标题匹配的列举网公开链接时可记为
   `published`；否则记为 `processing`。未知或无法解析的响应不得自动重试。
7. 官方接口没有状态查询时，自动对账不得伪造结论；任务保留人工确认已发布/未发布入口。人工确认
   未发布后，提交预留状态变为 `not_published`，才允许再次使用原任务重试。
8. `lieju_automation` 与 `sohu_automation` 必须被各自浏览器 Worker 接受，修正 T153 真实 Worker
   仍只接受 `manual` 来源的遗漏。该兼容修复不改变冻结质量门禁。

## 数据与兼容

- 新增 `lieju_api_publications`，保存提交预留、远端引用、响应哈希和终态，不保存 API Key 或正文。
- 列举网加密凭据增加 `delivery_method=official_api|browser_gateway`；缺少该字段的旧凭据按
  `browser_gateway` 读取。
- 不增加公开 API 端点；平台账号创建/编辑继续使用既有接口。

## 不做

1. 不猜测未提供的查询、修改、删除或统计接口。
2. 不关闭 TLS 校验，不记录原始响应正文，不在前端回显 API Key。
3. 不把“提交成功”直接解释为“公开发布成功”。
4. 不自动重新投递未知提交，不重新评估旧内容或旧质量报告。

## 验收

- GBK 表单字段、广州/搬家 ID、图片 BBCode 和响应解析均有确定性测试。
- API Key 不出现在能力响应、错误、日志、审计或快照。
- 同一发布任务在未知态、重放和 Worker 恢复时最多发起一次官方提交。
- 明确拒绝直接失败；明确提交成功进入处理态；公开链接经核验后才完成发布。
- 旧浏览器账号和搜狐号/列举网自动化来源回归通过。
