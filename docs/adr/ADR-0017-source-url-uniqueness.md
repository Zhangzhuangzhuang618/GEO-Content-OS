# ADR-0017：知识库 URL 唯一性与历史重复清理

## 状态

Accepted — 2026-07-20

## 背景

ADR-0016 的表格预检只排除文件内部重复，既有 `POST /sources` 只按抓取内容哈希去重。同一 URL
重复提交时，动态页面或失败响应可能产生不同哈希，导致同一工作区出现多条 URL 资料。重复记录
会浪费抓取、解析和索引资源，并使知识库状态难以理解。

## 决策

- URL 资料在同一租户、同一工作区内以最终抓取 URL 唯一；项目不改变该唯一边界，与既有内容
  哈希去重范围一致。
- 迁移 0034 在事务内按 URL 分组。优先保留 `active`、被 Brief 引用或包含有效分块的记录，再按
  更新时间选择；Brief 引用先迁移至保留记录，随后删除冗余资料及其级联解析产物。
- 清理完成后创建部分唯一索引 `uq_source_url_active`，仅约束未删除的 URL 资料，不影响文件资料。
- `POST /sources` 同时按内容哈希和最终 URL 查重；数据库唯一冲突作为并发兜底，统一返回既有
  409 `STATE_TRANSITION_INVALID`，不新增公开 API 或错误码。
- 冻结 DOCX 保持只读；Schema、迁移、测试和项目上下文同步更新。

## 后果

- 表数和公开 API 数不变；当前迁移序号更新为 0034。
- 同一 URL 内容变化时使用现有重新索引流程，不通过重复创建资料保存快照。
- 历史重复清理是不可逆的数据删除；执行前必须备份数据库并核对 Brief、事实和引用依赖。
