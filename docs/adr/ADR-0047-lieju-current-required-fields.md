# ADR-0047：列举网官方 API 现行必填字段对齐

- 状态：已批准实施
- 日期：2026-08-18
- 任务：HOTFIX-20260818-03
- 影响范围：列举网官方 API 适配器、平台账号配置、PUB-01
- 前置决策：ADR-0038、ADR-0046

## 背景

列举网提供的 PHP 示例只提交一级栏目 `postdb[fid]=73`，但当前“生活服务 / 搬家”发布页还要求
二级类别 `postdb[leibie]` 和地址 `postdb[dizhi]`。受控真实测试中，GEO 请求和官方 PHP/cURL
示例得到完全相同的 HTML 响应；有效 API Key 能进入字段校验，而缺少现行必填字段的请求未在会员
内容列表中产生文章。问题不是 GBK、multipart 或 Key 失效，而是官方示例落后于当前发布表单。

## 决策

1. 继续提交一级栏目 `postdb[fid]=73`，并增加二级类别 `postdb[leibie]`。
2. “生活服务 / 搬家”的默认二级类别使用列举网页面当前值 `4`（搬家搬场）；服务端为未显式
   保存类别的旧官方 API 配置补该默认值。
3. 增加必填发布地址，使用当前页面字段名 `postdb[dizhi]`，长度上限 120；不伪造或从企业资料
   猜测地址。
4. 新建列举网官方 API 账号时必须填写地址；旧账号可在“修改账号”中只补地址，已加密保存的
   API Key、联系人、电话、区域和其他配置继续保留，敏感凭证不回显。
5. 接口返回不明确结果时继续进入 `PUBLISH_STATE_UNKNOWN`，先对账再决定是否重投。
6. 官方成功文本中的公开 URL 以英文或中文逗号为字段边界，不得把后续内容 ID、用户名或剩余
   额度元数据拼入 URL。

## 兼容性

- 无数据库迁移和公开端点变更。
- 未保存地址的旧列举网官方 API 账号在补齐地址前不能发布；Web 和 API 部署后可直接补充，
  无需重新填写 API Key。
- 旧内容、旧质量报告、旧发布尝试和未知态记录不自动重评或重投。
- 不改变任何冻结质量门禁、重写次数、候选上限或发布幂等规则。

## 验收

- multipart 同时包含 `postdb[fid]=73`、`postdb[leibie]=4` 和非空 `postdb[dizhi]`。
- 新账号缺少地址时前端拒绝保存。
- 旧账号只补地址时，服务端保留原 API Key 和其他发布资料。
- 受控真实发布只提交一次；未知响应先查会员内容列表，不盲目重试。
- 2026-08-18 受控真实提交返回内容 ID `105541615`；标准公开页标题与测试标题一致，确认发布成功。
