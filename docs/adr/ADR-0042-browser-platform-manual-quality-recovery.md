# ADR-0042：浏览器平台人工质检恢复与批量处理

- 状态：已批准实施
- 日期：2026-08-17
- 任务：HOTFIX-20260817-09
- 影响范围：搜狐号与列举网人工恢复、发布管理界面
- 前置决策：ADR-0037、ADR-0039、ADR-0040、ADR-0041

## 背景

列举网日批候选进入 `manual_required` 后，用户从内容详情重新质检只能创建独立质检运行，原
`browser_platform_automation_runs` 和批次项不会恢复，因而无法继续重写、配图和排期；发布管理页也
只能逐篇打开。生产日志还显示模型连续把本公司名称或无法定位的名称报告为
`brand.other_company_name`，语义修复后仍触发 `SKILL_OUTPUT_INVALID`；该类无效输出必须继续失败关闭，
不能由服务端删除问题后改判通过。

## 决策

1. 模型返回不可验证的 `brand.other_company_name` 时，继续按 ADR-0040 执行一次完整模型重判；重判
   仍无效时进入人工处理。服务端不删除模型问题、不重算模型决策，也不自动放行。
2. 用户对搜狐号或列举网人工内容发起重新质检时，同时把没有发布任务的自动化运行恢复为
   `quality_pending`，重写计数从零开始，批次项恢复为 `quality_check`。当日停止批次恢复为
   `running`，以便后续质量通过后正常配图、排期和发布。
3. 已关联发布任务的失败项不得通过内容重检重复提交，继续从发布任务执行核验、重试或人工对账。
4. 发布管理页提供“一键批量重新质检”，仅处理有当前正文且没有发布任务的人工项。前端复用既有
   单篇质检接口；部分请求失败时保留失败项并显示成功/失败数量。

## 不变项

- 旧内容版本、旧质量报告、旧发布任务和审计记录不删除、不覆盖；新操作生成新的质检运行和报告。
- 冻结质量门槛、最多三次自动重写、真实发布判定和平台隔离保持不变。
- 不新增数据库迁移，不允许批量操作发布失败项，不自动重试外部平台提交。

## 验收

- 品牌误报触发一次完整模型重判；重判仍无效时不得生成质量报告或伪造通过结论。
- 准确指向正文中真实第三方名称的问题继续 BLOCK，确定性名称扫描保持不变。
- 单篇和批量重新质检均恢复浏览器平台自动化运行、批次项及当日批次，并产生新的质检事件。
- Web、Skills、AI Worker、API 单元与集成回归通过。
