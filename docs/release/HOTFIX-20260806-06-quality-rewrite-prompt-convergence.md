# HOTFIX-20260806-06 质量报告重写提示收敛

## 生产证据

- 部署 HOTFIX-20260806-05 后连续四次百家号重写均被安全门禁拒绝：两次原样返回、一次仍含 CTA、一次结构化输出失败。
- 最后一次结构化输出失败路径为 `/master_content/schema_version` 和 `/variants/0/schema_version`。
- Content Writer 的模型输出 Schema 不允许 `schema_version`，该字段由服务端在生成结果落地前确定性添加。
- 质量重写输入此前直接包含旧内容的服务端 `schema_version`，模型在重写时照抄后会被当作额外字段拒绝；并非日志说明中推断的“缺少字段”。

## 根因

- 传给模型的待修改内容混入了模型无权输出的服务端字段，输入示例与输出 Schema 相互矛盾。
- “修复质量问题”的重写消息之后仍追加普通生成指令，模型可能把最后一条指令理解为重新生成完整草稿，弱化对旧问题的定向修改。
- 最终重写指令没有再次强化运行时已冻结的百家号无 CTA 输出要求，导致模型修复其他问题时重新产生 CTA。

## 修复

- 质量重写候选交给模型前移除服务端拥有的 `schema_version`；最终内容仍由服务端统一写入固定版本。
- 最后一条用户指令区分普通生成和质量重写，重写时再次要求逐项修复、实质变化且不得原样返回。
- 所有模型输出明确禁止返回 `schema_version` 和服务端 Envelope 字段。
- 百家号最终重写指令明确要求 `cta=null`，并禁止 `block_type=cta` 内容块；已发布版本化 Prompt 不变。

## 安全边界

- 不删除或改写持久化内容来伪造重写成功；服务端仅清理发送给模型的服务端字段。
- HOTFIX-20260806-05 的原文哈希拦截、结构字数检查、确定性风险检查和重写后质检保持不变。
- 不修改质量报告、评分、问题、通过结论或冻结质量门槛。
- 旧内容、旧运行和旧质量报告不会自动重新评估。

## 部署与验收

- 重新构建并部署 AI Worker；无需数据库迁移、API 或 Web 变更。
- 重写消息中的候选不再包含 `schema_version`，最终重写指令仍包含原质量问题。
- 百家号重写不得原样返回、不得产生 CTA，合法输出由服务端补充固定 `schema_version` 后落库并进入既有质检。
