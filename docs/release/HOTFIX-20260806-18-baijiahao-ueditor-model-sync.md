# HOTFIX-20260806-18 百家号 UE 编辑器模型同步

## 真实页面证据

- 发布前正文在 `iframe#ueditor_0` 中可见，页面字数显示 1109，但点击发布后百家号提示“内容少于40字”。
- 继续选择“保持图文发布”后，真实接口 `/pcui/article/publish` 返回 `errno=20040036`、`文章内容不能为空`，六个作品状态均无目标文章。
- 页面实际正文实例是 `window.UE_V2.instants.ueditorInstant0`。直接键盘写入 iframe 后，该实例 `getContent()` 长度为 0、`hasContents=false`。
- 使用实例 `setContent` 并触发 `contentchange`、`sync` 后，真实页面 `getContent()` 长度为 3864、`getContentTxt()` 长度为 1294、`hasContents=true`，2 秒后不回滚；DOM 中 2 个有序列表和 11 个列表项保持完整。

## 修复

- 检测到 `iframe#ueditor_0` 时，必须等待 `UE_V2` 实例就绪并通过平台编辑器 API 写入正文。
- 正文转换为经过 HTML 转义的段落和有序列表，不直接拼接未转义内容。
- 写入后同时校验编辑器模型非空、模型纯文本字符全集、DOM 全文、`<ol>` 数量和直属 `<li>` 数量。
- 无 UE iframe 的兼容编辑器仍保留键盘输入路径。
- 浏览器仿真增加独立编辑器模型；仅 DOM 可见但模型为空时不得通过。

## 安全边界

- 不伪造发布响应，不直接调用发布接口。
- 不使用包含关系、长度近似或服务端推断替代全文校验。
- 不放宽正文、列表、图片、AI 声明、质量、幂等或未知态门禁。

## 部署与验收

- 重新构建并部署 Baijiahao Browser Worker；无需数据库迁移。
- 单元测试和浏览器回归必须保持通过。
- 使用两篇生产质检通过且确认未发布的不同文章连续完成真实百家号发布，才可判定修复完成。
