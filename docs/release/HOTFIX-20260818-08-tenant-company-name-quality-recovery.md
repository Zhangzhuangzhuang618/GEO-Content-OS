# HOTFIX-20260818-08 多企业名称隔离与质检完整重判

## 问题

列举网在另一个企业运行日批时，系统仍把示例企业“广州志远搬家服务有限公司”作为全局唯一允许的
本企业名称。当前企业的法定名称可能被错误识别为第三方名称。模型同一轮若还返回错误正文位置、
不存在的联系方式或无对应声明的高风险事实问题，断言层只反馈首个错误；既有一次语义重判修正首项
后又被下一项阻断，最终批量进入 `QUALITY_CHECK_EXECUTION_FAILED`。

## 修复

- 内容生成、共享质检和确定性品牌扫描统一从当前企业已发布品牌档案的 `positioning`、`cta` 读取
  本企业法定名称，不再跨企业复用示例企业名称。
- 禁止词和差异化字段不进入允许名单，避免把竞品名称误当作当前企业名称；档案未声明完整名称时
  保持失败关闭，不回退到其他租户。
- 一次质检输出中的全部不可核验问题聚合为脱敏原因列表，交给既有的一次完整模型重判同时修正。
- 列举网联系方式与高风险事实问题增加结构化原因码，重判可明确区分错误分类、错误位置、正文没有
  字面联系方式以及不存在合格声明等情况。
- 服务端仍只验证模型结果，不删除问题、不修改质量分或重算决策；第二次结果无效时仍转人工。

## 安全边界

- 真实第三方企业或品牌名称继续形成 BLOCK；真实电话号码、网址、微信 ID、QQ ID 继续受列举网
  正文禁用规则约束。
- 冻结质量门槛、最多三次内容重写和一次质检重判不变。
- 不修改旧候选、旧内容版本、旧质量报告或历史运行。

## 部署与恢复

重新构建并部署 AI Worker。无需数据库迁移，API、Web、Publisher 和浏览器发布 Worker 无需因本
Hotfix 重建。旧失败候选不会自动重新质检；部署后需在界面显式重新处理，或保留历史候选并重新发起
当日日批新尝试。
