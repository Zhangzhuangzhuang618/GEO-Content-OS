# HOTFIX-20260819-02 百家号回执 ID 精确对账

## 生产证据与根因

- 生产日志显示内容列表核对返回 `MULTIPLE_MATCHES` 后，账号会话进入
  `attention_required`，后续排期统一被 `SESSION_ATTENTION_REQUIRED` 阻断。
- 现有实现统计匹配到的 DOM 节点数，未按远端文章 ID 去重；百家号同一文章由多个嵌套节点
  展示时会被误判为多篇文章。
- 发布接口已经返回严格文章 ID，但立即列表核对和后续状态对账仍只按标题、可选指纹和可选时间
  查找，没有优先使用该文章 ID。

## 修复

- 严格发布回执返回文章 ID 后，立即列表核对只接受该 ID；暂未出现在列表时保留原
  `processing` 回执。
- 后续状态对账在浏览器发布记录已有文章 ID 时继续按该 ID 精确查找。
- 所有列表候选按远端文章 ID 去重；同一文章的多个 DOM 节点只算一条，只有不同文章 ID 的
  多个候选才返回 `MULTIPLE_MATCHES`。
- 内容行扫描限制在已验证的内容列表或表格内。多匹配诊断只包含原始节点数和去重后文章数，
  不记录标题、正文、链接参数、Cookie 或凭证。

## 安全边界

- 没有严格文章 ID 的未知提交仍按标题、指纹和提交时间核对；多个不同远端文章继续转人工。
- 不把提交受理等同于审核通过；仅远端状态为 `published` 时完成百家号发布任务。
- 不自动恢复已有 `attention_required` 会话，不改写旧任务、旧尝试或旧质量报告。
- 不改变验证码、登录失效、未知态禁止盲目重投和冻结质量门槛。

## 部署与验收

- 无数据库迁移和公开 API 变化，只需重新构建并部署 Baijiahao Browser Worker。
- 部署后需人工实时核验并恢复当前安全暂停会话；旧人工任务按原有对账或未发布收尾入口处理。
- 本地仿真应覆盖：同一文章重复 DOM 节点去重、不同文章 ID 的同标题候选仍阻断，以及严格
  回执 ID 从多个同标题候选中精确选中目标文章。
