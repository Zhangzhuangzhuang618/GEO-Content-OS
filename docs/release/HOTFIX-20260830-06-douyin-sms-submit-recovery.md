# HOTFIX-20260830-06 抖音短信验证码提交恢复

## 生产证据与根因

2026-08-30 生产日志确认短信验证码提交动作已到达 Worker。提交后保存的页面诊断显示：二次验证前景层已经消失，验证码输入选择器仍命中一个可见输入框，但验证提交控件已经不存在。此后会话继续停留在 `attention_required`，Web 的动作请求同时因上游连接重置而没有取得最终结果。

代码核验确认两个根因：

1. 登录结果等待和状态复核使用全页面的宽泛验证码输入选择器。二次验证层关闭后，抖音首页的普通验证码输入元素仍会被误判为活动的短信验证步骤，导致登录成功检查被短路。
2. Playwright headless 默认参数仍注入 `--enable-unsafe-swiftshader`。现有 `--disable-gpu` 没有阻止软件 GPU 进程；生产实测 Worker 约占用 515% CPU，其中 SwiftShader GPU 子进程约占用 415%，放大了页面检查、截图和代理请求超时。

现有证据不能证明本次验证码本身是否正确或是否已被抖音接受；本修复不基于该假设。

## 修复

1. 验证码输入框只允许在已经确认的前景验证容器内识别。验证层消失后，首页或登录页背景中的普通验证码输入不再维持 `sms_code` 状态。
2. 登录结果等待只把前景验证容器、可见安全挑战标记或图形验证码视为仍在验证；验证层关闭后继续执行登录成功检查。
3. headless Chromium 忽略 Playwright 默认的 `--enable-unsafe-swiftshader`，并同时禁用 GPU 与软件光栅化；有界面开发模式保持原行为。
4. 没有可确认验证容器时，安全诊断只截取当前视口，不再生成整页长截图；文字、输入、媒体和身份内容继续脱敏。

## 回归保护

Playwright 模拟器新增“短信验证层关闭，但背景验证码输入仍存在”的生产同构用例。验证码提交后必须返回登录成功、诊断必须为空，并且保存的浏览器状态必须包含模拟登录凭据。完整浏览器套件继续覆盖二维码、验证方式选择、短信发送与重发、验证码提交、遮罩阻断、原设备二维码和图文发布。

## 边界

- 不自动选择验证方式，不自动发送短信，不绕过抖音安全验证。
- 不记录验证码、Cookie、完整手机号、页面正文或原始 DOM。
- 不假定错误、过期或被平台拒绝的验证码为登录成功。
- 无数据库迁移、公开 API 形状、生产环境变量或发布质量门槛变化。
