# HOTFIX-20260831-03 抖音发布预检崩溃页恢复

## 生产证据

2026-08-31 08:00 两个抖音账号的首条排期均连续失败三次。抖音 Worker 的容器内存事件记录了两次
`oom_kill`，随后两个账号的发布请求都在进入编辑器前返回 `page.goto: Page crashed`。第三次失败后，
两条任务均进入 `PUBLISH_STATE_UNKNOWN`，但数据库没有 `submitted_at`，说明失败发生在点击发布之前。

现有发布恢复只覆盖 `driver.submit()` 内的编辑器操作。发布前的登录态预检直接调用
`verifyAuthenticated()`；Playwright 页面崩溃后 `page.isClosed()` 仍可能为假，后续重试继续复用同一崩溃
页面，因此不会自行恢复。

## 修复

1. 发布前登录态预检识别 `Page crashed`、页面/上下文/浏览器已关闭等确定性运行时错误。
2. 首次命中时关闭该账号的浏览器上下文，以相同独立 Profile 和已保存登录态重新打开页面并只重试一次。
3. 第二次仍失败则保持原有失败关闭语义，不循环重试、不把登录态或发布状态伪判为成功。
4. 恢复日志只记录账号 ID 和脱敏错误，不记录 Cookie、凭据、页面正文或发布内容。

## 不变项与部署

- 不修改发布按钮动作、远端成功判定、幂等键、未知状态对账、内容质量门禁或账号隔离。
- 无数据库迁移、公开 API、环境变量或 Compose 变化。
- 只需重建 `douyin-browser`；部署后对两条未进入提交阶段的失败任务执行既有安全重试并继续监控。
