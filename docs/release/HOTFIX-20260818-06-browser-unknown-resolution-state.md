# HOTFIX-20260818-06 浏览器平台未知态人工重试恢复

## 问题

百家号、搜狐号或列举网自动发布返回未知结果时，Publisher 会把自动化运行和每日批次项置为
`manual_required`。用户在平台后台确认未发布后点击“确认未发布并重试”，API 却只根据最新尝试的
错误码推导自动化状态；`PUBLISH_STATE_UNKNOWN` 被错误推导为 `publish_failed`，导致状态更新匹配
不到 `manual_required` 运行记录并返回 409。事务回滚，没有创建新的发布尝试或 Outbox 事件。

## 修复

- 人工核实重试按最新尝试的状态和错误码恢复自动化：`unknown` 或 `MANUAL_REQUIRED` 对应
  `manual_required`，列举网官方 API 已成功提交但仍在 processing 的人工核实仍对应
  `publish_failed`。
- 保留自动化运行状态的精确匹配，不把普通重试放宽为同时接受多个状态。
- 新增生产同构数据库回归：列举网官方 API 第 2 次尝试进入未知态、运行和批次项进入
  `manual_required` 后，普通重试继续被阻断；人工确认未发布可以恢复任务、运行和批次项，重置
  官方 API 提交预留并创建第 3 次 Outbox 执行事件。
- 回归同时验证前两次发布尝试保持追加只读，并补齐未知态详情的 `blocked_reason: null` 断言。

## 安全边界

- 未经人工确认仍禁止盲目重试，不改变最多 3 次发布尝试限制。
- 不把未知结果判为成功，不修改历史尝试、旧内容、旧质量报告或冻结质量门槛。
- 不放宽自动化运行的一致性校验；其他异常状态仍返回 409。
- 本 Hotfix 只恢复本地状态机闭环，不证明此前更新的列举网 API Key 已被远端接受。

## 部署与恢复

重新构建并部署 API。无需数据库迁移，Web、Publisher 和浏览器 Worker 无需因本 Hotfix 重建。

部署后，先在列举网后台按标题确认目标内容确实未创建，再从原发布任务点击“确认未发布并重试”。
任务将使用剩余的第 3 次发布机会；若远端仍返回登录页或其他未知响应，系统会再次停止并要求人工
核实，不会自动重复提交。
