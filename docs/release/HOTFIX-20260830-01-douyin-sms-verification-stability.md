# HOTFIX-20260830-01 抖音短信验证状态与安全诊断稳定性

## 生产证据与根因

2026-08-29 生产诊断在同一会话先后记录到 `code_input_visible=true`、`code_input_actionable=false`。抖音页面已经进入短信验证码步骤，但 Worker 把短时点击命中失败当成“输入步骤不存在”，向 Web 返回 `has_code_input=false`。Web 又只在 `has_code_input=true` 时轮询，导致一次处于动画或遮罩切换期的误判长期停留在“发送短信验证码”。原诊断截图对整页文字、媒体和包含 `user/account/name` 等宽泛 class 的容器同时掩码，不同验证状态会形成近似的深色块，无法辅助区分页面。

## 修复

1. `has_code_input` 表示输入框已经可见、启用且可编辑，不再承担浏览器点击安全判定；真正提交时继续独立校验输入框和提交控件。
2. 选择“接收短信验证码”后最多等待 5 秒，直到输入框或发送控件出现，不再固定等待 300ms 后立即判错。
3. 使用浏览器实际命中目标判断遮挡，并在私有诊断中分别记录输入框、提交控件的可见、启用、编辑、命中及步骤可操作布尔证据。
4. Web 在整个 `attention_required` 状态每 3 秒复核一次，使动画或临时遮罩结束后自动展示验证码输入区。
5. 诊断截图优先裁切已识别的前景验证层，继续隐藏原页面全部文字、背景图片、输入内容和媒体，只显示不含账号信息的安全状态摘要；移除容易覆盖大型父容器的宽泛 class 掩码。

## 安全边界

- 发送、重发和提交验证码仍必须由用户明确触发。
- 验证码不落库、不写日志、不进入截图或错误正文。
- 输入框展示不代表绕过安全验证；提交前命中目标异常、图形验证码或遮罩仍返回人工处理。
- 日志不记录原始 DOM、平台控件正文、完整或脱敏手机号、账号名称及页面正文。
- 无数据库迁移、公开 API 形状、生产配置、登录成功判定或发布质量门槛变化。

## 验证

- Douyin Browser Worker 单元、类型和 Chromium 集成测试。
- 新增验证方式延迟切换、输入框被遮挡但可展示、提交控件安全保护及裁切截图场景。
- Web 类型检查、生产构建和 `attention_required` 持续轮询场景。
