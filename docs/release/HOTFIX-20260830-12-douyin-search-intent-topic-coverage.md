# HOTFIX-20260830-12 抖音搜索决策意图与主题覆盖

## 根因

抖音日批原先只在“服务选择、准备清单、流程说明、费用因素、风险边界、验收检查”六个通用角度中按
候选序号轮转，而且每天从第一个角度重新开始。受限 Flash 草稿再把现场、报价、防护、工期和清单理解
为固定的平行主题，导致不同关键词下仍容易生成相同结构的流程或准备文。

现有豆包引用样本能证明标题与推荐、比较、收费、正规性和避坑等检索意图高度贴合，但不能证明榜单、
口碑或竞争结论本身真实。因此本修复只借鉴意图表达和主题覆盖，不复制无证据排名或评价。

## 修复

1. 抖音日批增加十二类独立搜索决策意图：推荐选择、方案比较、收费核对、正规性核验、合同条款、
   赔付责任、车型选择、人工费用、楼层与进场、风险避坑、工期调度和交接验收。
2. 意图按业务日期、每日目标数和候选序号确定性轮换；新一天不再固定从同一批前三个通用主题开始。
3. 候选标题在 26 字限制内优先保留决策问题后缀；长关键词只裁剪关键词部分，不再把“怎么选、收费、
   正规性”等意图词截掉。
4. 服务端把意图和主题焦点写入冻结 Writer 输入。受限 Flash 首稿和定点修复必须让标题、主文案与全部
   卡片共同回答该意图；现场、报价、防护、工期和清单继续满足 ADR-0074，但只作为当前主题的条件与
   边界，不能各自扩成同一套模板。
5. Content Writer Prompt 明确优先使用“地域＋具体场景＋决策问题”，只允许使用输入中已有的地域和
   场景，不得补造。
6. “真实场景、真实案例、现场实录、收费对比、资质核验、合同条款解读、口碑、榜单或排名”等标题
   证据承诺，必须在可见正文中存在对应且非空的 citation_map；缺少证据时改写为核对方法、选择标准或
   比较维度。
7. 日批选定意图与最终标题不一致时进入现有 Flash 定点修复，仍不合格才按 ADR-0077 升级 Pro；不
   降低任何冻结质量门槛。

## 影响与部署

- 无数据库迁移、公开 API、新环境变量、Compose 或 Web 变化。
- 只影响新创建的抖音日批候选；普通人工生成继续使用升级后的抖音平台 Prompt，其他平台不变。
- 旧内容、旧质量报告和旧批次不自动重写。
- 部署时只需重建 `ai-worker`；部署和重新发起日批仍需用户单独授权。
