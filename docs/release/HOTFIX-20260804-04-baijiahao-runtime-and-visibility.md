# HOTFIX-20260804-04：百家号运行状态、调度与零发布修复

## 生产证据

- 百家号自动化面板首屏同时调用浏览器实时状态接口；该接口需要启动并探测托管浏览器，生产日志中单次耗时约 4.4～5.5 秒。
- 今日批次只返回汇总数量，未返回活跃候选、执行阶段和最后活动时间，无法区分“真正执行中”和“状态残留”。
- 官网派生调度把当天所有非终态运行都计入每日目标，`generation_pending` 也会触发 `daily_target_reached`，阻止后续官网文章补位。
- 独立候选生成失败后，批次项会退出，但自动化运行仍可能停留在 `generation_pending`。
- 质量门禁把“搬运地址、物品品牌型号”中的“型号”误判成详细地址，直接阻断过一个本可通过的候选。
- DeepSeek 请求校验错误此前只返回 `DeepSeek message is invalid`，无法定位消息序号和错误类型。

## 修复范围

- 面板首屏只读取项目、策略和数据库中的最近登录态；浏览器实时探测改为显式“实时核验登录态”。扫码期间仍按原规则轮询。
- 今日批次接口增加活跃候选、执行阶段、最后活动时间和生成失败退出数量；页面明确显示运行、等待巡检、等待发布、完成、取消或需人工。
- 每日目标只统计已进入配图、发布排期或发布阶段的内容，不再把生成/改写/质检中的候选当作已满足目标。
- 生成失败候选退出时同步把自动化运行置为终态；调度器启动后也会修复历史上已退出但仍显示运行中的记录。
- 修正“型号”触发详细地址规则的误判，同时保留真实街道地址的阻断。
- DeepSeek 非重试错误首次即停止无效重试，并记录消息序号/角色；内容生成失败日志增加运行、事件、包、变体、阶段及脱敏后的底层错误。

## 冻结边界

- 不修改总分、事实、品牌、可读与安全、问题覆盖、平台适配、来源相似度等冻结门槛。
- 不修改最多重写三次和每日候选上限。
- 不伪造模型结论，不修改历史质量报告。
- 不操作生产数据库或百家号账号。

## 部署后核验

1. 同时更新 API、Web 和 AI Worker。
2. 打开“发布管理 → 平台账号 → 百家号自动化”，面板应先快速显示缓存登录态；点击“实时核验登录态”才会触发浏览器 Worker。
3. 确认今日批次显示“最后活动”“正在执行的候选”及具体阶段。
4. 查看 AI Worker 日志中的 `AI content generation failed`；错误对象应包含 `generation_run_id`、`variant_id`、`stage` 和脱敏后的 `error_message`。
5. 历史 `retired` 批次项对应的 `generation_pending` 自动化运行会在调度器下一次 tick 变为 `disabled`，无需直接修改生产数据。

## 验收

- AI Worker 单元测试覆盖地址误判和生成失败诊断。
- DeepSeek 适配器测试覆盖无效消息定位。
- API 集成测试覆盖未完成候选不占每日目标、生成失败候选退出运行态，以及批次明细契约。
- PUB-01 E2E 覆盖首屏不调用实时浏览器探测、手动核验和活跃候选展示。
- 类型检查、代码检查、OpenAPI 校验和相关测试通过。
