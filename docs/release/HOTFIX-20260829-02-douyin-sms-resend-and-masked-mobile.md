# HOTFIX-20260829-02 抖音短信重发与脱敏接收号码

## 根因

1. 抖音二次验证进入验证码输入阶段后，Web 只展示“提交验证码”，并按
   `has_code_input` 隐藏原“发送短信验证码”按钮，导致用户无法明确触发重发。
2. Worker 的诊断只保留验证类型和控件状态。页面即使显示 `138****5678`，该脱敏号码也没有进入
   白名单响应，用户无法判断验证码发送到了哪个绑定手机。
3. Worker 的发送动作只识别首次发送文案，未覆盖“重新发送”“重新获取”等重发按钮，也没有把
   抖音页面的按钮禁用状态返回给 Web。

## 修复

1. 二次验证诊断增加可选 `masked_mobile` 和 `sms_resend_available`。Worker 只从可见页面文本中提取
   带掩码的手机片段并规范化为 `138****5678`；完整手机号仍被 Contracts 和 Web Schema 拒绝。
2. Worker 识别首次发送及重发按钮。验证码输入已出现时直接操作重发控件，不再重新选择短信验证
   方式；抖音倒计时或禁用状态下返回不可重发，不伪报短信已发送。
3. Web 在短信验证区域展示脱敏接收号码；未取得安全脱敏号码时明确提示在账号绑定手机上查收。
   验证码输入阶段始终展示“重新发送验证码”，按抖音实时控件状态启用，并每 3 秒刷新等待状态。

## 安全与边界

- 不返回、保存或记录完整手机号；验证码仍只存在于单次请求和当前 Worker 浏览器内存。
- 不自动发送或重发短信，每次发送均需要用户明确点击。
- 不绕过抖音倒计时、验证码或身份验证，不改变登录成功判定和独立浏览器 Profile 隔离。
- 无数据库迁移，不修改发布质量门槛、发布任务状态或历史记录。

## 验证

- Contracts：30 个文件、150 个测试通过，覆盖脱敏号码白名单和完整手机号拒绝。
- Douyin Browser Worker：4 个文件、24 个单元测试及 8 个 Playwright 集成测试通过。
- Web 类型检查、生产构建通过；PUB-01 抖音短信二次验证交互测试通过，覆盖号码展示、重发和验证码
  不回显。
- API 类型检查、OpenAPI 生成、Worker 构建和 v2.1/T161 Release static gate 通过。
