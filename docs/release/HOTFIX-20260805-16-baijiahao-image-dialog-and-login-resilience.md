# HOTFIX-20260805-16 百家号图片弹窗与登录健壮性修复

## 生产证据

- 正文图片工具栏按钮打开顶层自定义弹窗，不直接触发浏览器 `filechooser`。
- 弹窗包含 `input[type="file"][accept="image/*"][multiple][name="media"]` 和“确认”按钮。
- 登录等待跳转可能抛出 `net::ERR_ABORTED`；原异步任务未捕获该异常，导致 Worker 进程退出。
- 正文配图上传发生在提交按钮之前，但底层异常被转换为 HTTP 503，错误进入 `PUBLISH_STATE_UNKNOWN`。

## 修复

- 点击正文图片按钮后等待“本地图片”弹窗，直接向弹窗图片输入框写入文件，等待“确认”可用后点击，并核验正文图片已插入。
- 本地仿真页改为与生产一致的自定义图片弹窗，不再使用按钮直接触发文件选择器的错误模型。
- 登录后台任务完整捕获导航和持久化错误；失败时记录脱敏诊断并进入 `attention_required`，不再形成未处理 Promise。
- 提交按钮前的浏览器操作失败持久化为 `manual_required`，返回 `423 EDITOR_OPERATION_FAILED`，不再误报为远端发布状态未知。

## 验收

- 两张正文图片可通过自定义弹窗一次上传并插入正文。
- 登录核验出现导航异常时 Worker 保持运行。
- `upload_body_images` 等提交前失败保留阶段诊断、截图和人工处理状态。
- 提交动作开始后的不确定结果仍保持 `PUBLISH_STATE_UNKNOWN`，不降低发布安全边界。
