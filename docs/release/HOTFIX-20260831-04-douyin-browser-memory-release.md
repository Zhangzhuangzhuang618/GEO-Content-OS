# HOTFIX-20260831-04 抖音自动发布浏览器内存释放

## 生产证据

HOTFIX-20260831-03 上线后，第一条替代任务已成功点击发布并进入 `processing`。此时
`douyin-browser` 从空闲态增长到约 1.0 GiB，而 Docker 虚拟机只剩约 1.2 GiB 可用内存，交换空间几乎
耗尽。抖音 Worker 在修复前会为每个账号长期保留 Playwright 持久上下文；第二个账号发布或后续跨账号
对账会继续打开新的 Chromium 上下文，能够再次触发生产已经记录的 OOM。

## 修复

1. 自动发布请求完成后，无论成功或失败，都在账号锁释放前关闭该账号浏览器上下文。
2. 非终态发布的自动对账完成后同样关闭上下文；终态查询和等待人工二次验证的登录页面保持原行为。
3. Profile、Cookie 快照、发布任务、预提交证据和远端状态均继续持久化；后续操作按原 Profile 重新打开。
4. 关闭失败只记录账号 ID 和脱敏错误，不覆盖已经取得的发布或对账结果。

## 不变项与部署

- 不修改登录挑战流程、发布按钮动作、幂等键、远端状态判定、内容质量门禁或三次发布尝试上限。
- 无数据库迁移、公开 API、环境变量或 Compose 变化。
- 只需重建 `douyin-browser`；部署后继续对账已进入 `processing` 的两条替代任务。
