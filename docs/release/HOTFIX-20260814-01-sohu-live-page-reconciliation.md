# HOTFIX-20260814-01：搜狐真实页面发布与对账修复

## 问题

搜狐真实页面与首版仿真签名存在差异：登录需要先打开登录层再选择微信；未实名账号只能发布动态；图文编辑器首次必须从内容首页进入；正文图片需要经过上传管理器确认；发布控件不是 `button`。此外，发布完成等待错误地匹配了编辑器自身 URL，对账又在内容首页异步渲染完成前判断登录状态，导致真实提交被中断或成功后误报登录失效。

## 修复

- 支持搜狐两阶段微信登录，并明确识别 OAuth 绑定失败和未实名发文限制。
- 编辑器直链回到内容首页时，自动通过“发布内容”入口进入图文编辑器。
- 使用真实上传管理器文件输入，等待上传完成并点击“确定”后再校验正文图片。
- 精确匹配当前 `li.publish-report-btn.active` 发布控件。
- 仅在离开图文编辑器或出现明确结果时进入对账，避免中断发布请求。
- 等待内容首页账号标识异步渲染；对账忽略同名草稿，只接受 `processing | published | failed`。
- API 安全透传 `ACCOUNT_PERMISSION_REQUIRED`，不把账号权限问题泛化为未知错误。

## 验证

- 搜狐 Worker 单元测试：21/21 通过。
- 搜狐本地浏览器集成测试：6/6 通过，覆盖编辑器入口、异步登录标识、同名草稿、重复匹配和未实名限制。
- Worker 类型检查通过；API 搜狐网关测试通过。
- 经用户明确授权，真实测试文章已由搜狐接受并进入“审核中”；只读对账返回外部内容 ID `1062672985`、`status=processing`，两条同名草稿未被误判为发布结果。

## 发布与回滚

部署 API 与 `sohu-browser` Worker。回滚本提交可恢复旧行为，但会重新暴露真实页面登录、上传、发布和对账问题；数据库与公开接口无变更。
