# HOTFIX-20260806-05 质量报告重写原文返回拦截

## 生产证据

- 百家号 v1 质检结果为 `score=45 / decision=block`，随后连续触发两次按报告重写。
- 第一次重写因结构化输出不符合 Schema 而失败，没有产生新版本。
- 第二次重写主稿成功，但目标百家号变体与 v1 的内容哈希完全相同。
- 相同内容直到写入 `content_versions` 时才触发 `content_versions_object_hash_uq`，最终被记录为通用 `GENERATION_FAILED`。

## 根因

- API 已校验并传递当前内容、最新质量报告和问题清单，AI Worker 也已把这些诊断交给 Content Writer。
- 重写输出只执行平台结构、字数和确定性风险检查，没有验证目标平台内容是否相对待修改版本发生变化。
- 模型原样返回旧内容时会被运行时当作已完成重写，旧质量问题也随之完整保留。

## 修复

- 质量报告驱动重写对每个目标平台比较新旧内容的规范化哈希。
- 首次输出与待修改版本完全相同时，携带原质量问题和“不得原样返回”诊断再执行一次完整修复。
- 如果唯一可验证问题是正文长度不足，继续使用既有精确缺口定向续写；续写后的最终内容仍必须与旧版本不同并通过完整平台字数门槛。
- 第二次仍完全相同时，以 `CONTENT_QUALITY_INSUFFICIENT` 失败，不写入重复内容版本。
- 二次完整修复继续保留原质量报告问题，不因追加确定性诊断而丢失。

## 安全边界

- 哈希变化只证明内容发生变化，不代表质量问题已经通过；重写后的内容仍须进入既有机器质检和冻结门禁。
- 不修改或伪造质量报告、评分、问题和通过结论。
- 不降低百家号及其他平台的字数、结构、事实、品牌、合规或平台适配门槛。
- 不自动重新评估旧内容、旧运行或旧质量报告。

## 部署与验收

- 仅需重新构建并部署 AI Worker；无 API、数据库、Contracts 或 Web 变更。
- 首次原样返回、第二次实质修改时，保存修改后的目标平台内容。
- 连续两次原样返回时明确失败，且不再暴露数据库唯一约束错误。
