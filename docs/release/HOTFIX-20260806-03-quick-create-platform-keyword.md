# HOTFIX-20260806-03 快速创作关键词平台匹配修复

## 生产证据

- 用户仅选择百家号，快速创作却提交了关键词“仓库搬迁”。
- 该关键词和词集均为 `active`，但 `platform_scope` 只有 `official_site`。
- `POST /briefs` 因此返回 `409 STATE_TRANSITION_INVALID`；前端错误地提示用户检查登录状态。
- 同一次用户操作产生了两个 `POST /briefs`，说明仅依赖 React 渲染后的按钮禁用不足以阻止同步重复提交。

## 修复

- 快速创作只展示并自动选择与当前平台范围有交集的关键词。
- 管理员在没有兼容关键词时，使用当前主题和所选平台自动创建关键词。
- 非管理员没有兼容关键词时停止提交，并给出明确配置入口。
- Brief API 客户端保留服务端错误代码；401、403、409、422 分别显示对应原因，不再统一归因于登录态。
- 增加同步提交锁，重复提交事件只允许一个请求进入保存链路。

## 安全边界

- 不放宽后端关键词、资料、项目或平台范围校验。
- 不自动修改已有关键词的平台范围。
- 资料有效性仍由原有门禁校验；本 Hotfix 不把失效或不可信资料带入生成。

## 验收

- 仅选择百家号时，不再显示或提交仅适用于官网的关键词。
- 有管理权限且无兼容关键词时，自动创建百家号关键词后再创建 Brief。
- `409 STATE_TRANSITION_INVALID` 显示配置冲突原因，不显示登录失败。
- 同步触发两次表单提交时，后端只收到一个 `POST /briefs`。
