# HOTFIX-20260828-01 抖音生成与发布门禁对齐

## 问题

- HOTFIX-20260827-02 的叙事规则只在 Content Writer 生成阶段执行；人工修改等入口仍可能通过通用质量
  检查进入排期。
- 托管浏览器实际写入“主文案、换行和全部话题”，原 Render 只限制主文案自身，生成结果可能在最终
  发布时才因合计长度超限失败。

## 修复

1. 将抖音图文标题、主文案叙事、话题、卡片和当前企业名称规则收口为共享确定性策略。
2. Content Writer 与发布前 Quality Worker 复用该策略；模型给出 `pass` 也不能覆盖确定性阻断项。
3. 主文案、换行和全部 `#topics` 的实际输入合计上限为 1000 字，生成门禁、发布前质检、Render 和
   Browser Worker 使用同一拼接函数与上限。
4. 旧 `script_package` 不进入图文叙事门禁，继续兼容读取和导出。

## 边界

- 不降低事实、品牌、资质、图片或平台冻结门槛，不由服务端修改模型正文或伪造质量结论。
- 不自动重评旧内容、旧质量报告或旧发布任务；已排期旧任务仅在实际输入超过技术上限时于最终发布前
  失败关闭。
- 无数据库迁移、公开 API 或生产配置变化；本 Hotfix 不部署生产环境。

## 验证

- 共享策略覆盖合格叙事、人工短文旁路、当前企业名称位置与频次和实际输入总长度。
- 发布前风险扫描覆盖人工修改阻断，并验证旧脚本包不受图文门禁影响。
- Render 契约覆盖合计长度阻断；托管浏览器本地仿真验证填写内容与共享拼接函数一致。
