# HOTFIX-20260829-04 抖音验证方式选择页识别与安全诊断

## 根因

1. 抖音身份验证选择层可能同时展示“接收短信验证码”“手机刷脸验证”和“发送短信验证”。Worker 将
   “接收短信验证码”与语义不同的“发送短信验证”合并为同一种短信方式，并优先选择后者。
2. Worker 使用 Playwright `isVisible()` 判断验证码输入框。该判断不检查前景遮罩和点击目标，导致
   选择层下方仍可见但不可操作的输入框被误判为已经进入验证码填写阶段。
3. 既有脱敏截图已写入私有对象存储，但运行日志没有截图哈希、对象位置和安全控件特征，无法直接判断
   当前是选择层、验证码输入层还是被另一层安全验证遮挡。

## 修复

1. 优先识别可见的 `#uc-second-verify` 身份验证层，并将控件查找和验证码输入限制在该前景层内；没有
   专用容器时才使用带身份验证标记的标准对话框或当前页面。
2. `verification_sms_send` 只选择“接收短信验证码”或明确的通用短信验证入口，不再选择
   “发送短信验证”，也不自动操作刷脸验证。只提供不受支持方式时返回页面结构变化并失败关闭。
3. 验证码输入框必须同时可见、启用、可编辑且通过 Playwright 试点击的可操作性检查，才返回
   `has_code_input=true`；被遮罩的底层输入框不再使 Web 展示验证码提交入口。
4. 页面签名和私有诊断增加纯布尔控件证据：前景验证层、接收短信、发送短信、刷脸、原设备扫码、
   验证码输入可见性和可操作性。诊断日志同时记录截图 SHA-256、私有对象 URI、页面签名和挑战类型。
5. 脱敏截图继续隐藏全部文字与背景图，并遮盖输入框、图片、二维码、头像和账号区域；截图只增加验证
   对话框边界标记。新增结构化日志不记录企业名、头像、完整或脱敏手机号、验证码、Cookie、原始 DOM
   或页面正文；HOTFIX-20260829-02 已批准的脱敏手机号白名单响应保持不变。

## 边界

- 本 Hotfix 不实现刷脸验证或“发送短信验证”，不识别或绕过抖音风控。
- 短信仍只能由用户明确点击后发送，验证码不落库、不进对象存储或日志。
- 无数据库迁移、公开 API、生产配置、发布质量门槛或登录成功判定变化；旧诊断继续兼容读取。

## 验证

- Worker 单元测试覆盖诊断证据持久化、截图索引日志及敏感信息不进入日志。
- Playwright 仿真同时放置前景三方式选择层和被遮挡的底层验证码输入框，验证只选择“接收短信验证码”；
  另覆盖验证码输入层被安全遮罩时不得判定为可输入。
- Worker 类型检查、构建、单元测试和相关浏览器集成测试通过。
