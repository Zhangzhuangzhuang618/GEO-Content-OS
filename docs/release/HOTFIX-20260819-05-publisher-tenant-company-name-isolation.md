# HOTFIX-20260819-05 Publisher 企业名称租户隔离

## 根因

生产日志中的失败对象实际是众人搬家官网任务，不是列举网外部发布请求。生文与质检已经按当前企业
资料运行，但 Publisher 的官网 Render Adapter 仍把“广州志远搬家服务有限公司”写成全局唯一允许
名称，导致众人租户内容在发布前被跨租户规则拦截。

## 修复

- Publisher 领取任务时按 tenant/workspace 读取当前工作区已发布品牌档案。
- 从该档案提取完整法定企业名称，并显式传给官网 Render Adapter。
- 移除公共企业名称策略中的志远默认值；未传入企业边界时保持失败关闭。
- 当前企业名称允许出现，其他企业名称继续阻断；不做地区或简称模糊匹配。
- 官网 Render 输入契约升级到 `official-site-render-rules@1.2.0`。
- 不改变冻结质量门槛、质量报告、未知发布防重复规则或旧任务状态。

## 部署与旧任务

- 无数据库迁移和公开 HTTP API 变化。
- 重新构建并部署 Publisher Worker；共享构建产物部署模式下同时重建 AI Worker，避免使用旧公共契约。
- 部署前确认各企业当前工作区的已发布品牌档案中包含准确完整的法定名称。
- 旧失败任务不会自动重投。部署后核对文章中的名称与当前品牌档案一致，再使用普通重试；名称本身写错
  的内容仍应回到内容处理流程修正并重新质检。
