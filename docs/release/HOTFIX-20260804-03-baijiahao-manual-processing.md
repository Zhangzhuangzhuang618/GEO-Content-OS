# HOTFIX-20260804-03：百家号需人工项处理链路

## 现状核验

生产查询返回两条百家号发布前 `manual_required` 记录：

- 独立生成候选因 `ADAPTATION_EXECUTION_FAILED` 停止，尚未创建发布任务。
- 官网派生候选因 `QUALITY_GATE_FAILED_AFTER_MAX_REWRITES` 停止，阻断规则为
  `gate.question_coverage`，尚未创建发布任务。

它们都应回到内容处理和质量检查链路，不能按发布失败任务直接重试。首页此前把发布任务汇总链接到缺少
`id` 的 `/pub-03` 详情路由，属于无效入口。

## 修复范围

- 首页发布任务汇总统一进入 `/pub-02` 发布任务列表。
- 百家号自动化面板返回今日需人工项明细，并提供内容、质量报告及已有发布任务的精确链接。
- 内容详情同时展示官网与百家号自动化运行状态、最后错误、全部内容版本和质量报告。
- 人工编辑后可重新发起质量检查；百家号运行和每日批次项同步恢复到质量检查状态。
- 只允许改写执行失败、质检执行失败、达到最大重写次数三类发布前错误进入重新质检。
- 浏览器提交结果不确定等发布阶段错误继续要求从发布记录人工核对，禁止借重新质检盲目重发。

## 冻结边界

- 不修改任何冻结质量分数或阻断规则。
- 不伪造模型判断，不自动把历史质量报告改为通过。
- 重新质检创建新的运行和报告，保留历史版本、报告和错误记录。
- 本 Hotfix 不操作生产数据库或生产平台。

## 验收

- API 集成测试覆盖需人工项查询、详情回显、重新质检状态恢复及浏览器歧义阻断。
- PUB-01 E2E 覆盖需人工项标题、错误摘要和精确处理链接。
- DASH-01 E2E 覆盖首页发布任务入口。
- CONT-04 E2E 覆盖内容全文、历史版本、质量报告和重新质检入口。
- Web 构建、类型检查和相关代码检查通过。
