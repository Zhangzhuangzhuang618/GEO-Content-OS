# HOTFIX-20260903-01 浏览器平台发布可靠性修复

## 根因

1. 抖音多账号错峰排期在首个配置时段冲突后立即顺延，没有先检查同一策略当天其余配置时段，导致多个候选集中排成连续的 20 分钟间隔。
2. 百家号当前编辑器已移除旧版“采用AI生成内容”勾选项，原页面驱动仍把该旧控件作为必需签名；账号封停弹窗还会在封面阶段被误报为普通页面变化。
3. 列举网日批虽然向 Content Writer 提供了引用资料，但首稿没有确定性要求至少使用一条与当前主题直接相关的引用；局部重写也可能删除正文仍保留声明的原有引用映射。

## 修复

1. 抖音排期按“全部原始配置时段优先、再逐轮增加 20 分钟偏移”选择空位，并继续以工作区事务锁和已有任务检查保证同公司账号错峰。
2. 百家号保留旧编辑器勾选逻辑；旧控件缺失时，仅在同时识别到当前“智能创作”区域及其已知控件后继续发布。未知页面仍失败关闭。账号封停弹窗改为明确的 `ACCOUNT_RESTRICTED`，不再误报为封面上传故障。
3. 列举网真实日批在输入含引用时要求至少产出一条直接支持当前正文事实的引用映射。完整重写后，如果原声明仍可见、引用仍属于本次冻结输入且声明键未被替代，服务端保留原映射；错误匹配和无关引用继续由既有事实与质量门禁阻断。

## 兼容性与限制

- 不修改数据库、公开 API、环境变量或 Docker Compose。
- 不重排历史发布任务；新排期在修复部署后生效。
- 百家号账号被平台封停属于外部账号限制，本修复只准确识别并停止自动发布，不能解除封停。
- 列举网普通手工生成不新增强制引用要求；修复仅作用于系统已冻结引用输入的自动日批。

## 验证范围

- AI Worker 完整单元测试，以及抖音跨账号排期和列举网引用生成、重写保留专项测试。
- 百家号 Worker 完整单元测试和本机浏览器仿真，覆盖新版编辑器、旧版编辑器及账号封停弹窗。
- 两个 Worker 的 TypeScript 类型检查与生产构建。
- 变更文件 Lint、格式检查、Git 差异检查和 Release static gate。
