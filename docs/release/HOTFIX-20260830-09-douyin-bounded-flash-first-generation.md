# HOTFIX-20260830-09 抖音日批受限结构生成

## 根因

生产模型路由恢复后，新批次的主要问题从 JSON 结构退化转为内容质量：18 个候选中 11 个由既有门禁
淘汰、3 个达到工具轮次上限、4 个完成生成。Content Writer 原流程要求一次返回完整母稿和抖音变体，
并允许模型重复读取已绑定在输入中的品牌资料和平台规则。工具调用和大型输出均不是抖音日批的必要
条件。

## 修复

1. 抖音日批首稿改用 Flash，Quality 模型与 Quality Checker 继续使用 Pro。
2. 服务端在事件中标记已绑定上下文；运行时不向该路径提供工具。
3. 模型只填写固定叙事和卡片槽位；服务端确定性组装现有冻结 Content Writer 数据结构。
4. 组装结果继续执行所有现有质量、企业名称、证据和资质门禁。
5. 首稿问题先由 Flash 定点修复一次，仍不合格才由 Pro 按相同浅层结构兜底。
6. 扩展抖音资质扫描范围到主文案和卡片元数据，避免浅层输出绕过既有证据门禁。

## 部署与回滚

- 无数据库迁移、公开 API 或新增环境变量。
- 重建并替换 `ai-worker` 即可生效；API、Web、Publisher 和抖音浏览器容器无需因本修复重建。
- 部署后核验启动日志中的 `douyin_daily_draft_model_key=deepseek-v4-flash`、
  `quality_model_key=deepseek-v4-pro` 和 `quality_checker_model_key=deepseek-v4-pro`。
- 历史批次不自动重跑；由发布管理员显式重新发起当日日批。
- 回滚到上一提交并重建 `ai-worker` 后，抖音日批恢复由 Pro 直接生成完整结构。
