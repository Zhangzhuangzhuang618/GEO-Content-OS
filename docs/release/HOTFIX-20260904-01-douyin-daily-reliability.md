# HOTFIX-20260904-01 抖音日批生成与发布可靠性修复

- 状态：已完成
- 日期：2026-09-04
- 影响范围：AI Worker、Douyin Browser Worker
- 前置决策：ADR-0074、ADR-0077、ADR-0081、ADR-0082

## 根因

1. Chromium 在生产发布前复核中返回 `locator.count: Target crashed`。现有恢复规则只识别 `Page
   crashed`，因此没有释放损坏页面重试，并把四个账号会话持久化为 `BROWSER_RUNTIME_FAILED` 的
   `attention_required`。后续定时发布又在打开浏览器前直接拒绝所有 `attention_required`，即使加密
   登录态仍然有效也无法自行恢复。
2. 抖音短卡的候选经常已经收到当前企业的结构化证照引用，但模型没有把逐字可见事实写入正文及
   `evidence_claims`，导致“证据映射为空”或“声明不在可见文案中”。
3. 一线师傅口吻缺少“你/您”时，局部修复错误地指向服务端锁定结尾；修复结果随后被固定结尾覆盖，
   同一问题在有界重试中必然重复。

## 修复

1. 浏览器运行时恢复同时识别 `Page crashed` 与 `Target crashed`。会话轮询和发布前复核遇到该错误时，
   释放当前账号页面并只重试一次。
2. 仅当会话错误码为 `BROWSER_RUNTIME_FAILED` 且仍有完整加密登录态时，下一次定时发布先复核登录态；
   复核通过后清除运行时错误并恢复为 `authenticated`。CAPTCHA、短信验证、页面签名变化及其他人工状态
   不进入该路径，继续返回 `SESSION_ATTENTION_REQUIRED`。
3. 抖音直接日批先删除无效或不可见的模型证据映射；如果没有可见映射，服务端从本次冻结输入中选择
   当前唯一法定企业持有、主体精确匹配且已授权的结构化企业证照，优先使用营业执照，确定性补入一条
   简短事实并映射原引用。没有合格证照时继续由原质量门禁失败关闭，不编造事实。
4. 一线师傅的直接客户称呼缺失时，修复目标改为未锁定的首个方案正文段；服务端固定结尾保持不变。

## 边界

- 不修改数据库、公开 API、环境变量或 Docker Compose。
- 不降低标题、长度、口吻、证据或发布质量门禁，不把随机模型质量失败视为代码成功。
- 不处理没有新页面截图、DOM 特征或网络响应证据的百家号选择器变化；账号人工状态仍需获得可复现证据后
  单独修复。
- 不自动重写历史内容，也不自动重新触发历史日批。
