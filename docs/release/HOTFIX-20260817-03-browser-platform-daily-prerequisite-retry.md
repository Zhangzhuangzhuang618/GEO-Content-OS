# HOTFIX-20260817-03 搜狐号与列举网今日批次前置资料重试

## 现象与根因

- 搜狐号或列举网日批到点创建后，若项目当时缺少适用关键词等前置资料，批次会立即进入 `attention_required`。
- 后续补齐资料不会自动复活该批次；当天唯一批次已经存在，调度器也只处理 `running` 批次。
- 原管理界面没有受控恢复入口，只能等次日或直接修改数据库。

## 修复

- 新增发布管理员可见的“重试今日批次”入口。
- 仅允许今日、错误码为 `AUTOMATION_PREREQUISITE_MISSING`、候选数为 0 的批次恢复为 `running`。
- 请求必须携带幂等键和当前批次版本，恢复操作写入审计事件。
- 一键同步关键词后的提示会引导用户在资料补齐后显式重试，不自动产生新的 AI 调用。

## 安全边界

- 候选已经创建、候选上限耗尽、发布失败、非前置资料错误或历史日期均不可使用此入口。
- 不删除批次，不修改候选上限，不降低质量门禁，不重新评估旧内容或旧质量报告。
- 若前置资料仍不完整，调度器会再次按真实检查结果停止，不伪装为成功。

## 部署

- 重新构建并部署 Contracts、API 和 Web；AI Worker 逻辑未修改，无数据库迁移。
- 部署后在搜狐号或列举网“全链路自动化”面板中补齐资料，再点击“重试今日批次”。
