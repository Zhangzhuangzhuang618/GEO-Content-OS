# HOTFIX-20260905-02 抖音登录态判定与图文标题边界修正

## 生产证据

- 2026-09-05 12:00 后的人工链路先完成抖音登录，随后在发布 21 字图文标题时进入未兼容页面并报
  `PAGE_SIGNATURE_CHANGED`；会话进入 `attention_required` 且浏览器上下文被释放后，状态轮询因找不到
  原验证页面返回 `AUTH_REQUIRED`，服务端直接把账号写成 `reauth`。
- 生产 Creator Center 页面明确显示图文标题最多 20 字；现有写作、平台规则和渲染载荷分别允许
  26 或 30 字，超过页面边界的标题会在浏览器阶段失败。

## 根因

- 页面驱动以布尔值表示认证状态：既没有认证特征也没有明确登录特征的未知页面，与明确登录页同样返回
  `false`。登录 URL 判断还会把查询参数中含 `/login` 的非登录页误判为登录页。
- `attention_required` 会话失去内存页面后，状态轮询没有使用已有的加密持久化登录态重新验证，而是把
  “原验证页面不可用”直接解释为登录过期。
- 图文标题上限分散在写作提示、契约、确定性门禁、日批标题、渲染载荷和平台规则版本中，未与生产页面
  的 20 字限制同步。

## 修复

- 页面认证判定改为 `authenticated`、`login_required`、`unknown` 三态；只有明确登录控件或 URL
  pathname 为登录页时才返回登录失效，未知页面改报 `PAGE_SIGNATURE_CHANGED`。
- 已有完整持久化登录态的 `attention_required` 会话在原页面不存在时重新打开 Profile 验证；验证成功
  恢复 `authenticated`，只有明确落到登录页才写 `LOGIN_EXPIRED` 和 `reauth`。
- 预发布验证遇到未知页面时保存 `attention_required` 并返回结构化 HTTP 423，不再冒泡成 500，也不
  写成登录失效。
- 抖音图文标题的写作提示、Content Writer 契约、直接日批、编辑质量门禁、日批主题截断、渲染输入、
  冻结载荷和浏览器网关统一按最多 20 字校验。新增平台规则 `douyin@1.2.0`，将动态规则上限同步为 20。

## 数据库与部署

- 迁移 `0058_douyin_image_note_title_limit.sql` 仅退役当前抖音规则并发布不可变的新规则版本；不修改
  历史内容、冻结输入、发布任务或浏览器发布记录。
- 历史规则 `douyin@1.1.0` 保留，以便已有冻结任务继续还原当时输入。浏览器发布记录的 30 字历史存储
  包络保持不变，新写入由应用契约和当前平台规则实施 20 字限制。
- 需重建 `api`、`ai-worker`、`publisher-worker` 和 `douyin-browser`，并执行迁移 0058。无公开 API、
  环境变量或 Compose 变化。

## 边界

- 未知页面仍暂停自动发布并要求检查页面适配，不会被当成登录成功继续提交。
- 历史失败、终态任务和超过 20 字的既有排期不自动改写或重试；重新生成或处置排期需要单独操作。
- 不从昵称、头像或未冻结 DOM 推断账号身份，不降低验证码、短信验证、页面签名或发布状态确认门禁。

## 验收

- 未兼容页面及查询参数含 `/login` 的非登录页不得返回登录失效；明确 `/login` pathname 仍返回失效。
- 已认证的持久化会话从未知页面恢复后保持认证；重新验证明确进入登录页时才转为 `reauth`。
- 未知预发布页面返回 `PAGE_SIGNATURE_CHANGED`/423，并记录 `attention_required`。
- 图文标题 20 字通过，21 字在写作契约、渲染契约和浏览器网关入口被拒绝；旧脚本载荷仍保持原兼容边界。
