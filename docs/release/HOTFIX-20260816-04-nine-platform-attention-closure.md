# HOTFIX-20260816-04 九平台入口与待处理闭环

## 问题

- 搜狐号和列举网已经进入生成与发布主链路，但首页快速创作及多个平台筛选仍只显示原有七个平台。
- 部分前端与契约仍按最多八个平台解析，选择全部九个平台时可能把合法响应判为异常。
- 首页“需要处理的异常”只打开最近一条失败任务，没有完整队列。
- 搜狐号和列举网日批只显示汇总数量，用户无法从界面进入对应内容、质量报告或发布任务。

## 修复

- 将创作、内容、选题、关键词、审核、发布、工作区、平台规则和数据页面的平台选项统一为九个平台。
- 将内容、审核、工作区和分析契约的旧八平台上限统一为九个平台，并重新生成 OpenAPI。
- 内容包列表增加 `attention_required=true` 服务端筛选，覆盖生成失败、质量失败、审核退回和发布失败；首页异常卡片进入该队列。
- 搜狐号和列举网日批返回逐篇待处理明细，展示失败原因，并提供全文、质量报告和发布任务链接。
- `publish_failed` 仍需从发布任务重试或对账；质量失败仍需编辑并重新质检。没有伪造成功状态。

## 质量边界

- 不修改质量门槛、最多三次重写、候选上限或发布重试上限。
- 不重新评估历史内容和历史质量报告。
- 不新增数据库迁移。

## 验证

- Contracts 内容、发布、分析契约测试通过（22/22）。
- Contracts、API、Web 类型检查通过。
- Web 生产构建通过。
- 首页原有回归 11/13 首轮通过；两项因旧构建和日期夹具失败，重建并修正夹具后复跑 2/2 通过。
- 内容列表原有回归 11/11 通过；新增待处理筛选用例通过。
- 发布账号页原有回归 11/11 通过；新增搜狐号待处理明细用例通过。
