# HOTFIX-20260822-02 百家号浏览器生命周期与恢复校验

## 问题

- 百家号 Worker 按账号永久缓存 Playwright Page 与 BrowserContext，只判断 Page 是否关闭，不在发布、登录核验或对账结束后释放。
- 生产页面崩溃后，后续排期继续复用同一个空白或高 CPU 页面，形成“首次发布完成，后续发布持续失败”的账号级阻断。
- “检查并恢复”只确认百家号首页仍为登录状态，没有确认图文编辑器可用，因此可能错误解除 `attention_required`，下一次发布随即再次失败。

## 修复

- 为百家号 Page Driver 增加按账号释放能力；每次登录核验、发布和内容列表对账完成后关闭并移除该账号的 Page 与 BrowserContext。
- 下次操作使用加密 storage state 初始化并沿用现有临时 Profile 建立新上下文；同一 Worker 生命周期不反复用旧加密状态覆盖 Profile 中更新后的 Cookie，不保存账号密码，不改变账号串行锁。
- 保留普通登录核验对“已登录首页”的兼容；只有解除安全暂停时增加严格可发布校验，必须直接或经“发布作品 → 图文”进入冻结编辑器签名。
- 扫码登录仍在同一上下文等待完成；旧发布任务的状态查询在 `qr_ready` 期间不启动浏览器，避免打断扫码。
- 上下文释放失败只记录脱敏诊断，不覆盖已经持久化的发布或会话结果。

## 不变边界

- 不修改百家号质量门槛、最多重写次数、发布重试上限、幂等键或未知提交对账规则。
- 不把首页登录态、空白页或不可识别页面伪装为编辑器可发布。
- 不自动重投旧失败任务，不重新评估旧内容或旧质量报告。
- 无数据库迁移、公开 API 或 Web 变更。

## 验证

- 百家号 Worker 单元测试通过，覆盖严格恢复、失败保持安全暂停、异常后释放和扫码会话隔离。
- 本地 Chromium 仿真回归通过，覆盖登录态与可发布态分离、首页回退进入编辑器、上下文释放后从加密状态恢复及既有发布对账链路。
- 百家号 Worker 类型检查与生产构建通过。

## 部署

- 只需重新构建并部署 `baijiahao-browser` Worker。
- 部署后对已处于 `attention_required` 的账号点击“检查并恢复”；只有编辑器可用时才会恢复。
- 已失败且达到人工处理条件的旧任务继续按现有人工确认或重试路径收尾，不会自动重复发布。
