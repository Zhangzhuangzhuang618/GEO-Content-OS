# HOTFIX-20260805-06 质量重写追踪与收敛

## 问题

- 质量报告页发起“按质检报告重写”后只显示请求已受理，没有保存接口返回的生成任务 ID，也不查询生成及后续质检状态。用户停留在当前页面时无法知道任务是否排队、运行、失败或已生成新报告。
- 百家号质量报告同时要求补足字数和删除 CTA 时，重写使用 `balanced` 模型策略对应的生成阶段折算门槛，可能在 680 个有效字符时结束；外部冻结门禁仍要求 850 个有效字符。删除 CTA 后正文变短，下一轮又可能补回 CTA，造成反复重写而不收敛。
- 质量报告页手动重新检查时只判断“是否存在报告”，旧报告仍在数据库时会被错误当作本次检查结果。

## 修复

- Web 保存重写接口返回的生成任务 ID，每 2 秒查询生成任务和内容详情，并显示排队、生成、自动质检、失败、取消和超时状态。
- 重写产生新内容但新质量报告尚未落库时，页面显示明确过渡态，不再退化为“没有质量报告”；生成详情链接在处理期间及处理结束后均可访问。
- 新质量报告到达后自动切换到最新报告并恢复操作按钮。没有自动质检链路的平台在生成成功后提示用户手动检查。
- 手动质量检查以发起时的报告 ID 为基线，只在出现不同的新报告 ID 后结束轮询。
- 所有平台的质量报告驱动重写均按各平台完整冻结结构和字数门槛做生成阶段校验；`balanced` 仍只决定模型选择和温度，不再降低重写验收门槛。
- 百家号 CTA 字段和 CTA 内容块加入确定性生成校验。存在 CTA 或其他结构问题时先做一次联合修复；删除后若最终允许正文仍不足 850 个有效字符，再沿用定向续写机制补充实质内容，并对最终结果重新校验。

## 多平台核验

- 百家号冻结下限保持 850；头条号 850、知乎 1100、小红书 500、微信公众号 1300、抖音 420，均通过 `balanced` 质量报告重写测试验证使用完整平台门槛。
- 官网继续使用独立的 1300 字直接生成与重写链路，本 Hotfix 不改变官网门槛或发布流程。
- 头条号、知乎、小红书、微信公众号和抖音不新增自动质检；重写成功后页面明确提示发起质量检查。

## 冻结契约

- 未降低任何平台的字数、结构、事实、品牌、合规、来源相似度或 GEO 质量门槛。
- 服务端不删除正文来伪造合格结果，也不创建或修改模型质量结论；重写结果仍须经过原机器质检和发布门禁。
- 百家号仅确定性禁止现有冻结规则不允许的 CTA 字段和 CTA 内容块，其他内容问题仍由既有质量报告与门禁判断。

## 部署

- 重建并更新 AI Worker 和 Web；API 接口未变更，无需因本 Hotfix 单独重建 API。
- 旧内容、旧生成任务和旧质量报告不会自动重评；需在质量报告页重新发起“按质检报告重写”验证新链路。

## 验证

- AI Worker：16 个测试文件、105 项测试全部通过，包含百家号 CTA 删除后按 850 字门槛续写，以及六个平台完整字数门槛回归。
- 质量报告页 Playwright：9 项测试全部通过，覆盖生成任务追踪、无报告过渡态和新质量报告自动刷新。
- 全仓 TypeScript 类型检查通过；全仓 ESLint 检查通过（排除用户现有未跟踪文件 `build_keywords.mjs` 和 `outputs/`）。
- Web 生产构建通过；本 Hotfix 相关文件 Prettier 检查通过。
