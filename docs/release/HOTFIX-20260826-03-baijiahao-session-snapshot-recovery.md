# HOTFIX-20260826-03 百家号加密会话快照恢复

## 问题

- 百家号明文浏览器 Profile 按安全约束只保存在 `tmpfs`，容器重启后必须依赖数据库中的加密 storage state 恢复。
- 实时登录核验和发布前核验成功时只更新 `last_verified_at`，没有同步刷新加密 storage state；通过“检查并恢复”恢复的旧会话可能因此始终没有可用快照。
- 临时 Profile 被容器重启清除后，下一次发布无法恢复登录，并进入 `LOGIN_EXPIRED`。
- 平台账号的普通“重新验证授权/测试连接”只探测浏览器网关能力，可能把浏览器会话仍为 `reauth` 的百家号账号误标为 `active`，使重试继续进入必然失败的发布链路。

## 修复

- 每次百家号实时登录核验成功后，导出当前 storage state、使用既有凭证信封加密，并与最新核验时间一起原子更新浏览器会话。
- 每次发布前确认登录有效后同样刷新加密快照，再进入幂等发布流程；后续容器重启从最近一次成功核验的快照恢复。
- 百家号平台账号执行普通授权刷新或能力测试时，以浏览器会话为登录状态权威：`authenticated` 和 `attention_required` 保持账号可用，缺少会话、`login_required`、`qr_ready` 或 `reauth` 均保持账号为 `reauth`。

## 不变边界

- 明文 Profile 继续只存在受限 `tmpfs`，不增加未加密持久卷，不记录 Cookie、二维码令牌或凭证。
- 不弱化登录、验证码、页面签名、未知提交或质量门禁。
- 不自动恢复已失效登录，不自动重投旧失败任务，不修改旧内容或旧质量报告。

## 验证

- 百家号 Worker 单元测试覆盖无旧快照的安全暂停恢复、核验后加密快照持久化、发布前快照刷新和原有异常处理。
- 平台账号 PostgreSQL 集成测试覆盖浏览器会话为 `reauth` 时能力探测不得伪装为可用，以及会话重新认证后账号恢复为 `active`。
- 百家号 Worker 类型检查、API 类型检查和相关生产构建必须通过。

## 部署与现有账号处理

- 重新构建并部署 `api` 与 `baijiahao-browser`。
- 已经处于 `reauth` 且没有加密快照的账号仍需重新扫码一次；扫码成功后新逻辑会保存可用于后续容器重启恢复的加密快照。
- 原失败任务保持原状态，确认百家号后台未发布后再从现有人工重试入口处理。
