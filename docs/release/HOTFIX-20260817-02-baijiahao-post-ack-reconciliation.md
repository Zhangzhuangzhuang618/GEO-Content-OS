# HOTFIX-20260817-02 百家号成功回执与列表对账隔离

## 现象与根因

- 生产日志显示百家号发布请求已经受理，但紧随其后的内容管理页没有打开可验证列表。
- 驱动把列表核验的 `PAGE_SIGNATURE_CHANGED` 覆盖到已经取得的严格发布成功回执上。
- 服务随后把账号会话标记为 `attention_required`，导致下一次排期直接返回 `SESSION_ATTENTION_REQUIRED`。

## 修复

- 发布按钮触发的接口必须仍然返回业务成功码和文章 ID，才形成严格成功回执。
- 取得严格成功回执后，立即列表核验发生页面签名异常时保留回执，任务进入 `processing` 等待后续对账。
- 已保存文章 ID 的后续列表签名异常返回 `unknown`，不暂停整个账号会话。
- 已保存文章 ID 的任务只能继续对账，禁止经过未知态宽限期后重新提交。

## 不变的安全边界

- 验证码、登录过期、重复匹配、平台明确驳回和提交前编辑器异常仍按原规则停止自动化。
- `processing` 和 `unknown` 都不等于已发布；只有真实远端对账结果可以完成发布任务。
- 不降低内容质量门禁，不修改旧质量报告，不由服务端伪造平台状态。

## 部署与验收

- 只需重新构建并部署 Baijiahao Browser Worker，无数据库迁移。
- 部署后先恢复当前 `attention_required` 会话，再观察下一次排期；旧任务继续走状态对账，不重新提交。
- 若仍出现 `page.goto: Page crashed`，属于浏览器运行时故障，需要独立日志和进程状态继续排查，不应归因于本 Hotfix。
