# HOTFIX-20260805-02 多平台质量误判修复

## 问题

2026-08-05 官网日批生产样本显示，质量检查模型会把唯一允许的公司名称“广州志远搬家服务有限公司”以及明确允许的“某公司”“某搬家公司”错误报告为 `brand.other_company_name`。模型还会报告并不存在于指定标题或正文块中的公司名称，服务端此前直接接纳这些问题，导致自动重写在合法名称与匿名名称之间反复切换。

同一批次还暴露出两项确定性扫描误判：官网技术字段 `platform_meta.slug` 中的随机数字被当作电话号码；车型套餐“配备2人”被当作企业人员规模。上述扫描和质量检查入口由所有平台共用，因此官网、百家号、头条号、知乎、小红书、微信公众号和抖音均存在同类风险。

## 修复

- 服务端复核模型返回的 `brand.other_company_name`：报告明确指出的第三方名称真实存在于当前内容中时保留；本公司全称、允许的匿名描述或与当前内容不一致的具名报告不进入门禁。未给出可复核名称的报告继续保留，避免漏掉无公司后缀的真实品牌。
- 确定性公司名称扫描继续作为硬门禁；真实出现的其他法定公司名称、数据提供商名称以及模型明确定位的第三方品牌仍会阻断。
- 电话、价格、地址、规模和百家号导流扫描排除 slug、Schema.org 类型等技术元数据；官网必需的技术字段完整性检查保持不变。
- 企业规模规则不再把按车型或套餐配置的作业人数当作企业规模；“公司配备80名员工”等企业人员规模仍需品牌资料或证据支持。
- 官网和百家号自动重写对无证据事实增加明确指令：无直接证据时删除命中数值或整项声明，禁止只改标点、运算符、数字写法或同义词。

## 多平台核验

- 所有平台统一经过 `QualityCheckWorker`、模型问题复核和确定性风险扫描，修复不依赖平台分支。
- 官网和百家号继续使用各自冻结门禁与最多三次自动重写。
- 头条号、知乎、小红书、微信公众号和抖音继续执行既有人工质检与按报告重写流程。

## 冻结契约

- 未修改任何平台的字数、结构、GEO 分数、事实、品牌、合规或来源相似度门槛。
- 服务端只删除能够由当前内容客观证明为错误的模型公司名称问题，不生成新的模型评分，也不把真实第三方名称改判为合格。
- 无证据的价格、电话、地址、企业规模和高风险事实仍由原有确定性规则阻断。
