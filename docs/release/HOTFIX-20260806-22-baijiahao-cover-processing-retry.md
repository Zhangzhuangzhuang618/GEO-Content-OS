# HOTFIX-20260806-22 百家号封面裁剪完成后重试确认

## 真实页面证据

- 完整正式驱动的点击审计确认，上传后按钮由浅蓝逐渐变为深蓝，第一次确认点击发生在深蓝状态，且全程只有一次点击。
- 第一次确认后平台明确提示“封面裁剪处理中，请稍后再点击‘确定’”，弹窗保持打开。
- 调试流程等待该提示消失、移开鼠标并重新观察到深蓝按钮后，第二次确认成功关闭弹窗，驱动到达发布前截图；调试断点随后在发布点击前停止。
- 这证明按钮颜色只能用于单次点击前的页面状态门禁；平台的裁剪处理中提示才是允许封面确认重试的业务证据。

## 修复

- 第一次封面确认后同时等待弹窗关闭或精确的裁剪处理中提示。
- 弹窗正常关闭时不重试。
- 仅在出现该精确提示时，等待提示消失和按钮重新进入深蓝状态，再执行一次封面确认。
- 第二次确认后仍未关闭弹窗时按超时失败处理。
- 浏览器仿真覆盖第一次确认收到裁剪处理中提示、第二次确认成功的路径。

## 安全边界

- 封面确认最多两次，第二次必须由平台精确提示触发。
- 不因通用超时、未知提示或页面异常重复点击。
- 不重试发布按钮，不放宽封面预览、质量、幂等或未知态门禁。

## 部署与验收

- 重新构建并部署 Baijiahao Browser Worker；无需数据库迁移。
- 单元测试和浏览器回归必须保持通过。
- 第二篇必须由正式驱动取得平台成功确认，并在内容列表按精确标题检索到，之后才能统一推送本批 Hotfix。
