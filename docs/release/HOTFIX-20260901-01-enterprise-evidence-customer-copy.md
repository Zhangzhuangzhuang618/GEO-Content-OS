# HOTFIX-20260901-01 企业资料引用与客户化表达

## 根因

官网和列举网原来只有一个资料检索通道。证照与主题资料共同竞争最多 5 个引用位置，且证照最多保留
3 份，导致已导入的体系认证、运输证件和保障资料不能稳定进入文章。Content Writer Prompt 同时要求
解释第一方资料边界，使内部核验语言反复出现在客户正文。

全新数据库还存在两个初始化缺口：历史迁移 0037 和 0046 在身份 Seed 之前执行，无法取得 Prompt 或
平台规则的创建人，因此不会插入自动日批 Quality Checker 1.2.0 和列举网规则 1.0.0；原冻结 Seed
也没有补齐这两条运行基线。

## 修复

1. 从当前工作区最新已发布品牌资料识别唯一法定企业名称；名称缺失或冲突时停止官网/列举网生成。
2. 按主体精确匹配、有效期、状态和公开授权加载当前企业全部结构化基础资料，独立于最多 3 份主题资料。
3. 官网与列举网由服务端确定性插入动态资质保障文案，并把全部基础资料加入最终引用映射。
4. 工作区只有显式确认支持客户索取资料时才输出对应联系方式文案，默认使用“可供客户核验”。
5. 所有平台从 Prompt、模型输入、生成扫描和发布层清除内部风控、证据分类和模板化免责语言；事实及引用
   门禁不变。
6. Publisher 在发布前重新读取当前有效基础资料，核对唯一主体、正文名称、资料名称和完整引用映射。
7. 新增 Prompt 迁移 0054；表数保持 92，公开端点保持 170。
8. 新增可选工作区资料完整性策略 `enterprise_evidence_required_kinds`；配置后，官网和列举网在缺少任一
   必需类别时停止生成和发布，未配置时按企业当前实际拥有的有效资料生成。
9. 修复全新数据库初始化缺口：冻结 Seed 幂等补齐自动日批 Quality Checker Prompt 1.2.0 与列举网
   规则 1.0.0，不再依赖历史迁移执行时已经存在创建人记录。

## 兼容性

- 不修改历史文章，不自动重发旧内容。
- 不为列举网增加证照图片能力。
- 百家号、搜狐号、头条号、知乎、小红书、微信公众号和抖音不强制完整基础资料包，但统一禁止内部话术。
- 基础资料数量不写死；没有任何合格基础资料时官网和列举网生成失败关闭。

## 验证范围

- 企业资料分类、唯一主体、动态文案和工作区确认开关单元测试。
- 两个企业工作区的名称与引用隔离测试。
- 7 份基础资料加 3 份主题资料的检索测试。
- 官网/列举网发布门禁及所有平台内部话术阻断测试。
- AI Worker、API、Knowledge Worker、Publisher 类型检查与相关测试。
- OpenAPI、全新数据库迁移、Compose 解析和 Release static gate。
