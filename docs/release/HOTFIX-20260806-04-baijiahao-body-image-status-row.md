# HOTFIX-20260806-04 百家号正文图片状态行定位修复

## 生产证据

- 正文图片弹窗已显示两张缩略图和“2张上传成功”，确认按钮可见。
- `upload_body_images` 仍等待精确等于“2张上传成功”的独立文本节点，并在 30 秒后超时。
- 真实弹窗把上传结果和“拖动可调整顺序”等辅助信息放在同一状态区域，视觉文案存在不等于存在同名独立 DOM 文本节点。
- 失败发生在点击发布前，现有 `423 EDITOR_OPERATION_FAILED` 和人工处理状态正确阻止了不确定提交。

## 修复

- 正文图片在整个“本地图片”弹窗的可见文本中等待与本次图片数量一致的“X张上传成功”。
- 允许状态区域同时包含排序提示等辅助文案，不再要求某个独立 DOM 节点只包含上传成功文案。
- 数量匹配保留数字边界，避免请求两张时误匹配“12张上传成功”。
- 浏览器仿真把上传结果和排序提示放入同一状态行，覆盖真实页面结构。

## 安全边界

- 未出现与本次图片数量一致的上传成功状态时，不点击确认、不继续发布。
- 确认后仍必须等待弹窗关闭，并核验正文实际插入全部图片。
- 不改变质量门禁、登录态、幂等键、发布状态机或远端结果判定。

## 部署与验收

- 仅需重新构建并部署 Baijiahao Browser Worker。
- 两张图片和排序辅助文案共存时，可以确认并插入正文。
- 图片数量不一致、弹窗不关闭或正文未实际插图时继续失败关闭。
