# HOTFIX-20260817-04 浏览器发布重试耗尽后的未发布收尾

## 问题

百家号自动化发布结果进入人工核实且已经达到 3 次自动尝试上限时，PUB-03 只提供“确认已经发布”。该动作必须填写公开 HTTP/HTTPS 链接，这是正确的已发布证据门槛；但平台后台确认没有该文章时，页面既不能继续重试，也没有结束任务的操作，任务和日批条目会持续停留在待处理状态。

## 修复

- 为人工核实请求新增 `not_published_closed` 处置，仅允许重试次数已经达到上限、当前任务为 `failed`、内容变体为 `publish_failed`，且没有关联远端文章 ID 时使用。
- PUB-03 在不能继续重试时显示“确认未发布并结束任务”。用户必须先确认已在对应平台后台按标题核对。
- 收尾事务将发布任务置为 `cancelled`，浏览器发布记录保留为无远端 ID 的失败终态，自动化运行置为 `disabled`，日批条目置为 `retired`，并恢复内容变体到发布前稳定状态。
- 原有发布尝试保持追加只读；不删除三次失败记录，不再次请求外部平台，并记录独立审计动作 `publish_job.unknown_resolved_not_published_closed`。

## 安全边界

- “确认已经发布”继续强制要求有效公开 HTTP/HTTPS URL，不允许以结束任务替代发布成功证据。
- 未达到重试上限时仍只能“确认未发布并重试”，不能提前通过该动作跳过剩余自动尝试。
- 已有关联远端文章 ID、非浏览器发布平台、非人工核实状态或内容版本已变化时拒绝收尾。
- 不降低质量门禁，不修改旧质量报告，不伪造发布成功，也不操作生产平台。

## 部署

重新构建并部署 Contracts、API 和 Web。无需数据库迁移，浏览器 Worker 与 Publisher Worker 无需因本 Hotfix 重建。
