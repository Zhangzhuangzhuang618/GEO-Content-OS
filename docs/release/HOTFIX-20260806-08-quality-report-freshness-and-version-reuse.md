# HOTFIX-20260806-08 质量报告新鲜度与重复版本复用

## 生产证据

- `日志 (21).txt` 中三次百家号手动重写都复用了质量报告 `f72b517f-c4d1-4db7-adc1-d43ba414d4e2`，部署新的 Quality Checker 校验逻辑后没有产生新的质检运行或质量报告。
- 首次重写生成了变化后的百家号变体，但主稿未变化；保存主稿时命中 `content_versions_object_hash_uq`，整次生成被记录为通用 `GENERATION_FAILED`，目标变体未能保存。
- 后续两次重写的目标变体未变化，被既有原文返回守卫正确拒绝。
- 失败后的变体处于 `generation_failed`，但 Web 和 API 都不允许重新质检，只允许继续按旧报告重写，形成死循环。

## 根因

- 质量报告只按“当前内容版本的最新报告”选择，没有记录并校验 Quality Checker 的模型、Prompt、Skill 和内部评估策略，因此旧评估逻辑生成的报告仍被视为当前报告。
- `generation_failed` 被重写入口接受，却被重新质检入口和质检结果落库条件排除。
- 内容版本表按对象和内容哈希唯一，但生成落库对未变化的主稿仍执行新版本插入，没有复用已存在的不可变版本。

## 修复

- 所有 API、官网自动化和百家号自动化创建的质检运行，统一写入由内容哈希、模型、Prompt、Skill 和评估策略版本计算的评估指纹。
- 质量报告驱动重写前校验该指纹；旧策略报告会被明确拒绝，必须由用户对当前内容重新发起质检。
- Web、API 和 AI Worker 允许对保留了当前内容的 `generation_failed` 变体重新质检；质检结果落库后将残留的 `all_failed` 内容包恢复为 `generated`，页面在失败状态禁用旧报告重写并提示先重新检查。
- 生成内容哈希已存在时复用对应不可变内容版本，不重复写入 blocks 和 citations；如果冲突不是同内容复用，则继续失败，不掩盖其他一致性问题。

## 安全边界

- 不修改旧质量报告，不自动重新评估旧内容，也不把旧报告转换为新结论。
- 服务端不伪造模型评分、问题或通过结论；新报告必须由当前 Quality Checker 完整运行后落库。
- 不降低冻结质量门槛、百家号自动化门禁、原文返回守卫或重写次数限制。
- 内容版本仍保持不可变和按内容哈希唯一；复用只发生在同租户、同内容包、同变体对象和同内容哈希完全匹配时。

## 部署与验收

- 重新构建并部署 Contracts、API、AI Worker 和 Web；无需数据库迁移。
- 旧报告直接发起重写应返回状态错误；`generation_failed` 页面应允许重新检查并禁止继续按旧报告重写。
- 新质检完成后，新报告可正常驱动重写。
- 目标变体发生变化而主稿未变化时，应复用已有主稿版本并继续保存目标变体，不再暴露 `content_versions_object_hash_uq`。
