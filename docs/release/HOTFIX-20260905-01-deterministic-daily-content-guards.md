# HOTFIX-20260905-01 日批内容确定性校验修正

## 生产证据

- 百家号和浏览器平台的质量重写曾在内容哈希没有变化时复用原内容版本，并再次进入质量检查。
- 列举网正文中的“地址、停车与搬运路线”“地址、楼层、电梯、物品清单和计划时间，再核验道路限行”等清单式说明，被详细地址规则误判为未核验地址。
- 抖音一线师傅和客户口吻同时要求解决方案段、固定结尾包含当前企业名称；服务端再自动补入“企业全称持有证照”时，会把全文企业名称增加到 3 次并触发既有最多 2 次门禁。

## 根因

- 百家号、列举网和搜狐重写会先删除服务端字段，构造只供模型修改的精简候选；无变化检测错误地把该精简候选当作原内容基线，与完成服务端归一化后的结果比较。
- 详细地址正则只按松散前缀和后续地址字样判断，会把“地址、楼层”“地址与搬运路线”以及园区进场
  规则等清单说明拼成详细地址；同时无法稳定识别带多级逗号的真实地址。
- 抖音证照兜底句无条件重复法定企业全称，没有为口吻固定结尾预留名称次数。

## 修复

- 模型仍接收原有精简候选，但无变化检测改用进入精简投影前的完整当前内容；只有最终规范化内容相对真实待修改版本发生变化，才可继续落库和质检。
- 详细地址识别改为在同一完整句段中查找明确的门牌号、道路、街巷、大厦或园区地址特征；“搬运路线”
  “道路”“街道”“园区进场规则/要求”和联系方式清单不再作为地址，带多级逗号的行政区地址及
  “公司地址和平路88号”等明确地址仍继续阻断。
- 抖音自动证照句使用“该企业持有证照名称”的自然指代，引用仍绑定主体精确匹配、已授权的结构化企业证照。企业名称最多 2 次、解决方案段提及、师傅固定结尾和客户备选结尾规则均保持不变。

## 边界

- 不修改质量分数、重写次数、企业名称上限、证照授权、主体匹配或引用门禁。
- 不修改 Contracts、数据库、公开 API、环境变量、Compose 或浏览器发布流程。
- 历史内容、质量报告、批次和发布任务不自动重写或重试。
- 只需重新构建并部署 AI Worker；生产部署和历史任务处置需另行授权。

## 验收

- 百家号完整内容含平台元数据时，连续两次返回相同最终内容必须以 `CONTENT_QUALITY_INSUFFICIENT` 失败。
- 列举网配置 CTA 被服务端恢复后，正文原样返回必须触发再次重写；第二次真实修改标题后可通过。
- 二十二类清单、路线、编号、联系方式及园区规则说明不触发 `unsupported_address`，十一类明确道路、门牌、
  大厦、园区及多级逗号地址继续触发。
- 一线师傅和客户口吻自动补入授权证照后无需模型修复，企业全称恰好出现 2 次，证照句及引用映射保持可见且一致。
