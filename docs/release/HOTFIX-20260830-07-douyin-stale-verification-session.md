# HOTFIX-20260830-07 抖音失效验证会话回收

## 生产证据与根因

HOTFIX-20260830-06 部署重启 Worker 后，数据库仍保留部署前的 `attention_required` 和脱敏诊断，但二次验证页面只存在于旧进程的内存浏览器上下文中，已经无法继续提交验证码。

状态复核无法区分“活动页面已没有验证层”和“Worker 重启后根本没有活动页面”。后者因此错误地新建浏览器并反复导航登录校验，生产表现为一个状态请求长期占用账号锁，其他状态请求快速返回旧诊断；长期请求约每 65 秒触发一次代理连接重置，并维持不必要的浏览器 CPU 占用。

## 修复

1. 二次验证页面检查在浏览器页面不存在或已经关闭时返回 `AUTH_REQUIRED`，不再把它等同于“活动页面没有验证层”。
2. 状态服务沿用既有失败关闭路径，将失去内存验证页的会话切换为 `reauth`，并把平台账号标记为需要重新认证。
3. 活动页面仍存在但验证层已经关闭时继续执行真实登录态检查，HOTFIX-20260830-06 的验证码提交恢复逻辑不变。

## 边界

- 不恢复、伪造或持久化验证码；Worker 重启后未完成的验证码必须重新扫码获取。
- 不自动生成二维码，不自动发送短信，不绕过抖音安全验证。
- 无数据库迁移、公开 API 形状、生产环境变量或发布质量门槛变化。
