# HOTFIX-20260806-14 百家号清单输入与 AI 声明

## 真实发布证据

- HOTFIX-20260806-13 后的发布前截图显示正文已注册为非零字数、生成封面已就绪，但有序列表显示为“2. 2.”“3. 3.”等重复编号。
- 原因是百家号把 `1. `触发为 `<ol>` 后会为后续 `<li>` 自动编号，驱动仍继续输入原文中的 `2. `、`3. `字面前缀。
- 同一截图中“采用AI生成内容”复选框仍未勾选。真实 DOM 显示该控件为 `label` 下的原生 `input[type=checkbox]`，可直接设置并复核 `checked` 状态。
- 提交后已再次搜索“全部、已发布、待发布、未通过、已撤回、草稿”六个状态，均不存在目标文章。

## 修复

- 每个编号清单保留首项 `1. `以触发百家号有序列表，输入前移除后续行的数字前缀，让平台生成唯一的视觉编号。
- 输入后要求规范化正文等于移除全部编号前缀后的原文，同时 `<ol>` 数量和直属 `<li>` 数量分别与原文清单数、清单项数完全一致。
- “采用AI生成内容”改为必需控件：直接设置原生复选框并立即复核；控件缺失或未选中时在发布前阻断。

## 安全边界

- 不删除清单内容，只去除由平台负责渲染的重复数字前缀。
- 不使用相似度、包含关系或长度近似替代全文和列表结构校验。
- 不绕过 AI 内容声明，不修改质量门禁、图片门禁、发布幂等或未知态策略。

## 部署与验收

- 重新构建并部署 Baijiahao Browser Worker；无需数据库迁移。
- 浏览器回归必须验证有序列表项数、正文完整性、封面完成态和 AI 声明选中状态。
- 真实发布前截图中不得出现重复编号，“采用AI生成内容”必须显示已选中。
