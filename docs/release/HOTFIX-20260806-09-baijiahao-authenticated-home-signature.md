# HOTFIX-20260806-09 百家号已登录首页签名识别

## 生产证据

- `日志 (22).txt` 显示发布任务 `4310450a-5576-432c-b773-7d07526b7160` 在会话人工恢复后进入第二次尝试，发布前实时核验于 `verifyViaLoginPage` 抛出 `PAGE_SIGNATURE_CHANGED`。
- 同次 attention 截图是正常登录后的百家号首页和数据总览，明确包含“发布作品”“内容管理”“个人中心”，没有登录按钮、二维码、验证码或安全验证弹窗。
- 旧代码只通过 `[data-testid="account-menu"]`、`.user-info`、`.user-name` 识别登录态；百家号首页改版后这些冻结选择器均未命中。

## 修复

- 保留原有账号菜单选择器，并增加由“发布作品”“内容管理”“个人中心”三个独立页面标记共同构成的已登录首页签名。
- 登录开始、扫码等待和实时登录核验统一识别新首页签名。
- 登录页加载后等待已登录、登录入口、二维码或验证码中的任一明确状态出现，避免异步页面尚未渲染时立即误报页面签名变化。

## 安全边界

- 必须同时存在三个已确认的首页标记才判定为已登录；单一文本不构成登录凭据。
- 登录按钮或二维码仍返回未登录，验证码仍进入人工处理，不绕过百家号登录、验证码或风控。
- 编辑器、标题、正文、图片和提交按钮继续使用冻结发布签名校验；本 Hotfix 不把正常首页误当成可提交编辑器。
- 不自动重试状态未知的外部发布，不改变发布幂等和人工处理策略。

## 部署与验收

- 重新构建并部署 Baijiahao Browser Worker；无需数据库迁移。
- 人工恢复会话后执行实时核验，正常已登录首页应恢复为 `authenticated`，不再返回本次 `PAGE_SIGNATURE_CHANGED`。
- 重新执行失败发布任务；若编辑器页面还有独立签名变化，应保留新的阶段和截图继续诊断，不得假定发布成功。
