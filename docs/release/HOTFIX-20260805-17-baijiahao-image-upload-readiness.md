# HOTFIX-20260805-17 百家号图片上传就绪竞态修复

## 生产证据

- 封面文件已进入百家号上传弹窗并显示预览，但发布停在 `upload_cover`，最终返回 `EDITOR_OPERATION_FAILED`。
- 失败截图中的按钮已显示“确定 (1)”，弹窗仍未关闭；提交到失败约 20 秒。
- 原实现仅等待“确定”按钮可见，按钮从弹窗打开时就已存在，可能在百家号异步处理图片完成前被点击并被页面忽略。
- “(1)”表示已选图片数量，不是倒计时；它同时提供了比“按钮可见”更可靠的上传完成信号。

## 修复

- 封面和正文图片写入文件后，等待确认按钮显示与本次上传数量一致的“确定（数量）”或“确认（数量）”。
- 仅在数量就绪后点击确认，并使用统一的浏览器导航超时等待弹窗关闭。
- 本地浏览器仿真加入异步上传完成延迟：就绪前点击会被忽略，用于覆盖本次生产竞态。
- 浏览器错误日志保留三层脱敏 `cause`，以后能直接看到最内层 Playwright 超时位置。

## 安全边界

- 不改变百家号发布门禁、登录态判定和远端结果核验。
- 图片弹窗未确认关闭时仍失败关闭并进入人工处理，不会继续点击发布。
- 所有日志继续执行 Cookie、Token、密码等敏感信息脱敏。

## 验收

- 封面和正文图片均等待上传数量就绪后确认。
- 仿真页在异步就绪竞态下仍能完成图片上传和发布。
- 嵌套浏览器错误可记录到最内层 Playwright 原因且不泄露凭据。
