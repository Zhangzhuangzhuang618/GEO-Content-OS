# HOTFIX-20260831-01 抖音日批受限修复闭环

## 生产证据

HOTFIX-20260830-12 上线后的首个 00:30 日批中，两个抖音账号共尝试 18 个候选，只有 1 个进入排期；
14 个在受限草稿阶段失败，3 个在质量报告重写阶段失败。直接失败中：

- 6 个包含 `claim_text 未出现在可见文案中`；
- 8 个包含“第二句话缺少具体对象、现实问题或后果”；
- 多个 Pro 草稿仍有字段比冻结最小长度少 1–12 字的问题。

这些不是质量门禁误报。根因是修复路径不完整：证据映射错误没有受限修复目标，只能整体升级 Pro；
Pro 返回后也没有再次处理仍可确定定位的长度或字面规则问题。

## 修复

1. 新增证据元数据专用受限修复，只允许返回 `evidence_claims`，不得改标题、正文、卡片或事实。
2. 修复输入只提供当前可见字段、原证据映射和服务端已绑定引用；要求 `claim_text` 从可见字段逐字复制，
   引用 ID 必须来自输入，引用原文必须直接支持完整声明，无法满足时不得制造映射。
3. 修复结果继续通过原有引用 ID、可见文案、资质证照、标题证据承诺和 Content Writer Schema 校验；
   未通过仍升级 Pro 或失败，不删除、绕过或降低门禁。
4. `opening_pain` 首稿与字段修复明确要求写出具体对象及问题或后果，并自然包含冻结检测词之一。
5. 字段最小长度修复要求保留 5–10 个汉字余量，同时不得超过原最大长度。
6. Pro 若仍留下能够定位到具体字段的确定性问题，再调用一次无工具 Flash 字段修复；仍不合格则失败。

## 影响与部署

- 无数据库迁移、公开 API、环境变量、Compose 或其他服务变化。
- 只影响抖音日批的受限生成与修复路径。
- 部署只需重建 `ai-worker`；随后重新发起两个失败批次并跟踪至完成。
