# HOTFIX-20260827-02 抖音连续叙事主文案

## 现场证据

- 真实发布作品的内容版本包含 8 张结构化卡片和 15 个正文块，但实际进入抖音作品说明的
  `platform_meta.description` 只有 58 字，并且直接复制了结论段。
- 该内容由 `deepseek-v4-flash` 首稿生成。Content Writer 已报告说明不足 160 字，但原实现允许
  `fast` 首稿忽略全部语义不足项；后续 Quality Checker 给出 `pass / 88`，因此短说明被保存并发布。
- 问题不在抖音输入框或托管浏览器截断：Publisher 按载荷原样填写了 58 字说明。

## 修复

1. 抖音说明改为 420–900 字、5–8 个自然段的独立主文案，不再允许摘要或单个正文块充当说明。
2. 确定性门禁检查首段点题与痛点、现场解决动作、报价或服务边界、防护或责任、预约或工期、至少
   3 条编号实操建议、结尾选择依据，以及模板钩子、助手过渡语、空泛免责声明和无任务问句。
3. 卡片按主题痛点、现场核对、费用边界、防护风险、工期调度、实操清单和结论推进；`总结` 也列入
   通用模板标题，不再作为合格卡片标题。
4. 有当前企业法定名称时，主文案必须在第二或第三段自然出现一次，全文最多两次；其他企业名称、
   无证据服务、案例、报价、资质和榜单仍按既有冻结规则阻断。
5. `fast` 首稿不再绕过抖音专用语义门禁；不合格时沿用一次完整质量引导重写，仍不合格则失败关闭。

## 不变边界

- 不降低事实、品牌、资质、内容、图片或平台冻结门槛，不由服务端改写模型正文或伪造质量结论。
- 不允许根据无证据样例生成竞品榜单或具名推荐；没有可靠榜单证据时只写选择标准和对比维度。
- 不自动重写或重新评估旧内容、旧质量报告、旧素材或旧发布任务。
- 无数据库迁移、公开 API 或生产配置变化；本 Hotfix 不操作生产环境。

## 验证

- Content Writer 单元测试覆盖 420–900 字、5–8 段、首段点题与痛点、编号建议和去模板化表达。
- AI Worker 单元测试覆盖 `fast` 首稿不能绕过抖音门禁，以及当前企业名称在解决方案段自然出现。
- 浏览器平台重写与日批提示同步使用同一叙事结构。
