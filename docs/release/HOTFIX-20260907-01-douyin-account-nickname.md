# HOTFIX-20260907-01 抖音登录用户名展示

用户授权：为多抖音账号增加登录用户名展示并部署生产。本次为 T162 多账号管理的展示补全。

## 证据与实现

- 原链路仅存储认证状态；账号卡片展示的是人工填写的 display_name，没有真实昵称字段。
- 生产 Creator Center 首页确认账号头部 `header-* > left-*` 有两种完整昵称结构：
  `button.account-trigger-* > span.name-*` 与直接的 `div.name-*`。已分别在志远企业号、众人企业号及
  老杨账号核实。只读取头部唯一、可见且已认证页面上的元素，不使用作品文本或其他名称。
- 登录成功和历史已登录账号首次核验时，通过该账号的独立浏览器 Context 临时打开首页读取昵称，随后关闭临时页。
- 新二维码开始时清空旧昵称；昵称读取失败保留认证判定，返回空值。昵称不参与 UID 绑定或登录失效判断。
- 昵称存入抖音会话；既有账号列表与登录会话响应增加可空的 account_nickname。
- PUB-01 账号卡片和抖音面板分别显示自填账号名与抖音用户名；关闭面板刷新列表。

## 迁移与部署

- 0059 为 douyin_browser_sessions 增加可空 varchar(120) 字段，不改写历史业务数据。
- 保持 93 张业务表、170 个公开端点。同步契约、OpenAPI 和发布基线。
- 先执行兼容性迁移，再更新 api、douyin-browser、web；保留生产环境配置与登录 Profile。
- 回滚可使用原服务镜像，新增列保留即可兼容旧代码。

## 验收

- 不同账号昵称及加密会话隔离；新扫码不显示上一账号昵称。
- 唯一头部昵称正确采集；缺失、重复或读取异常不影响登录状态，不导航发布页。
- 前端登录响应昵称回显及旧账号迟到响应隔离。
- Worker 单元及 Chromium 集成、Web 浏览器回归、契约与类型检查、生产构建、迁移及上线健康核验。
