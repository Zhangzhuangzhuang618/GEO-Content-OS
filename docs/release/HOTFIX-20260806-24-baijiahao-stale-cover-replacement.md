# HOTFIX-20260806-24 百家号残留封面替换

## 真实页面证据

- 第二篇前一次发布未创建远端文章，但持久浏览器保留了编辑页中的封面预览。
- 后续正式驱动完成同标题预查后，在封面阶段因“选择封面”入口不存在而返回 `PAGE_SIGNATURE_CHANGED`，发布按钮未点击。
- 只读 DOM 诊断确认页面已有 `coverWrapper` 封面预览，悬浮操作中提供 `aria-label="更换封面"` 的“更换”按钮；页面没有可直接使用的封面文件输入。
- 对底层封面图片执行悬停时，“更换封面”覆盖层会拦截指针事件，因此应直接操作该精确按钮。

## 修复

- 正常存在“选择封面”时保持原上传路径。
- “选择封面”不存在但已有封面预览时，直接点击精确“更换封面”，再执行相同的上传、裁剪确认和预览校验。
- 两种入口均不存在时继续按页面签名变化停止。
- 浏览器仿真从已有封面状态启动，并要求本次替换确认真实完成。

## 安全边界

- 不直接复用来源未知的残留封面。
- 不清空整篇草稿，不删除用户内容。
- 不增加发布点击次数，不放宽封面、质量、幂等或未知态门禁。

## 部署与验收

- 重新构建并部署 Baijiahao Browser Worker；无需数据库迁移。
- 单元测试和浏览器回归必须保持通过。
- 第二篇必须由正式驱动取得平台成功确认，并在内容列表按精确标题检索到，之后才能统一推送本批 Hotfix。
