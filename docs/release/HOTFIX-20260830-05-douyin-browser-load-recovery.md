# HOTFIX-20260830-05 抖音浏览器高负载恢复

## 生产证据与根因

2026-08-30 生产抖音 Worker 进入身份验证方式选择页后，容器与 Chromium GPU 进程出现持续高 CPU。此后登录和会话状态接口同时返回 HTTP 500，Web 无法取得数据库中已经保存的 `attention_required` 与短信验证方式，只能保留旧的二维码状态。

代码核验发现两个放大因素：

1. 同账号浏览器操作占用账号锁时，状态查询继续进入同一锁队列，浏览器操作迟滞便会让状态查询一并超过 API 到 Worker 的 65 秒时限。
2. 空闲状态下每次二次验证轮询都会重新生成一张脱敏截图。Web 已不展示该截图，但截图仍会触发 Chromium 渲染并随响应返回。

生产高 CPU 数据说明 Chromium GPU 进程异常，但无法仅凭进程占用证明具体的 Chromium 内部缺陷。本修复只消除系统可确认的负载放大路径，并为无 GPU 的 headless 容器关闭 GPU 加速。

## 修复

1. 账号锁增加只读忙碌状态。浏览器登录或验证动作进行中，状态接口直接返回数据库中已保存的会话与安全诊断，不再排队等待浏览器。
2. 空闲时仍保留二次验证页面状态复核，但使用不截图的轻量检查；首次挑战、验证动作结果和失败仍按原规则保存脱敏截图。
3. 用户明确放弃当前二维码或二次验证并重新扫码时，先关闭旧浏览器上下文，再启动新上下文，避免复用高负载 Chromium 进程。
4. headless Chromium 增加 `--disable-gpu`；有界面开发模式保持原行为。

## 边界

- 不自动选择验证方式，不绕过抖音安全验证。
- 不修改短信发送、验证码提交或登录成功判定。
- 不记录验证码、Cookie、手机号、页面正文或原始 DOM。
- 无数据库迁移、公开 API 形状、生产环境变量或发布质量门槛变化。

## 验证

- Worker 单元测试覆盖账号锁忙碌状态、重新扫码关闭旧上下文、状态查询不等待活动浏览器操作，以及轻量复核不返回新截图。
- Playwright 集成测试在禁用 headless GPU 的实际 Chromium 中覆盖二维码、身份验证方式、短信发送/重发/提交、原设备二维码和轻量诊断。
- Worker 类型检查、构建、API/Web 回归、Compose 解析和静态发布门禁。
