# HOTFIX-20260805-08 百家号手动发布与配图任务恢复

## 问题

- 手动创建并排期到百家号的发布任务会被浏览器网关以 `STATE_INVALID` 拒绝；网关和 Publisher 对账链路只接受 `baijiahao_automation` 来源。
- 百家号自动化在配图完成后更新每日批次时，`UPDATE ... FROM` 中的 `version=version+1` 同时匹配批次和策略表，PostgreSQL 报 `42702 column reference "version" is ambiguous`。
- 上述事务失败后，配图运行残留在 `running`；短期队列重试被运行中租约拒绝，重试耗尽后无法自行恢复。

## 修复

- 百家号浏览器网关允许来源为 `manual` 或 `baijiahao_automation` 的正在发布任务，仍保留租户、账号、内容版本、幂等键及状态校验。
- Publisher 的浏览器提交、异步状态查询、发布成功和失败回写链路支持手动来源；手动任务不读写百家号自动化运行及每日批次记录。
- 百家号每日批次更新显式使用 `batch.version`，消除 SQL 列歧义。
- 配图任务领取后若规划、持久化或后续排期失败，立即回到 `queued` 并保留脱敏错误，由既有队列重试接管。
- AI Worker 启动时只恢复超过 10 分钟、且对应官网或百家号自动化仍处于 `media_pending` 的历史配图任务；正在运行的任务和手动配图任务不在恢复范围内。

## 冻结边界

- 不降低文章、配图、品牌、事实或平台质量门槛，不伪造模型质量结论。
- 不改变浏览器登录、安全检查、发布幂等或内容版本冻结规则。
- 不为手动任务伪造百家号自动化运行或每日批次记录。

## 部署

- 重建并更新 AI Worker、Publisher Worker 和 Baijiahao Browser。
- API、Web 和数据库结构无变更，不需要数据库迁移。
- 部署后 AI Worker 启动恢复会重新投递符合条件的历史 `running` 配图任务；原手动百家号失败任务可从现有重试入口重新发布。
