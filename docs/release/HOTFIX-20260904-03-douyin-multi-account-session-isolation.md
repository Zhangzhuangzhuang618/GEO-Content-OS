# HOTFIX-20260904-03 抖音多账号登录隔离与浏览器回收

## 问题

多企业、多抖音账号场景下，账号切换会复用上一个账号的二维码、短信验证码和异步请求状态；登录成功、二维码过期或普通登录态核验结束后，Chromium Context 也未及时释放。前者可能造成操作错位，后者会让账号数量转化为持续增长的内存与进程占用。

同时修正两个已在生产日志中出现的登录恢复问题：公开版本冲突错误码判断不一致，以及短信验证完成后页面已跳转但未及时确认认证结果。

## 修复

- 抖音账号切换时按账号重新挂载面板，并清空二维码、验证码、提示和执行中状态。
- 所有异步请求与轮询在写回界面前校验账号代次，旧账号的迟到结果不能覆盖当前账号。
- 页面明确显示当前操作账号；二次验证页面中断后清除临时信息并提示重新扫码。
- 二维码过期、扫码或短信验证成功、普通登录态核验结束后释放对应 Chromium Context。
- 仍需人工完成的短信、扫码或验证码页面继续保留，不影响后续操作。
- 旧二维码后台任务不会释放新一轮登录使用的 Context。
- 发布与状态查询不会占用或导航仍在使用的二维码、短信验证页面；普通页面签名变化会正常回收 Context。
- 关闭 Context 前保存最后刷新后的加密登录快照；若末端保存失败，保留当前 Context 且不覆盖已经成功的发布结果。
- Web 端按公开 `VERSION_CONFLICT` 错误码刷新账号版本并重试。
- 短信验证对话框消失后，在剩余超时预算内通过发布编辑页确认认证结果；未知页面保存脱敏诊断。

## 验证

- Douyin Worker 单元测试：49 项通过。
- Douyin Chromium 集成测试：15 项通过。
- Web 抖音浏览器回归测试：8 项通过。
- Web API 与反馈单元测试：12 项通过。
- Web 与 Douyin Worker 类型检查、定向 ESLint、Prettier 和 Web 生产构建通过。

新增回归覆盖同一租户两个账号重叠扫码时的二维码、Profile 路径、加密快照、账号激活和 Context 释放归属，以及前端切换账号时旧请求迟到的隔离行为。

## 边界

本次不从 Creator Center 昵称、头像或未文档化 DOM 中推断真实抖音 UID。当前浏览器登录链路没有可验证的稳定远端标识；错误推断会引入新的错绑风险。后续应通过正式、稳定的账号标识来源再写入 `provider_account_id` 并启用重复绑定校验。
